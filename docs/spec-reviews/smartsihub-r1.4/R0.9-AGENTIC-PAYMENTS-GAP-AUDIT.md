# R0.9 Gap Audit — Agentic Payments, Platform Subscription and PAYG

Date: 2026-11-01. Baseline: local R0.8 draft, plus canonical GitHub source excerpts from `naibarn/SmartSpecPro` and public 2026 protocol docs. **Design/review only, no Git push, DB migration or payment execution.**

| Gap in R0.8 | Correction in R0.9 | Evidence / targeted test |
|---|---|---|
| No platform-plan subscription distinct from Mini App | Explicit separate plan/period/grant entitlements (SPEC-322, 321, 313) | User has both; grants once; App-only included Skill |
| Monthly platform credits not contractually guaranteed | On verified paid period post one grant; rollover configurable | Repeat webhook 1 credit grant, failed renewal none |
| No first-class Agent spend mandate | Versioned payer+agent+tenant bounded authority | Revoke/expire, cross-tenant, budget overage rejected |
| Payg implied but no reserve or credit line algorithm | Quote→reserve→execute→actual→release; formula | Concurrency, smaller actual and extension denial tests |
| No class-level overdraft policy | Versioned explicit class, default zero without agreement | Balance never drops below `-limit` |
| Uncollected PAYG creates payout-funded mismatch | Pending four-role owner credit shares until collection | No spendable unfunded creator credits |
| Top-ups are human checkout only | Programmatic payment intents + tokenized PSP support; manual handoff where needed | Mock API + verified eligible PSP account |
| Multi-vendor payment standards unspecified | Internal model + ACP/UCP/AP2/x402/PSP adapter registry | Eligibility/region/PSP receipt validation |
| R0.8 only showed Mini App subscription UI | Marketplace copy distinguishes platform, App, Skill costs | Responsive product/UAT testing |
| Financial release tests risk global gates | Block unsafe transaction only, deploy useful UI/independent features early | Safe beta demo while PSP adapter pending |
| Existing job admission independent of wallet reserve | Atomic reserve/outbox/job identity; Rust supervisor reports actual only | Crash/retry/ACK loss no double-charge |
| Old/new ledger unit confusion | Preserve 10x denomination epoch across legacy/new | old balance, refund, monthly grant and debt unit compatibility |

**Verified source hotspots:** `apps/web/server/services/creditService.ts` imports `creditTransactions`, `creditPackages` and reservation helpers; `postgresCreditReservationStore.ts` manages `credit_reservation_snapshots` with `drawCreditReservation` idempotency; `apps/web/server/services/billing/orchestration.ts` works with invoices/payment attempts/billingSubscriptions and Beam; `billing/topupService.ts` exposes Beam card/PromptPay and manual direct PromptPay. Source inspection is not confirmation of live payment token support or deployed DB columns. SPEC-207/280/303 authority boundaries remain unchanged.

**Business invariants:** platform account mandatory, paid platform subscription not mandatory for each App unless offer states so; plan subscriptions separate; App-exclusive only covered; shared Skill charge always, referral once; role-earned credit to user wallets, credit purchase/grant not four-way revenue; no withdrawal until later separate design. No automatic agent payment beyond user mandate and PSP capability.

**Unresolved business knobs (configurable, not developer guesswork):** platform subscription tiers/price/monthly grant, rollover/expiry; maximum overdraft per user class, collection thresholds, allowed PSP; subscription grace/chargeback terms; supported payment jurisdictions. These should be decisions in pricing/risk configuration, not new project-wide production rollout vetoes.
