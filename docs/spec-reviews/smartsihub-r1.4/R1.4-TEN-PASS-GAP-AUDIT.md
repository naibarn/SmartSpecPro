## Detailed owner decisions confirmed

1. **Never replatform old Core by conversion.** Fresh minimal TypeScript/Hono Core and React app Shell; public Astro site also fresh. Rust native supervisor not global Rust rewrite.
2. **Old app is the new app's builder.** Existing `smartaihub.app` Autonomous Implements/Creator initiates development; an old blocked run triggers narrow repair then resumes same goal until new authority demonstrably works.
3. **Use the old core data only where legitimately owned.** App-specific domain tables for new apps are outside `smartspec`. Tenant identity, ledger, job state and registered legacy tables remain.
4. **Build real user-visible features before polishing audit metrics.** No G0–G6 blanket implementation gates. Isolation/financial correctness is a per-operation constraint and development should continue elsewhere.
5. **Inline interactive UI and detached artifact/browser are first-class.** OpenUI and browser WebMCP are complementary, neither substitutes authenticated headless HTTPS/MCP. Three reference themes are attached in this package.
6. **Financial integrity is non-optional.** 1 USD = 10,000 new credits and previous balances preserve value with unit-version transition; real concurrent writer migration needs controlled rollout. New revenue roles exactly four, referral bonus once outside the split.
7. **Cloud-based always-on is a runtime property not a visual toggle.** If the only authorized device shuts down, a job should be truthfully waiting, not shown as cloud-running.

## Residual unknowns — not blanket blockers

- Exact live PostgreSQL schema/migration drift, active payment webhooks, old credit denomination implementation and current production writer count require runtime/source inventory before **financial write** changes.
- Existing `smartaihub.app` Autonomous Implements' end-to-end dispatch and reconnect health has not been exercised in this review. P0 must prove one actual user-driven implementation and visible URL before declaring the engine migrated.
- Moli is **not production-qualified** by SPEC-208 current findings, including browser isolation and advisory issues. Kitesurf is beta; Clef model routing needs scoped evaluation. These do not block Core, Chat, Creator or Chromium pilot.
- Cloudflare resource inventories previously decommissioned by SPEC-311 must be read back before each new Worker/Queue/Hyperdrive provisioning. No old resource IDs may be treated as deployed.
- The three mockups are visual direction only; actual theme CSS, responsive behavior, accessibility, performance, functional WebMCP and UI screenshots require implementation evidence.
- A full 307-old-SPEC text audit is outside this 13-spec revision; legacy owners are cross-referenced and must be reconciled at their concrete implementation boundaries.

## Notes on status

The statements **'review passed'** and **'documents repaired'** concern static text/contracts and packaging only. They do **not** prove that Jobs are durable under actual production failure, finances balance, a new Core was deployed, or any Agent has executed an always-on cloud task.
