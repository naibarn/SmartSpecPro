# R1.3 Gap Review — Computer Use & Cloudflare Clef

**Scope and evidence:** Read canonical `SPEC-208` Rev9 from connected GitHub, compared it with R1.2 package; verified Cloudflare announcements/docs current on 2026-11-01. This is a document-level audit, not an implementation or production benchmark.

| Gap in R1.2 | Correction in R1.3 |
|---|---|
| No explicit distinction between Clef and browser/desktop computer use | Clef is bounded typed decision model only, no OS/browser action execution |
| Risk of building another decision model layer | Explicitly reuse frozen SPEC-208 Rev9 Clef-first `DecisionProvider` |
| Prior advice described Moli as preferred despite SPEC-208 not qualifying it | Corrected production profile to qualified Chromium first; Moli disabled pending isolation/compatibility evidence |
| Missing Cloudflare Kitesurf option | Added stateless low-resource browser route, with beta and WebMCP limitations documented |
| Desktop computer use conflated with cloud browser | Runner Windows/Linux for native UI; Cloudflare Browser Run only browser; Sandbox SDK built-in desktop removed |
| No final-result-only UAT for sleep/offline | Chat/Artifact final output and durable job acceptance with disposable browser session |
| Missing Clef model boundaries | Deterministic authorization first; Clef-flash optional shadow routing and no payment/policy privilege |
| No per-provider failure isolation | Provider-specific fallback/repair; no global project block |
| Insufficient fault scenarios for side effects | Unknown outcome and no blind retries for financial / irreversible browser/GUI actions |
| No reproducible router policy | Added JSON example with documented limitations |
