# R0.5 review — Go vs Rust for SmartAIHub canonical worker_jobs (2026-11-01)

## Grounding

- R0.4 SPEC-318 defaulted to an optional Go native executor; it already specified canonical PostgreSQL `worker_jobs`, outbox, Queue at-least-once and partial beta.
- Current canonical GitHub `apps/cloudflare/src/queueConsumer.ts` has TypeScript envelope parsing, retry/quarantine; this is a historical source foundation, not proof of currently deployed Queues.
- SPEC-311 2026-11-01 decommission record says migration Workers/Queues/Containers were removed; do not reuse prior provider IDs.
- Cloudflare officially supports Rust `workers-rs` Queue handlers, with Wasm + JS bridge and possible bundle/startup overhead.

## Decision and tradeoffs

Rust is preferred for the **native long-running supervisor** because bounded resource use, no GC and precise control over concurrency are strategic goals. Go remains an allowed alternative and is often easier/faster to ship. **Correctness properties are identical in principle**: language selection does not stop a host crash or deduplicate a provider payment. Tiny TS Worker remains default in Cloudflare Queue push path. Pure contracts may be shared with optional Rust/Wasm work, not platform-specific execution code.

## Critical gaps closed from R0.4

1. Explicit 202-after-transactional job/outbox acceptance and uncertain-commit dedupe.
2. Dedicated DB fencing token for stale attempts and ACK-after-durable-handoff semantics.
3. Crash after external effect => outcome-unknown/reconciliation, not automatic duplicate provider call.
4. Queue retention + DLQ expiry cannot delete a canonical outstanding job; DB scanner/audits required.
5. Rust on Debian is still a Debian production dependency; native Rust not magically Cloudflare-hosted.
6. Bounded tenant fairness and horizontal supervisor replica planning; no process-wide single bottleneck.
7. DB/PITR backup/restore and observable recovery time; no absolute zero-loss claim.
8. Native Rust vs Go performance benchmark distinguished from durability tests.
9. Required scoped crash/duplicate/payment tests affect *that job class*, do not block unrelated UAT.
10. SPEC-312/314/315/316/317, README, mission and resource budgets updated for new language decision.

## No deploy and no fabricated results

These are design/spec modifications, not implemented Rust services, passing end-to-end tests or Cloudflare releases. Real DB schema/catalog inspection and exact-source acceptance are still required during implementation.
