# R1.2 Focused Gap Review — Interactive Chat / Artifacts / Agent Browser

## Source and review scope

- Based on local SPEC-312–324 R1.1 drafts and existing user's three screenshots (inline diagram, YAML code block, interactive choice). Screenshot contents are product-design references, not implemented behavior or reliable proof of old service capability.
- Online technical check 2026-11-01: `thesysdev/openui`, `lexmount/moli`, Cloudflare Browser Run. External project claims and benchmark figures are not platform-measured data.

## Gaps closed

1. Inline chat contract previously did not enumerate typed renderable block kinds and state restoration.
2. OpenUI had been discussed as optional but not integrated into SPEC-319's canonical actions and three-theme component profile.
3. Artifact split view, detached window, storage/versions, source/preview history and backend receipts were unspecified.
4. Browser panel + link to familiar Chrome/Edge needed explicit distinction between URL open and remote session takeover.
5. Moli needed status as optional provider, not default browser, and its current compatibility envelope/feature fallback acknowledged.
6. Cloudflare Browser Run human handoff/live viewing needed provider-neutral contract.
7. Long-running browser job vs temporary browser process ambiguity now addressed.
8. Third-party pages/JS/model-generated controls require input trust boundaries and tenant security.
9. Rich content must survive reload/stream disconnect and have accessible text fallback.
10. Chat first and Mini App Creator second migration leverage the same artifact/browser surface; no new all-project gate.

## Remaining implementation questions (discovery, not blockers)

- Current artifact registry storage schema and whether R2 signed URLs can be minted with appropriately scoped access.
- Actual selected OpenUI version, renderer weight, browser support and compatibility with three theme token profiles.
- Debian host browser memory/CPU baseline and existing Playwright/Chromium setup.
- Paid Browser Run limits and session economics for actual subscription account.
- Moli compatibility and TCO against Chromium for typical SmartSIHub workloads; treat vendor benchmark as a hypothesis.
- Cross-window synchronization mechanism and secure broker for Browser Live View; choose based on actual code architecture.
