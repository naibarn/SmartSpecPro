# R1.1 Review — migration sequence, autonomous execution and self-hosted repair

Reviewed local R1.0 spec pack plus current GitHub `main` (`912281e41763d03ba9c88ff4f8cd61c944e006dd`) on 2026-11-01. Prior R1.0 had tentative SPEC-317 waves placing public and Document/Library before Chat/Creator, and no binding instruction that **every new-system development Goal must be managed by the old `smartaihub.app` Autonomous UI**. This is corrected in R1.1.

| Issue | Source of mismatch | R1.1 correction |
|---|---|---|
| No mandatory development-entry point | New platform plans could be executed as unrelated direct Codex sessions | SPEC-324: old authenticated website owns program Goal, Runner/Workspace/Code/Deploy receipts |
| Circular dependency/bootstrap absent | Wanted new autonomous system before existing builder could create it | P0 verify/repair old tools, P1–P4 build new tools with old; P5 transfer |
| Chat/Creator too late | SPEC-317 waves put Public/Docs ahead | Override fixed P2 Chat, P3 Mini App Creator, P4 new Autonomous |
| No old control-plane recovery loop | Old UI/Runner/approval outages treated as external impediments | Same Goal scoped bootstrap repair child, resume original task; break-glass only if UI unavailable |
| Duplicate job during handover risk | Both old and new Orchestrators could run same Goal | Single owner per Goal, drain/fence/reconcile, selective transfer and rollback |
| Ambiguous domain roles | Developers confuse dev target with dev control website | smartaihub.app=current controller; aimarkethubs.com=new Debian UAT; smartsihub.com=new Cloudflare prod |
| Overly broad gate creep | Old G0/wave/completeness linked to release | Scope safety holds only; early UAT of usable slices and automatic repair continuation |
| Missing success receipts | Git SHA can be reported without working UI/browser | Task/Run/Runner/URL/UAT/cost artifact fields and real human UAT included |

**Limit:** This was a source/spec design update. No authenticated old-site Goal execution, new standalone repo, live Debian deployment, DNS, database or Cloudflare changes were made. The old Autonomous UI/Runner health must be measured through actual authenticated task evidence before declaring P0 passed.
