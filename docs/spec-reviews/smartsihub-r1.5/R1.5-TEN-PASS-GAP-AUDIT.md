## Pass 4 — Durable Agent lifecycle, queues, Runner presence and offline recovery

**Examined:** SPEC-318, 324, 325; Workers-first and Runner ADRs; canonical worker job/outbox references.

**Gap and repair:** R1.4 mixed cloud Agent continuity with resident native supervision and did not fully distinguish a boot Connector from a job Executor. R1.5 now states that cloud state/wakeups are event-driven and canonical `worker_jobs`/outbox/lease/fencing remains authoritative. The device Core Connector starts at OS boot; workload Executor is on demand. Added explicit presence states, finite reconnect, proof/epoch renewal, cursor reconciliation, wait states, idempotency and refusal to replay uncertain OS effects. Sleep/offline and revoke semantics are explicit.

**Evidence/status:** Validator checks the named Runner protocol messages, states, signed envelope fields, job authority and 32 acceptance IDs. **PASS — SPEC tests, not executed runtime tests.**

**Residual risk:** Real reconnect recovery, queue delivery, Do hibernation, DO sharding/cost and Windows/Linux service behavior have not been implemented or measured.

## Pass 5 — Chat-first UI, headless parity and shared Companion

**Examined:** SPEC-319, 312, 325; Chat ADR and Unified Desktop Companion ADR.

**Gap and repair:** Earlier package positioned old automation UI as the command entry and lacked an explicit shared desktop/web frontend contract. R1.5 now makes Chat primary and defines a floating Companion using the same frontend components, route/action schemas and server state. Chat, HTTPS and MCP pass the same typed authorization; UI close does not cancel durable work. Model-produced executable HTML/JS and generic native IPC are disallowed.

**Evidence/status:** Cross-SPEC traceability and SPEC-325 SEC-14/15/22 cover browser close, shared identity, WebView XSS, IPC and overlay fallback. Validator checks shared-frontend and typed-action clauses. **PASS.**

**Residual risk:** Accessibility, tray/overlay behavior, Linux Wayland and web/native version compatibility require platform UAT.

## Pass 6 — Tenant/module/BYOK isolation, device identity and credentials

**Examined:** SPEC-313/314/315/316/318/322/323/325; credential and Runner ADRs; credential record/API and placement matrix.

**Gap and repair:** The previous shared-DB assumption is not carried forward. R1.5 defines separate environment principals/DB credentials, six-plus identity types, server-derived tenant membership, effect grants, policy epochs and device proof-of-possession. Tier A Worker Secrets, Tier B selected Secrets Store and Tier C application-encrypted tenant vault have named owners and consumers. Tier C names AES-256-GCM, per-record DEKs, AAD, dedicated ciphertext storage and external AWS KMS envelope-key broker, plus rotation/recovery. Raw BYOK is broker-mediated; the no-plaintext rule covers prompt, memory, queue, log, browser, Runner and receipt.

**Evidence/status:** Validator checks credential matrix, required tier controls, broker checks, KMS, rotation, redaction and required negative-test categories. **PASS — architecture text only.**

**Residual risk:** No D1, KMS, Lambda, IAM role, Secret Store binding or real credential has been provisioned. The AWS cross-cloud profile must pass security, availability, cost and restore review before use.

## Pass 7 — Injection, computer use, endpoint and egress safety

**Examined:** SPEC-317, 318, 319, 320, 323, 325; Runner ADR; frozen SPEC-208 references.

**Gap and repair:** Added untrusted-content provenance, prompt-injection containment, brokered provider calls, SSRF/private-address/redirect checks, per-tenant browser profiles, output redaction and explicit Runner connector/executor IPC separation. Windows Session 0 and locked/no-login GUI limits are stated; the platform does not borrow personal cookies or bypass lock. Local files, shell, browser, clipboard and artifacts are separately scoped. TLS is not described as Edge-blind E2EE; optional application-layer E2EE has explicit inspectability limits, while no-inbound-listener and same-auth HTTPS polling fallback are specified.

**Evidence/status:** SEC-06/07/13/15/19/22/23/25/26/27/29/31/32 specify expected denial; validator verifies transport, egress, injection, credential-canary and endpoint boundary clauses. **PASS — negative test specifications only.**

**Residual risk:** Malware running with access to a locally usable signing key, a compromised enrolled endpoint or a vulnerable approved Executor can still cause local harm. Revoke cannot instantly stop disconnected or already executing hardware.

**Residual risk:** No live payment or ledger test was run; future implementation must use the frozen financial owner's verified contract.
