# Interview Transcript

ไม่มีคำถามธุรกิจที่จำเป็นต้องหยุดรอคำตอบเพิ่มเติมในรอบนี้ เพราะคำขอปัจจุบันและบริบทก่อนหน้าได้ระบุข้อจำกัดหลักครบแล้ว แผนจึงบันทึกคำตอบเชิงโดเมนที่ยืนยันได้และแยก auto-decisions ทางเทคนิคไว้ชัดเจน

## Q1: เนื้อเรื่องที่เดินไปถึงตอนที่ 25 ต้องได้รับการปกป้องอย่างไร

คำตอบจากผู้ใช้: ห้ามให้ solution ใหม่กระทบเนื้อเรื่องปัจจุบันหรือทำให้ต้อง rewrite ตอนเก่าโดยอัตโนมัติ ต้องใช้เป็นข้อมูล legacy สำหรับ audit และเริ่มบังคับใช้กับเนื้อหาที่วางใหม่ในอนาคต

## Q2: ระบบควรให้ความสำคัญกับการปิดปมหรือความเป็นเรื่องเดียวกันมากกว่ากัน

คำตอบจากผู้ใช้: ต้องหา solution ที่ไม่ทำให้การพะวงปิดปมทำให้เรื่องสเปะสปะหลุดจากแกน ดังนั้นการปิดปมเป็นข้อจำกัดด้าน continuity ไม่ใช่เป้าหมายสูงสุดของการเขียน เนื้อเรื่องหลัก ตัวละคร และอารมณ์ต้องมาก่อน

## Q3: ต้องการให้จัดการบทพระเอก/นางเอกและฝ่ายร้ายอย่างไร

คำตอบจากผู้ใช้: ต้องมีจังหวะที่ตรวจสอบได้สำหรับคู่กัด จีบกัน รักกัน หวาน และฉากอารมณ์ที่คนดูรอ รวมถึงสลับความได้เปรียบเสียเปรียบของฝ่ายดีและฝ่ายร้าย โดยไม่บังคับให้ทุกตอนหรือทุกช็อตมีจังหวะเหมือนกันจนเป็นสูตรตายตัว

## Q4: ระบบควรกำหนดความยาวของหนึ่ง episode อย่างไร

คำตอบจากผู้ใช้: ค่าเดิม `1 episode = 60 วินาที` ใช้เป็นกติกากลางไม่ได้แล้ว เพราะระบบวิดีโอกำหนด duration ต่อ shot ได้หลายค่า เช่น 8, 10, 15, 20, 25 และ 30 วินาที ขณะที่ storyboard ยังคงมี 9 shots ดังนั้นความยาว episode ต้อง derive จาก duration ของ 9 shots และค่อย ๆ ปรับระบบโดยไม่กระทบงานเดิม

## Auto-Decisions

- ใช้ season/arc control plan เป็นแผนล่วงหน้า และใช้ episode slot ที่มีขอบเขตแคบเป็น input ให้ skill เขียนตอน
- ให้ skill เป็นผู้ตัดสิน semantic quality; ให้ TypeScript/Zod เป็นผู้ตรวจ structural facts และ state transition
- ใช้ stable IDs และ canonical character keys เป็นแหล่งอ้างอิงกลาง
- แบ่ง scope ของปมเป็น moment hook, episode thread, arc thread และ season thread เพื่อไม่ให้ทุก cliffhanger กลายเป็นปมระยะยาว
- ให้สถานะ `parked`, `sequel_hook`, `legacy_unknown` แสดงตรง ๆ แทนการเดาเฉลยหรือ mark resolved อัตโนมัติ
- เริ่มจากการบังคับใช้กับซีรีย์ใหม่/episode ที่ยังไม่เขียน และให้ซีรีย์ปัจจุบันใช้ audit-only หรือ future-horizon mode ก่อน
- ใช้ Vitest สำหรับ contract/validator/quality orchestration และ Playwright เฉพาะหลักฐาน UI ที่จำเป็น
- ให้ `shotCount=9` เป็นโครงสร้าง storyboard แต่ให้ `shotDurationsSeconds[]`/duration profile เป็นแหล่งความจริงของ runtime; 60 วินาทีเก็บไว้เฉพาะ compatibility profile ที่ระบุชัด
