## Real implementation rules

- Use semantic tokens for `background`, `surface`, `foreground`, `muted`, `border`, `focus`, `accent`, `success`, `warning`, `danger`, code tokens, chart palette and job statuses. Themes must not alter authorization or financial behavior.
- Theme persisted per user and honored by fixed React shell, inline OpenUI renderer, artifact inspector, browser panel and supported Mini App host surfaces. Tenant branding is an additional controlled token layer, not arbitrary unreadable overrides.
- Left navigation and composer are familiar, easy to use and not visually noisy; right Inspector is collapsible and mobile uses drawer/modal pattern. Do not force wide 3-column layout onto phone.
- Admin/Back Office is absent for nonadmin users **based on verified server entitlement**, not just CSS hidden. Public Website is a verified link once deployed, otherwise an honest Coming Soon state.
- OpenUI is optional content, not the platform shell. Generated components use a vetted allowlist, schema validation and accessible keyboard focus; actions are authorized Core calls.
- Real run percentages, counts and success indicators only from `worker_jobs`/receipts. Mockup content (e.g. 72%) is placeholder illustration; do not render a fake live status in production.
- Verify computed styles in real browsers using Playwright, desktop/tablet/mobile, focus/keyboard, color contrast and reduced-motion behavior. Visual review is feedback, not a global prohibition against deploying unrelated usable slices.
- Design quality: no default AI landing/dashboard kits, gratuitous neon, dense unreadable tiny type, animation without purpose, vague action icons or unnecessary panels on blank Chat. When there are no active Runs, show a compact empty state and prioritize composer + recent context.
