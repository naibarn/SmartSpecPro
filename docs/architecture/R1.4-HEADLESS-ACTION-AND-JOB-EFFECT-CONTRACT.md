# SmartSIHub — Universal headless action / job / UI effect contract

**Scope:** cross-cutting clarification for SPEC-207/208/256/280 and SPEC-313/318/319/321/322/324. Draft — no new authority.

1. One action descriptor: `actionId`, `version`, `inputSchema`, `outputSchema`, `effectClass`, `requiredScopes`, `tenantId`, `appId` if relevant, `skillId` if relevant, `billingPolicyRef`, `idempotencyClass`, `asyncJobType`, `cancellationPolicy`.
2. Four surfaces may invoke the **same server-side implementation**: Chat typed input, OpenUI renderer, browser WebMCP tool, and MCP/HTTPS headless agent. None becomes an authorization server, accounting ledger or separate job queue.
3. For long jobs, admission records `jobId` + immutable `attemptId` and tenant/app identity + policy snapshot + financial reservation + outbox in atomic/core-owned operations. Queue dispatch is at-least-once; durable Job status lives in PostgreSQL, never in a socket, React state or browser session.
4. Every billable Child/Shared Skill invocation has a stable `invocationId` rooted in its user-authorized parent Goal. Exactly once **economic effect** by unique keys; provider side effect may not be exactly once. A reconnect, replay, delivery retry or duplicate ACK never becomes a new user invocation.
5. A signed, scoped agent spending mandate may permit no-click payment under existing limits. Unknown capture/provider outcome is `OUTCOME_UNKNOWN`; do not retry third-party checkout or job effect blindly.
6. For UI interactive mutations, Action Registry resolves real action ID and performs server-side verification of actor/tenant/entitlement/spending; do not execute arbitrary JS/SQL issued by a model. Read-only query refresh can reuse typed action without LLM calls.
7. Durable Artifacts use versioned object refs, access policy and provenance; detached views may inspect without new execution. Browser Session IDs are disposable, never the job authority.
8. `RUNNING_CLOUD` is valid only if a verified remote executor owns a live lease. When no executor is available use `QUEUED`/`WAITING_FOR_EXECUTOR` with truthful user messaging; closing a personal computer does not keep its own Runner operating.
