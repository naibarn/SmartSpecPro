# สถานะระบบ

## ภาพรวม

หน้าสถานะระบบแสดงภาพรวมของความพร้อมใช้งานและประสิทธิภาพของบริการทั้งหมดในระบบแบบเรียลไทม์ แอดมินสามารถตรวจสอบได้ทันทีว่าบริการใดทำงานปกติ บริการใดมีปัญหา หรือมีการใช้ทรัพยากรสูงผิดปกติ ข้อมูลนี้ช่วยให้ทีมสามารถตอบสนองต่อปัญหาได้อย่างรวดเร็วก่อนที่จะส่งผลกระทบต่อผู้ใช้

## วิธีเข้าถึง

เข้าสู่ระบบในฐานะแอดมิน จากนั้นไปที่เมนูด้านซ้าย เลือก **Admin** และคลิก **System Health** หรือไปที่ URL `/admin/system-health` โดยตรง

## ความสามารถหลัก

- ดูสถานะของบริการหลักทั้งหมด ได้แก่ ฐานข้อมูล PostgreSQL, Redis, Celery Workers และ LLM Providers
- ตรวจสอบตัวชี้วัดประสิทธิภาพ เช่น เวลาตอบสนอง (Latency) การใช้งาน CPU และหน่วยความจำ
- ดูประวัติอัพไทม์และเหตุการณ์ขัดข้องย้อนหลัง
- รับการแจ้งเตือนเมื่อบริการใดออฟไลน์หรือมีประสิทธิภาพต่ำกว่าเกณฑ์
- ตรวจสอบสถานะการเชื่อมต่อกับผู้ให้บริการ LLM ภายนอก เช่น OpenAI, Anthropic และ Google
- ดูจำนวน request ต่อวินาทีและอัตราความสำเร็จของแต่ละบริการ

## ขั้นตอนการใช้งาน

1. เปิดหน้า **System Health** จากเมนู Admin
2. ตรวจสอบการ์ดสถานะของแต่ละบริการ สีเขียวหมายถึงปกติ สีเหลืองหมายถึงมีคำเตือน สีแดงหมายถึงมีปัญหา
3. คลิกที่การ์ดบริการที่ต้องการดูรายละเอียด เพื่อดูตัวชี้วัดเพิ่มเติมและประวัติการทำงาน
4. ตรวจสอบแผนภูมิ Latency เพื่อดูแนวโน้มประสิทธิภาพในช่วงเวลาที่กำหนด
5. หากพบบริการที่มีสถานะผิดปกติ ให้ดู log ที่เกี่ยวข้องเพื่อวิเคราะห์สาเหตุ
6. ใช้ปุ่ม **Refresh** เพื่ออัพเดตข้อมูลสถานะล่าสุด หรือเปิดการรีเฟรชอัตโนมัติ

## เคล็ดลับ

- ตรวจสอบหน้านี้เป็นประจำในช่วงเวลาที่มีการใช้งานสูง เพื่อระบุปัญหาด้านประสิทธิภาพล่วงหน้า
- หาก Redis แสดงสถานะผิดปกติ มักส่งผลให้ Celery Workers หยุดรับงาน ควรตรวจสอบคู่กัน
- สถานะของ LLM Providers อาจเปลี่ยนแปลงได้เนื่องจากปัจจัยภายนอก ควรตั้งค่า fallback provider ไว้เสมอ
- บันทึกภาพหน้าจอหรือส่งออกข้อมูลสถานะเมื่อพบปัญหา เพื่อใช้ในการวิเคราะห์ root cause
