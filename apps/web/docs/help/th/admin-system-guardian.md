# ผู้พิทักษ์ระบบ (System Guardian)

## ภาพรวม

System Guardian คือระบบตรวจสอบสุขภาพอัตโนมัติที่คอยดูแลโครงสร้างพื้นฐานทั้งหมดของแพลตฟอร์มแบบเรียลไทม์ Guardian จะตรวจจับความผิดปกติ สร้างเหตุการณ์ (incident) โดยอัตโนมัติ และสามารถดำเนินการแก้ไขได้เองโดยไม่ต้องรอให้แอดมินเข้ามาดูแล

## แท็บหลักใน Guardian

หน้า System Guardian แบ่งออกเป็น 4 แท็บ:

- **Events** — รายการเหตุการณ์ผิดปกติทั้งหมดพร้อมสถานะ
- **Approvals** — คำขอที่รอการอนุมัติจากแอดมิน
- **Sensors** — สถานะเซนเซอร์ 11 ตัวที่ตรวจสอบระบบ
- **Chat** — สนทนากับ Guardian โดยตรงผ่านคำสั่ง

## จัดการเหตุการณ์ (Events)

### ระดับความรุนแรง

เหตุการณ์แต่ละรายการมีระดับความรุนแรง 4 ระดับ:

| ระดับ | ความหมาย |
|-------|---------|
| **info** | ข้อมูลทั่วไป ไม่กระทบการใช้งาน |
| **warning** | ควรติดตาม อาจพัฒนาเป็นปัญหาได้ |
| **error** | มีปัญหาเกิดขึ้น ต้องแก้ไข |
| **critical** | วิกฤต ต้องดำเนินการทันที |

### การดำเนินการกับเหตุการณ์

- **Acknowledge** — รับทราบเหตุการณ์เพื่อแสดงว่าแอดมินรับรู้แล้ว
- **Resolve** — ทำเครื่องหมายว่าแก้ไขเสร็จแล้ว
- **Auto-fix** — Guardian พยายามแก้ไขเองโดยอัตโนมัติ (ถ้าเปิดใช้งาน)

## ขั้นตอนการอนุมัติ (Approvals)

บางการดำเนินการของ Guardian ต้องรอการอนุมัติจากแอดมินก่อน เช่น การรีสตาร์ท service หรือการลบข้อมูล

1. Guardian สร้างคำขออนุมัติพร้อมคำอธิบายว่าต้องการทำอะไร
2. แอดมินจะได้รับแจ้งเตือน
3. กด **Approve** เพื่ออนุมัติ หรือ **Reject** เพื่อปฏิเสธ
4. Guardian ดำเนินการตามผลการอนุมัติ

## สถานะเซนเซอร์ (Sensors)

Guardian ใช้เซนเซอร์ 11 ตัวตรวจสอบระบบต่อเนื่อง:

| เซนเซอร์ | สิ่งที่ตรวจสอบ |
|---------|-------------|
| **Queue** | สถานะ job queue และ backlog |
| **Celery** | Worker status และ task failure rate |
| **Error Spike** | อัตราการเกิด error ที่ผิดปกติ |
| **LLM** | ความพร้อมและ latency ของ LLM providers |
| **Credits** | ยอดเครดิตของผู้ใช้และระบบ |
| **Disk** | พื้นที่จัดเก็บข้อมูล |
| **DB** | การเชื่อมต่อและประสิทธิภาพ database |
| **Certificate** | วันหมดอายุของ SSL certificate |
| **API Latency** | ความเร็วตอบสนองของ API |
| **Media Pipeline** | สถานะ pipeline สร้างสื่อ |
| **Escalation** | เหตุการณ์ที่รุนแรงขึ้นตามเวลา |

เซนเซอร์แต่ละตัวแสดงสถานะ **healthy**, **degraded**, หรือ **critical** พร้อมข้อมูลล่าสุด

## Guardian Chat

สนทนากับ Guardian โดยตรงโดยพิมพ์คำสั่งในแท็บ Chat:

| คำสั่ง | ผลลัพธ์ |
|--------|--------|
| `status` | ดูสถานะสุขภาพระบบโดยรวม |
| `incidents` | แสดงรายการเหตุการณ์ที่กำลังเกิดขึ้น |
| `retry [task-id]` | ลองรันงานที่ล้มเหลวใหม่อีกครั้ง |
| `approve [id]` | อนุมัติการดำเนินการที่รอการยืนยัน |
| `queue` | ดูสถานะ job queue ปัจจุบัน |
| `help` | แสดงคำสั่งทั้งหมดที่ใช้ได้ |

## ตั้งค่า Guardian

### เปิด/ปิด Guardian

สลับปิดได้จากสวิตช์ **Enable Guardian** ที่มุมขวาบน — Guardian จะหยุดตรวจสอบและไม่สร้างเหตุการณ์ใหม่

### Auto-fix

เมื่อเปิด **Auto-fix** Guardian จะพยายามแก้ไขปัญหาที่รู้จักโดยอัตโนมัติ เช่น รีสตาร์ท Celery worker หรือล้าง cache ที่เต็ม โดยไม่ต้องรอแอดมิน

### ช่องทางแจ้งเตือน

กำหนดช่องทางรับการแจ้งเตือนเมื่อมีเหตุการณ์วิกฤต:
- **Email** — ส่งอีเมลไปยังแอดมิน
- **Slack** — ส่งข้อความไปยัง channel ที่กำหนด
- **Webhook** — ส่ง HTTP POST ไปยัง URL ภายนอก

## แบนเนอร์สุขภาพ

เมื่อมีเหตุการณ์ระดับ **critical** เกิดขึ้น ระบบจะแสดงแบนเนอร์สีแดงที่ด้านบนของทุกหน้าในระบบ แจ้งให้ผู้ใช้และแอดมินทราบ แบนเนอร์จะหายไปเองเมื่อเหตุการณ์ได้รับการแก้ไข
