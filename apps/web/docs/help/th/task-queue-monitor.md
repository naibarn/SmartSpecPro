# มอนิเตอร์คิวงาน

## ภาพรวม

Task Queue Monitor แสดงสถานะของคิวงาน Celery ทั้งหมดในระบบแบบเรียลไทม์ แอดมินสามารถดูว่ามีงานใดรอดำเนินการ งานใดกำลังทำงาน งานใดเสร็จสมบูรณ์ และงานใดล้มเหลว รวมถึงตรวจสอบสถานะของ worker แต่ละตัวและค้นหาสาเหตุของงาน media ที่ค้างอยู่นานผิดปกติ ข้อมูลเหล่านี้จำเป็นอย่างยิ่งสำหรับการรักษาประสิทธิภาพของระบบสร้างเนื้อหา

## วิธีเข้าถึง

เข้าสู่ระบบในฐานะแอดมิน จากนั้นไปที่เมนูด้านซ้าย เลือก **Admin** และคลิก **Task Queue** หรือไปที่ URL `/admin/task-queue` โดยตรง

## ความสามารถหลัก

- ดูจำนวนงานในแต่ละสถานะ ได้แก่ Active (กำลังทำงาน), Pending (รอดำเนินการ), Completed (เสร็จสิ้น) และ Failed (ล้มเหลว)
- ตรวจสอบสถานะและ workload ของ Celery worker แต่ละตัวที่กำลังทำงานอยู่
- ดูรายละเอียดของงานแต่ละรายการ เช่น ประเภทงาน เวลาเริ่มต้น ระยะเวลา และผลลัพธ์
- ยกเลิกงานที่ค้างอยู่หรืองานที่ไม่ต้องการดำเนินการต่อ
- ดูสถิติ throughput ของระบบ เช่น จำนวนงานต่อนาทีและเวลาเฉลี่ยในการประมวลผล
- วินิจฉัยงาน media generation ที่ค้างอยู่นานโดยดู external task ID และสถานะจาก provider

## ขั้นตอนการใช้งาน

1. เปิดหน้า **Task Queue** จากเมนู Admin
2. ตรวจสอบการ์ดสรุปด้านบนที่แสดงจำนวนงานในแต่ละสถานะ
3. คลิกที่แท็บ **Active** เพื่อดูงานที่กำลังดำเนินการ และตรวจสอบว่ามีงานใดใช้เวลานานผิดปกติ
4. คลิกที่แท็บ **Failed** เพื่อดูงานที่ล้มเหลว พร้อม error message และ stack trace
5. คลิกที่งานแต่ละรายการเพื่อดูรายละเอียดเพิ่มเติม รวมถึง input parameters และ external task ID
6. ใช้ปุ่ม **Revoke** เพื่อยกเลิกงานที่ค้างอยู่ หรือ **Retry** เพื่อลองใหม่สำหรับงานที่ล้มเหลว
7. ตรวจสอบส่วน **Workers** เพื่อดูว่า worker แต่ละตัวกำลังรับงานอยู่หรือไม่

## เคล็ดลับ

- หากคิว Pending สูงมากแต่ Active น้อย อาจหมายความว่า worker ไม่เพียงพอหรือ worker หยุดทำงาน ให้ตรวจสอบ System Health ควบคู่กัน
- งาน media generation ที่ค้างนานกว่า 15 นาทีควรตรวจสอบด้วย external task ID ที่ได้รับจาก provider เพื่อดูสถานะจากฝั่งภายนอก
- งาน Failed ที่มี error ซ้ำๆ แบบเดียวกันมักบ่งบอกถึงปัญหา configuration หรือ API key หมดอายุ
- ตรวจสอบ throughput ในช่วง peak hours เพื่อวางแผนการ scale worker ให้เหมาะสมกับปริมาณงาน
- งานที่ค้างในสถานะ Active และ worker ที่รับงานนั้นหยุดทำงานแล้ว จะต้องยกเลิกด้วยตนเองเพราะระบบไม่สามารถ detect ได้อัตโนมัติในทุกกรณี
