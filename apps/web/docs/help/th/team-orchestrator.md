# AI Team Orchestrator — ระบบทีม AI

## AI Team Orchestrator คืออะไร?

AI Team Orchestrator ให้คุณสร้างทีม AI หลายตัวที่ทำงานร่วมกันแบบเรียลไทม์ แต่ละตัวมีบุคลิก ความเชี่ยวชาญ และบทบาทเฉพาะ — ร่วมกันวิจัย เขียน ตรวจทาน และผลิตผลงานที่ agent ตัวเดียวทำไม่ได้

- เหมาะสำหรับงานที่ต้องการ **หลายมุมมอง** — รายงานวิจัย, สร้างเนื้อหา, ตรวจสอบโค้ด
- แต่ละ agent เชี่ยวชาญเรื่องต่างกัน (หัวหน้านักวิจัย, นักเขียน, บรรณาธิการ, ผู้ตรวจสอบความปลอดภัย ฯลฯ)
- ระบบจัดการลำดับการพูด ติดตามงบประมาณ และเงื่อนไขหยุดโดยอัตโนมัติ

## การสร้างทีม

1. ไปที่ **Teams** แล้วกด **New Team**
2. ตั้งชื่อ คำอธิบาย และเลือกหมวดหมู่ (เช่น วิจัย, เนื้อหา, วิศวกรรม)
3. เพิ่ม **สมาชิก 2–10 คน** แต่ละคนต้องมี:
   - **Persona** — เทมเพลตบุคลิกและความเชี่ยวชาญ (เลือกจากคลัง Personas ของคุณ)
   - **Role Title** — ป้ายกำกับ เช่น "หัวหน้านักวิจัย" หรือ "บรรณาธิการ"
   - **Instructions** — คำสั่งเฉพาะว่า agent นี้ควรทำงานอย่างไร
4. กำหนด **สมาชิกหนึ่งคนเป็น Lead** — Lead ประสานงานการอภิปรายและสรุปผลลัพธ์
5. กด **Create Team**

### การใช้ Template

Template ที่มีอยู่ช่วยให้ตั้งค่าได้เร็ว:

| Template | สมาชิก | เหมาะสำหรับ |
|----------|--------|------------|
| **Research & Analysis** | หัวหน้านักวิจัย, นักวิเคราะห์ข้อมูล, ผู้เขียนรายงาน | วิจัยตลาด, วิเคราะห์คู่แข่ง, สืบค้นเชิงเทคนิค |
| **Content Creation** | นักวางกลยุทธ์เนื้อหา (Lead), นักเขียน, บรรณาธิการ | บทความ, การตลาด, เนื้อหาโซเชียลมีเดีย |
| **Code Review** | สถาปนิกหลัก, ผู้ตรวจสอบความปลอดภัย, ผู้ตรวจสอบคุณภาพ | ตรวจ Pull Request, ตรวจสถาปัตยกรรม, วิเคราะห์ Technical Debt |

ในหน้าต่าง **New Team** จะแสดงปุ่มเทมเพลตสำเร็จรูปด้านบน กดเลือกเพื่อสร้างทีมทันที แล้วปรับแต่งสมาชิกตามต้องการ

## ห้องทีม (Team Rooms)

**Room** คือพื้นที่สนทนาของทีม

### การสร้างห้อง

1. เลือกทีม
2. ระบุ **เป้าหมาย** — เช่น "วิจัยเครื่องมือ CRM 5 อันดับแรกสำหรับธุรกิจขนาดเล็ก แล้วแนะนำตัวที่ดีที่สุด"
3. เลือก **ประเภทห้อง**:
   - **Team** — อภิปรายร่วมกันหลาย agent (ใช้บ่อยที่สุด)
   - **Direct** — คุยตัวต่อตัวกับ agent เฉพาะ
   - **Auto Team** — ระบบจัดการอัตโนมัติ ผู้ใช้มีส่วนร่วมน้อย
   - **Job Review** — ตรวจงานแบบมีโครงสร้าง

### โหมดมุมมอง

ควบคุมระดับรายละเอียดที่เห็นในสนทนา:

| โหมด | สิ่งที่เห็น |
|------|-----------|
| **Transparent** | ทุกอย่าง — ข้อความ agent ทั้งหมด, การคิดภายใน, การส่งต่องาน |
| **Milestone** | เฉพาะการตัดสินใจสำคัญและเหตุการณ์หลัก |
| **Summary** | เฉพาะสรุปและข้อสรุปสุดท้าย |

### การส่งข้อความ

- ส่งข้อความถึง **agent ทุกตัว** โดยพิมพ์ในช่องข้อความแล้วกด **Enter** หรือคลิก **Send**
- ข้อความระบบ (แจ้งเตือนงบประมาณ, error) แสดงด้วยสไตล์ต่างออกไป

## Runs — การรันงานอัตโนมัติ

**Run** คือเซสชันทำงานอัตโนมัติภายในห้อง

### การเริ่มรัน

1. เปิดห้องแล้วกด **Start Run**
2. ตั้ง **เป้าหมาย** — สิ่งที่ทีมควรทำให้สำเร็จ
3. ตั้ง **Stop Policy**:
   - **จำนวนรอบสูงสุด** (ค่าเริ่มต้น 20) — จำนวนรอบ agent ก่อนหยุดอัตโนมัติ
   - **เวลาสูงสุด** (ค่าเริ่มต้น 30 นาที) — จำกัดเวลาทั้งรัน
   - **งบสูงสุด** — เพดานเครดิตป้องกันค่าใช้จ่ายเกิน
   - **หมดเวลาว่าง** (ค่าเริ่มต้น 120 วินาที) — หยุดอัตโนมัติถ้าไม่มี agent ทำงาน
   - **หยุดเมื่อ Lead สรุป** — จบเมื่อ Lead สร้างสรุป
   - **หยุดเมื่อเห็นพ้อง** — จบเมื่อ agent เห็นพ้องกัน
   - **ต้องสรุปผล** — สร้างรายงานสรุปเมื่อจบ

### การควบคุมรัน

| การกระทำ | ใช้เมื่อไหร่ |
|---------|------------|
| **Pause** | ตรวจสอบความคืบหน้าระหว่างรันโดยไม่สูญเสีย context |
| **Resume** | ทำต่อจากจุดที่หยุดไว้ |
| **Stop** | หยุดรันทันที สร้างสรุปผล |

### การติดตามงบประมาณ

- Token ที่ใช้ (input + output) และค่าใช้จ่ายต่อ agent ติดตามแบบเรียลไทม์
- **Budget Snapshot** แสดงค่าใช้จ่ายต่อ agent
- ถ้าเกิน `maxBudgetCredits` รันหยุดอัตโนมัติพร้อมเหตุผล "budget_exceeded"

### เมื่อรันเสร็จ

เมื่อรันจบ (จาก stop policy หรือหยุดเอง):

1. **สรุปผลต่อ Agent** — สถิติต่อ agent รวมจำนวนรอบ, token ที่ใช้, ค่าใช้จ่าย, การเรียกเครื่องมือ, และจำนวน error
2. ถ้าเปิด **ต้องสรุปผล** จะสร้างรายงานมีโครงสร้างพร้อมการตัดสินใจ ข้อค้นพบ ผลงาน และขั้นตอนถัดไป
3. ส่ง **การแจ้งเตือน** ถึงคุณ

## Unified Skill Execution ใน Team Room

เมื่อเปิดใช้ flag `unifiedSkillExecution` การเรียก skill ทุกครั้งภายในทีมรันจะถูกประมวลผลผ่าน **unified orchestrator** — pipeline เดียวกับที่ Chat ใช้:

- **ข้ามช่องทางอย่างสม่ำเสมอ** — skill เดียวกันให้ผลลัพธ์เหมือนกันไม่ว่าจะมาจากมนุษย์ใน Chat หรือ agent ใน Team Room
- **เลือก Executor อัตโนมัติ** — skill ข้อความ, รูปภาพ, วิดีโอ และเสียงถูกส่งไปยัง executor เฉพาะทาง
- **เลือกโมเดลแบบ dynamic** — เลือกโมเดลตาม skill requirement (vision สำหรับรูปภาพ, thinking mode สำหรับงานวิเคราะห์, web search สำหรับงานวิจัย)
- **Rate limit ต่อผู้ใช้** — ป้องกัน agent ใช้เครดิตมากเกินไป
- **บันทึกตรวจสอบครบถ้วน** — ทุกการรันบันทึกด้วย event `unified_route`, `unified_credit` และ `unified_error`

หาก orchestrator เกิดข้อผิดพลาด ระบบจะ **re-throw** เพื่อป้องกัน double execution (Team Room จะไม่ fallback ไปใช้ path เดิมหาก orchestrator ได้ทำรายการเครดิตหรือ audit ไปแล้ว)

## เคล็ดลับสำหรับทีมที่มีประสิทธิภาพ

1. **เริ่มจาก Template** แล้วปรับแต่ง — เร็วกว่าสร้างใหม่ตั้งแต่ต้น
2. **ให้แต่ละ agent มีความเชี่ยวชาญเฉพาะ** บทบาทที่ซ้ำกันจะได้ผลลัพธ์ซ้ำซ้อน
3. **ตั้งงบประมาณที่เหมาะสม** (100–500 เครดิต) และจำนวนรอบ (10–30) เพื่อป้องกันค่าใช้จ่ายบานปลาย
4. **ใช้โหมด Milestone** เมื่อสนใจเฉพาะการตัดสินใจสำคัญ ไม่ต้องอ่านทั้งหมด
5. **ตรวจสอบสรุปของ Lead** ก่อนหยุดรัน — สรุปจะรวมข้อสรุปของทีมทั้งหมด
6. **Pause เพื่อแทรกแซง** — ถ้า agent ออกนอกเรื่อง ให้ pause ส่งข้อความแก้ไข แล้ว resume
