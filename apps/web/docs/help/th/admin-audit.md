# บันทึกการตรวจสอบ

## ภาพรวม

Audit Log คือบันทึกที่เชื่อถือได้ของทุกสิ่งที่เกิดขึ้นบนแพลตฟอร์ม — ทุกคำขอ LLM การสร้างสื่อ การรัน Skill การดำเนินการ Admin และข้อผิดพลาด ใช้เพื่อตรวจสอบปัญหาที่ผู้ใช้รายงาน ยืนยันการเรียกเก็บเงิน ตรวจสอบ Security Event และติดตามคำขอตั้งแต่ต้นจนจบ

## การค้นหา Audit Logs

- **ช่วงวันที่** — จำกัดเป็นช่วงเวลาเฉพาะ
- **ผู้ใช้** — กรองเหตุการณ์ทั้งหมดจากบัญชีเดียว
- **ประเภทเหตุการณ์** — เลือกหมวดหมู่เหตุการณ์หนึ่งหรือหลายหมวด (ดูด้านล่าง)
- **Trace ID** — วาง Trace ID เพื่อดูทุกเหตุการณ์ในวงจรชีวิตของคำขอเดียว
- **สถานะ** — กรองเฉพาะข้อผิดพลาด หรือยกเว้นข้อผิดพลาดเพื่อดูเหตุการณ์ที่สำเร็จ

ผลลัพธ์แสดงจากใหม่สุด แต่ละแถวแสดง Timestamp ผู้ใช้ ประเภทเหตุการณ์ โมเดล/Skill (เมื่อเกี่ยวข้อง) ระยะเวลา และสถานะ

## ประเภทเหตุการณ์

| ประเภทเหตุการณ์ | คำอธิบาย |
|---|---|
| `llm_request` | คำขอที่ส่งไปยัง LLM Provider — รวมถึงโมเดล Token ขาเข้า พารามิเตอร์ |
| `llm_response` | การตอบกลับที่ได้รับ — รวมถึง Token ขาออก ต้นทุน Latency ของ Provider |
| `media_request` | งานสร้างสื่อที่ส่ง — Prompt โมเดล รูปอ้างอิง |
| `media_response` | การสร้างสื่อเสร็จสมบูรณ์หรือล้มเหลว — URL ผลลัพธ์หรือรายละเอียดข้อผิดพลาด |
| `skill_detect` | ผลการตรวจจับ Skill — Skill ใดที่จับคู่และคะแนนความมั่นใจ |
| `skill_execute` | การรัน Skill — พารามิเตอร์ที่แยกออก ชื่อ Skill โหมดการรัน |
| `admin_action` | การดำเนินการ Admin ใดก็ตาม — แก้ไขผู้ใช้ ปรับเครดิต เปลี่ยนการตั้งค่า |
| `auth` | เหตุการณ์ Login, Logout, Token Refresh, 2FA |
| `error` | ข้อผิดพลาดที่ไม่ได้จัดการทั่วทุก Subsystem |

## การวิเคราะห์ Trace

ทุกคำขอที่เข้าสู่ระบบจะได้รับ **Trace ID** เฉพาะ ใช้เพื่อติดตามคำขอจากตอนที่มาถึงจนถึงการตอบกลับสุดท้าย:

1. ค้นหาด้วย Trace ID
2. ผลลัพธ์แสดงเหตุการณ์ทั้งหมดที่แท็กด้วย Trace นั้นตามลำดับเวลา
3. คุณสามารถเห็นห่วงโซ่ทั้งหมด คำขอ → การตรวจจับ Skill → การเรียก LLM → การตอบกลับ ในมุมมองเดียว
4. คอลัมน์ Timing แสดงว่าแต่ละขั้นตอนใช้เวลานานเท่าไร ทำให้มองเห็น Bottleneck ได้ทันที

## การตรวจสอบต้นทุน

- เปรียบเทียบ `llm_response.costUsd` กับ `creditTransactions.amount` สำหรับ Trace ID เดียวกัน
- ตรวจสอบ `costCalculationMethod` บนแต่ละ Response Event — ค่าได้แก่ `provider-reported`, `model-lookup` หรือ `default-rate`
- สำหรับความคลาดเคลื่อน: ตรวจสอบตารางราคาโมเดลใน **Admin → Providers → Models**
- Export ผลลัพธ์ที่กรองแล้วเป็น CSV สำหรับการตรวจสอบในเครื่องมือภายนอก

## Orchestration Logs

แท็บ **Orchestration Logs** แสดง Execution Trace สำหรับ Agency Workflow และห่วงโซ่ Skill หลายขั้นตอน:

- การรัน Agency แต่ละครั้งมี Root Trace พร้อม Child Span สำหรับทุก Agent Node ที่รัน
- Log ระดับ Node แสดง Agent ที่ถูกเรียก Input ที่ได้รับ และสิ่งที่ส่งกลับ
- Node ที่ล้มเหลวแสดง Exception และสถานะของ Workflow ณ จุดที่ล้มเหลว
- ใช้ **Visual Timeline** เพื่อดู Execution Path แบบขนานและแบบลำดับ

## การ Export

- คลิก **Export CSV** เพื่อดาวน์โหลดชุดผลลัพธ์ที่กรองในปัจจุบัน
- Export ขนาดใหญ่ (มากกว่า 10,000 แถว) จะประมวลผลแบบ Asynchronous — ลิงก์ดาวน์โหลดจะส่งทางอีเมลไปยัง Admin ที่ขอ
- ไฟล์ที่ Export จะเก็บไว้ 24 ชั่วโมง
- สำหรับการเก็บรักษา Compliance และระยะยาว กำหนดค่า Log Forwarding ไปยัง SIEM ภายนอกใน **Admin → System Settings → Integrations**
