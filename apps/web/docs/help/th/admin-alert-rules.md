# กฎแจ้งเตือนและการยกระดับ

## ภาพรวม

หน้า Alert Rules ให้ผู้ดูแลระบบกำหนดเกณฑ์แจ้งเตือนตามเมตริก และนโยบายการยกระดับ เมื่อเมตริกเกินเกณฑ์ที่กำหนด ระบบจะสร้างการแจ้งเตือนให้กลุ่มเป้าหมาย หากแจ้งเตือนระดับวิกฤตไม่ได้รับการตอบรับ นโยบายการยกระดับจะแจ้งเตือนผู้รับผิดชอบระดับสูงโดยอัตโนมัติ

**Feature flag:** ต้องเปิดใช้งาน `notificationPreferencesEnabled` เพื่อให้หน้านี้ปรากฏ

## กฎแจ้งเตือน

### การสร้างกฎ

แต่ละกฎจะตรวจสอบเมตริกที่กำหนดและทริกเกอร์เมื่อเกินเกณฑ์:

- **ชื่อกฎ** — ชื่อที่อธิบายกฎ (เช่น "อัตรา Error ของ LLM สูง")
- **เมตริก** — เมตริกที่ต้องการตรวจสอบ (เช่น `llm_error_rate`, `queue_depth`, `response_latency_p95`)
- **ตัวดำเนินการ** — ตัวเปรียบเทียบ: มากกว่า, น้อยกว่า, เท่ากับ เป็นต้น
- **เกณฑ์** — ค่าตัวเลขที่ทริกเกอร์การแจ้งเตือน
- **หน้าต่างเวลา** — ช่วงเวลาเป็นนาทีสำหรับการรวมข้อมูล (ค่าเริ่มต้น: 5 นาที)
- **ระดับความรุนแรง** — ระดับความสำคัญของการแจ้งเตือนเมื่อทริกเกอร์: low, normal, high หรือ critical
- **คูลดาวน์** — จำนวนนาทีขั้นต่ำระหว่างการแจ้งเตือนซ้ำของกฎเดียวกัน (ป้องกันการแจ้งเตือนถล่ม)
- **เป้าหมาย** — ผู้ที่จะได้รับแจ้งเตือน: บทบาทเฉพาะ (เช่น admin) หรือผู้ใช้เฉพาะราย
- **ช่องทาง** — ช่องทางการส่ง: ในแอป, อีเมล หรือทั้งสอง

### การจัดการกฎ

- **เปิด / ปิดใช้งาน** — สลับกฎแต่ละข้อโดยไม่ต้องลบ
- **แก้ไข** — เปลี่ยนพารามิเตอร์ใดๆ ของกฎที่มีอยู่
- **ลบ** — ลบกฎออกอย่างถาวร
- กฎจะถูกแยกตาม Tenant — แต่ละ Tenant จัดการชุดกฎของตนเอง

## นโยบายการยกระดับ

นโยบายการยกระดับช่วยให้มั่นใจว่าแจ้งเตือนวิกฤตจะไม่ถูกมองข้าม เมื่อการแจ้งเตือนที่มีระดับความรุนแรงที่กำหนดไม่ได้รับการตอบรับเป็นเวลานานเกินไป ระบบจะสร้างการแจ้งเตือนยกระดับใหม่ให้เป้าหมายที่กำหนดโดยอัตโนมัติ

### การสร้างนโยบาย

- **ชื่อ** — ชื่อที่อธิบายนโยบาย (เช่น "ยกระดับวิกฤต 15 นาที")
- **ระดับความรุนแรงที่ทริกเกอร์** — ระดับที่ต้องเฝ้าดู (โดยทั่วไปคือ "critical" หรือ "high")
- **ทริกเกอร์หลัง (นาที)** — ระยะเวลาที่การแจ้งเตือนต้องยังไม่ถูกอ่านก่อนจะยกระดับ
- **ยกระดับไปยัง** — เลือกอย่างใดอย่างหนึ่ง:
  - **บทบาท** (เช่น admin) — ผู้ใช้ทุกคนที่มีบทบาทนั้นจะได้รับการยกระดับ
  - **ผู้ใช้เฉพาะราย** — เฉพาะผู้ใช้คนนั้นเท่านั้นที่จะได้รับ
- **ข้อความยกระดับ** — ข้อความกำหนดเองสำหรับการแจ้งเตือนยกระดับ (ไม่บังคับ)
- **ช่องทาง** — ช่องทางสำหรับการยกระดับ: ในแอป, อีเมล หรือทั้งสอง

### วิธีการทำงานของการยกระดับ

1. BullMQ Job ทำงานทุก 5 นาที ตรวจสอบนโยบายการยกระดับที่เปิดใช้งานทั้งหมด
2. สำหรับแต่ละนโยบาย จะค้นหาการแจ้งเตือนที่ยังไม่ได้รับทราบที่ตรงกับระดับความรุนแรงและเก่ากว่าหน้าต่างเวลาที่กำหนด
3. สร้างการแจ้งเตือนยกระดับใหม่พร้อม metadata `isEscalated: true` สำหรับแต่ละเป้าหมาย
4. การแจ้งเตือนที่ยกระดับแล้วจะข้ามตัวกรองการตั้งค่าของผู้ใช้ — ส่งเสมอ
5. การแจ้งเตือนต้นฉบับจะถูกทำเครื่องหมาย `escalatedAt` เพื่อป้องกันการยกระดับซ้ำ

### การจัดการนโยบาย

- **เปิด / ปิดใช้งาน** — สลับนโยบายเปิด/ปิด
- **แก้ไข** — เปลี่ยนเงื่อนไขการทริกเกอร์หรือเป้าหมาย
- **ลบ** — ลบนโยบายอย่างถาวร
- นโยบายจะถูกแยกตาม Tenant และเคารพ Feature Flag ของ Tenant

## เคล็ดลับ

- เริ่มต้นด้วยคูลดาวน์ที่ยาว (เช่น 30 นาที) แล้วปรับให้สั้นลงเมื่อเข้าใจรูปแบบการแจ้งเตือน
- ใช้นโยบายการยกระดับสำหรับแจ้งเตือนธุรกิจวิกฤต — ตั้งหน้าต่างเวลาเพื่อให้ทีมหลักมีเวลาตอบสนองก่อนยกระดับ
- Escalation Job ตรวจสอบ Feature Flag ต่อ Tenant — ปิด `notificationEscalationEnabled` เพื่อหยุดการยกระดับทั้งหมดโดยไม่ต้องลบนโยบาย
- รวมกฎแจ้งเตือนกับการตั้งค่าการแจ้งเตือนเพื่อให้ผู้ใช้ได้รับแจ้งเตือนเฉพาะหมวดหมู่ที่สนใจ
