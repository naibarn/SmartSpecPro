# การจับคู่โมเดล LLM

## ภาพรวม

หน้า LLM Model Mappings ช่วยให้แอดมินจัดการแค็ตตาล็อกโมเดลภาษาที่พร้อมใช้บนแพลตฟอร์ม กำหนดค่าว่าโมเดลใดเปิดใช้ กำหนดโมเดลให้ผู้ให้บริการ และตั้งค่าเริ่มต้นสำหรับแต่ละความสามารถ

## แค็ตตาล็อกโมเดล

หน้าแสดงโมเดล LLM ทั้งหมดจัดกลุ่มตามผู้ให้บริการ:

- **ชื่อโมเดล** — ตัวระบุ (เช่น `gpt-4o`, `claude-sonnet-4-20250514`, `gemini-pro`)
- **ผู้ให้บริการ** — OpenAI, Anthropic, Google, Groq, local ฯลฯ
- **ความสามารถ** — แชท, completion, vision, function calling
- **สถานะ** — เปิดหรือปิด
- **ราคา** — ราคา token ขาเข้า/ขาออก

## การเปิดและปิด

สลับสวิตช์ข้างโมเดลเพื่อควบคุมการเข้าถึง:

- **เปิด** — โมเดลปรากฏในตัวเลือกโมเดลแชทและสามารถใช้โดย skill
- **ปิด** — ซ่อนจากผู้ใช้ ไม่มี request ส่งไปยังโมเดลนี้

## การตั้งค่าโมเดลเริ่มต้น

ตั้งโมเดลเริ่มต้นสำหรับแต่ละความสามารถ:

- **Chat default** — โมเดลที่ถูกเลือกไว้เมื่อผู้ใช้เปิดแชทใหม่
- **Skill execution** — โมเดลที่ใช้เมื่อ skill ไม่ได้ระบุ
- **Vision** — โมเดลเริ่มต้นสำหรับงานเข้าใจรูปภาพ

กำหนดค่าเริ่มต้นในส่วน **Defaults** ด้านบนของหน้า

## กลุ่มโมเดล

โมเดลถูกจัดเป็นกลุ่มสำหรับ UI ตัวเลือก:

- **Premium** — คุณภาพสูงสุด ราคาสูงกว่า (GPT-4, Claude Opus)
- **Standard** — สมดุลคุณภาพและราคา (GPT-4o-mini, Claude Sonnet)
- **Fast** — latency ต่ำสุด ราคาต่ำสุด (Groq, โมเดล local)

## การกำหนดค่าราคา

แต่ละโมเดลมีราคาที่ปรับได้:

- **ราคาขาเข้า** — ราคาต่อ 1K input token
- **ราคาขาออก** — ราคาต่อ 1K output token
- **ตัวคูณเครดิต** — เครดิตผู้ใช้กี่หน่วยเท่ากับหนึ่งหน่วยราคา

## เคล็ดลับ

- เปิดอย่างน้อยหนึ่งโมเดลต่อหมวดหมู่ความสามารถ
- ตั้งโมเดลที่คุ้มค่าเป็นค่าเริ่มต้นเพื่อจัดการการใช้เครดิต
- ปิดโมเดลที่ผู้ให้บริการไม่พร้อมใช้งานชั่วคราว
