# การติดตามทีมและ Scoped Memory

## Run Monitor Panel

Run Monitor แสดงสถานะแบบเรียลไทม์ของรันที่กำลังทำงาน แผงนี้ปรากฏทางขวาเมื่อมีรันที่กำลังดำเนินอยู่

### สิ่งที่เห็น

- **แถบสถิติ** — ตัวนับ 3 ตัว แสดงจำนวน event ทั้งหมด, token ที่ใช้ และ agent ที่กำลังทำงาน
- **รายชื่อ Agent** — ชื่อ, บทบาท, จำนวนรอบ และสถานะ (กำลังทำงาน/ว่าง) ของแต่ละ agent โดย Lead จะมี badge กำกับ
- **Timeline เหตุการณ์** — log เลื่อนได้ของทุกการกระทำ: ข้อความที่ส่ง, การเรียกเครื่องมือ, การส่งต่องาน, การตัดสินใจ และ error
- **สถานะการเชื่อมต่อ** — จุดสีเขียว = สตรีมสดเชื่อมต่ออยู่; สีเทา = ขาดการเชื่อมต่อ (เชื่อมต่อใหม่อัตโนมัติ)

### การควบคุมรัน

| ปุ่ม | สิ่งที่ทำ |
|------|---------|
| **Pause** | หยุดรันชั่วคราว agent หยุดทำงาน แต่สถานะถูกเก็บไว้สำหรับ resume |
| **Resume** | ทำต่อจากจุดที่หยุดไว้พอดี |
| **Stop** | จบรัน สร้างสรุปผลต่อ agent และรายงานสุดท้าย (ถ้าเปิดไว้) |

### ประเภท Event

| ไอคอน | Event | คำอธิบาย |
|-------|-------|---------|
| 💬 | ข้อความ | agent ส่งการตอบกลับ |
| 🚀 | รันเริ่ม | รันเริ่มดำเนินการ |
| ✅ | รันเสร็จ | รันจบสำเร็จ |
| ⏸️ | รันหยุดชั่วคราว | ผู้ใช้กด pause |
| 🔧 | เรียกเครื่องมือ | agent ใช้เครื่องมือ (ค้นหา, รันโค้ด ฯลฯ) |
| 🤝 | ส่งต่องาน | agent ส่งสนทนาต่อให้ agent อื่น |
| ❌ | Error | เกิดข้อผิดพลาด (ลองใหม่อัตโนมัติ) |
| 🔄 | เปลี่ยนสถานะ | agent เปลี่ยนสถานะ (กำลังทำงาน ↔ ว่าง) |

## Scoped Memory — หน่วยความจำแบบแบ่งขอบเขต

ทีม AI แต่ละทีมใช้ระบบหน่วยความจำแบบลำดับชั้นที่มีการแยกขอบเขตอย่างเข้มงวด

### ขอบเขตหน่วยความจำ

ขอบเขตควบคุมว่าใครอ่านและเขียนหน่วยความจำได้:

| ขอบเขต | เจ้าของ | ใครอ่านได้ |
|--------|--------|-----------|
| **Agent** | agent แต่ละตัว | เฉพาะ agent นั้น (ส่วนตัว) |
| **Run** | เซสชันรันปัจจุบัน | agent ทุกตัวในรัน |
| **Room** | ห้องสนทนา | ผู้เข้าร่วมทุกคนในห้อง |
| **Team** | ทีมทั้งหมด | agent ทุกตัวในทีม |
| **Project** | แท็กโปรเจกต์ | ผู้ใช้/agent ทั้งหมดในโปรเจกต์ |
| **User** | คุณ (ผู้ใช้) | สนทนาทั้งหมดของคุณ |

### ลำดับความสำคัญ

เมื่อค้นหาหน่วยความจำ ผลลัพธ์จากขอบเขตเฉพาะเจาะจงกว่าจะอันดับสูงกว่า:

**Agent → Run → Room → Team → Project → User**

ถ้าข้อมูลเดียวกันมีทั้งในขอบเขต Agent และ Team จะใช้เวอร์ชันของ Agent

### ประเภทหน่วยความจำ

| ประเภท | ใช้สำหรับ |
|--------|---------|
| **Fact** | ข้อมูลที่ยืนยันแล้ว |
| **Rule** | ข้อจำกัดที่ต้องปฏิบัติตามเสมอ |
| **Preference** | วิธีทำงานที่ชอบ |
| **Decision** | การตัดสินใจที่เกิดขึ้นระหว่างอภิปราย |
| **Note** | ข้อสังเกตทั่วไป |
| **Checklist** | รายการขั้นตอน |
| **Artifact Note** | บันทึกเกี่ยวกับผลงานที่สร้าง |
| **Handoff Note** | context สำหรับการส่งต่องานระหว่าง agent |
| **Episode** | บันทึกสนทนาทั้งตอนเพื่ออ้างอิง |

### การค้นหาหน่วยความจำ

ระบบค้นหาใช้ **Hybrid Retrieval**:

1. **จับคู่คำสำคัญ** — หาหน่วยความจำที่มีคำค้นหาของคุณ
2. **ความคล้ายคลึงเชิงเวกเตอร์** — หาหน่วยความจำที่มีความหมายคล้ายกัน (แม้ใช้คำต่างกัน)
3. **คะแนนรวม** — 40% คำสำคัญ + 60% ความคล้ายคลึงเวกเตอร์ ถ่วงน้ำหนักด้วยความสำคัญและความใหม่

### การ Promote หน่วยความจำ

ย้ายหน่วยความจำจากขอบเขตแคบไปขอบเขตกว้าง:

1. หาหน่วยความจำในแผง Memory
2. กด **Promote**
3. เลือกขอบเขตปลายทาง (เช่น Agent → Team)
4. เพิ่มเหตุผลได้ตามต้องการ

มีประโยชน์เมื่อ agent ค้นพบสิ่งที่ทั้งทีมควรรู้

## การแจ้งเตือน

การแจ้งเตือน Orchestrator ช่วยให้คุณรับทราบกิจกรรมของทีม

### ประเภทการแจ้งเตือน

| ประเภท | ระดับ | เกิดเมื่อไหร่ |
|--------|------|-------------|
| **รันเสร็จ** | ข้อมูล | รันจบสำเร็จ |
| **เตือนงบประมาณ** | คำเตือน | การใช้เครดิตใกล้ถึงขีดจำกัด |
| **Agent ค้าง** | คำเตือน | agent ไม่มีผลงาน 2+ นาที |
| **งบเกิน** | Error | รันหยุดอัตโนมัติเพราะเกินค่าใช้จ่าย |
| **แจ้งเตือนระบบ** | วิกฤต | ปัญหาโครงสร้างพื้นฐานที่กระทบการทำงานของทีม |

### การจัดการแจ้งเตือน

- แจ้งเตือนที่ยังไม่อ่านแสดง badge จำนวน
- กดเพื่อ mark as read หรือ dismiss เพื่อซ่อนถาวร
- แจ้งเตือนมี **deep link** — กดเพื่อไปยังห้องหรือรันที่เกี่ยวข้องโดยตรง

## การตรวจจับ Agent ค้าง

ระบบติดตาม agent ที่ค้างโดยอัตโนมัติ:

- ถ้าไม่มีกิจกรรมของ agent เป็นเวลา **2 นาที** จะเกิดการแจ้งเตือน "ค้าง"
- คุณจะเห็นชื่อ agent ที่ค้างและระยะเวลาที่ว่าง
- ตัวเลือก: **Resume** (ลองใหม่), **Stop** รัน หรือ **Mute** agent ที่ค้างแล้วทำต่อกับตัวอื่น

## การสตรีมสด (SSE)

ห้องทีมใช้ Server-Sent Events (SSE) สำหรับอัปเดตแบบเรียลไทม์:

- Event สตรีมอัตโนมัติเมื่อมีรันที่กำลังทำงาน
- ถ้าขาดการเชื่อมต่อ ระบบ **เชื่อมต่อใหม่อัตโนมัติ** ด้วย exponential backoff
- **Last-Event-ID** ป้องกันไม่ให้พลาด event ระหว่างขาดการเชื่อมต่อสั้นๆ
- Heartbeat รักษาการเชื่อมต่อ (ทุก 15 วินาที)
- ระยะเวลาเชื่อมต่อสูงสุด 30 นาที (เชื่อมต่อใหม่อัตโนมัติหลังจากนั้น)
