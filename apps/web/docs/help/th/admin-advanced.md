# การจัดการขั้นสูง

## ภาพรวม

การจัดการขั้นสูงครอบคลุม admin surfaces พิเศษที่เกินกว่าการจัดการผู้ใช้ provider และการตั้งค่าพื้นฐาน หน้าเหล่านี้ให้ผู้ดูแลแพลตฟอร์มมองเห็นและควบคุม agencies, สภาพแวดล้อม multi-tenant, สุขภาพระบบ และการกำกับดูแลอัตโนมัติได้อย่างเต็มรูปแบบ

## การจัดการ Agency (/admin/agencies)

หน้า admin ของ Agencies ให้ผู้ดูแลระบบดูแล agencies ทั้งหมดที่ผู้ใช้สร้างบนแพลตฟอร์ม

- **แสดงรายการ agencies ทั้งหมด** — ค้นหาและกรองตามผู้สร้าง สถานะ ประเภทเทมเพลต หรือวันที่สร้าง
- **ตรวจสอบการกำหนดค่า agency** — ดูการตั้งค่า agent, เครื่องมือ และ system prompts สำหรับ agency ใดก็ได้
- **เปิด / ปิดใช้งาน** — สลับว่า agency พร้อมใช้งานสำหรับเจ้าของหรือไม่
- **ลบ** — ลบ agency และประวัติ run อย่างถาวร (ต้องยืนยัน)
- ใช้หน้านี้เพื่อบังคับใช้นโยบายเนื้อหาหรือตรวจสอบ agencies ที่สร้างผลลัพธ์ที่ไม่คาดคิด

## Approval Workflows (/admin/approvals)

การกำหนดค่า agency บางอย่างต้องการขั้นตอนการอนุมัติจากมนุษย์ก่อนดำเนินการต่อ หน้า Approvals คือคิวสำหรับการตัดสินใจที่รออยู่เหล่านั้น

- **การอนุมัติที่รออยู่** — รายการ agency run ที่หยุดที่ approval gate พร้อมผู้ใช้ที่ร้องขอ ชื่อ agency และขั้นตอนที่รอการอนุมัติ
- **ตรวจสอบ** — เปิด context ของ run ดูว่า agent กำลังเสนอให้ทำอะไร และตัดสินใจว่าจะอนุมัติหรือปฏิเสธ
- **อนุมัติ** — agency ดำเนินการต่อจากขั้นตอนการอนุมัติ
- **ปฏิเสธ** — agency ถูกยกเลิกและผู้ใช้ได้รับแจ้งพร้อมเหตุผลของคุณ
- **Bulk actions** — อนุมัติหรือปฏิเสธรายการที่รออยู่หลายรายการพร้อมกัน

Approval gates กำหนดค่าต่อ agency ใน Agency Builder ดูรายละเอียดการตั้งค่าในคู่มือ [Agency Builder](/help/agency-builder)

## การจัดการ Multi-Tenant (/admin/tenants)

หากการติดตั้งของคุณรองรับ tenant หลายราย (องค์กรที่มีสภาพแวดล้อม isolated ของตนเอง) ให้จัดการที่นี่

- **สร้าง tenant** — จัดเตรียม tenant ใหม่พร้อมชื่อโดเมน ชื่อที่แสดง และผู้ใช้ admin เริ่มต้น
- **กำหนดค่า tenant** — ตั้ง feature flags, ขีดจำกัดเครดิต, โควตา storage และ branding ต่อ tenant
- **การกำหนดโดเมน** — map โดเมนหนึ่งหรือมากกว่าไปยัง tenant เพื่อการแก้ไข tenant อัตโนมัติ
- **ระงับ / เปิดใช้งานใหม่** — บล็อกการเข้าถึงทั้งหมดสำหรับ tenant ชั่วคราวโดยไม่ลบข้อมูล
- **ลบ tenant** — ลบ tenant และข้อมูลที่เกี่ยวข้องทั้งหมดอย่างถาวร การดำเนินการนี้ย้อนกลับไม่ได้และต้องพิมพ์ยืนยัน

## Operations Dashboard (/admin/ops)

Operations Dashboard ให้มุมมอง real-time ของสุขภาพและประสิทธิภาพของแพลตฟอร์ม

- **Request throughput** — ข้อความต่อนาที, LLM request ต่อนาที
- **Latency percentiles** — เวลาตอบสนอง p50, p95, p99 สำหรับคำขอ LLM และสื่อ
- **Error rates** — เปอร์เซ็นต์คำขอที่ล้มเหลวในช่วง 5, 15 และ 60 นาทีที่ผ่านมา
- **Queue depths** — ความยาวปัจจุบันของคิว LLM, สื่อ และงานเบื้องหลัง
- **Active sessions** — จำนวนผู้ใช้ที่เชื่อมต่ออยู่และ live browser sessions

## Funnel Analytics (/admin/funnel)

หน้า Funnel แสดงว่าผู้ใช้ดำเนินการจากการสมัครไปสู่การใช้งานจริงอย่างไร

- **การลงทะเบียน → การเข้าสู่ระบบครั้งแรก** — การ drop-off ระหว่างการสร้างบัญชีและการเข้าสู่ระบบครั้งแรก
- **การเข้าสู่ระบบครั้งแรก → Chat ครั้งแรก** — ผู้ใช้เริ่มมีส่วนร่วมเร็วแค่ไหน
- **Chat ครั้งแรก → การใช้ฟีเจอร์** — ฟีเจอร์ใดที่ผู้ใช้ใหม่สำรวจก่อน
- **Conversion เมื่อเวลาผ่านไป** — เมตริก funnel ตามวัน สัปดาห์ หรือเดือน

ใช้ข้อมูล funnel เพื่อระบุจุดที่มีความขัดแย้งในขั้นตอน onboarding และจัดลำดับความสำคัญของการปรับปรุง

## Service Status (/admin/services)

หน้า Services แสดงสุขภาพของทุก component backend ที่แพลตฟอร์มพึ่งพา

| Service | สิ่งที่ตรวจสอบ |
|---|---|
| PostgreSQL | Connection pool, latency ของ query, replication lag |
| Redis | การใช้ memory, จำนวน connection, อัตราการขับออก |
| Celery workers | จำนวน worker, ความยาวคิว, อัตราความล้มเหลวของงาน |
| LLM providers | เวลาตอบสนอง, อัตราข้อผิดพลาด, สถานะ circuit breaker |
| Storage (S3/R2) | อัตราความสำเร็จในการ upload/download, latency |

- **สีเขียว** — สุขภาพดี ทำงานภายในพารามิเตอร์ปกติ
- **สีเหลือง** — degraded บางเมตริกสูงกว่าเกณฑ์แต่ service ยังทำงาน
- **สีแดง** — วิกฤต service ล่มหรือ degraded อย่างรุนแรง

คลิก service ใดก็ได้เพื่อดูรายละเอียดพร้อมเมตริกล่าสุดและ error logs

## Channel Router (/admin/channel-router)

Channel Router ควบคุมวิธีการ route ข้อความระหว่างผู้ใช้ agent และ AI models

- **Routing rules** — กำหนดกฎที่นำประเภทข้อความเฉพาะไปยัง provider หรือโมเดลเฉพาะ
- **Priority** — ตั้งลำดับความสำคัญของกฎเมื่อกฎหลายข้อตรงกับข้อความเดียวกัน
- **Default channel** — โมเดล fallback เมื่อไม่มีกฎ routing ตรงกัน
- **Test routing** — ป้อนข้อความตัวอย่างและดูว่าจะถูก route ไปยังโมเดลใด

## System Guardian (/admin/system-guardian)

System Guardian คือระบบตรวจสอบสุขภาพอัตโนมัติที่ประเมินแพลตฟอร์มตามชุดกฎและเรียกการแจ้งเตือนหรือการดำเนินการเมื่อเกณฑ์ถูกละเมิด

- **กฎ** — รายการกฎเชิงตรรกะ 18+ ข้อที่ครอบคลุมการหมดเครดิต การสำรองคิว การพุ่งสูงของอัตราข้อผิดพลาด และการหยุดทำงานของ provider
- **สถานะกฎ** — แต่ละกฎแสดงสถานะ pass/fail ปัจจุบันและเวลาที่ประเมินล่าสุด
- **การแจ้งเตือน** — กำหนดค่าว่าจะส่งการแจ้งเตือนที่ไหน (อีเมล, webhook) เมื่อกฎล้มเหลว
- **Auto-remediation** — กฎบางข้อสามารถเรียกการดำเนินการอัตโนมัติ (รีเซ็ต circuit breaker, รีสตาร์ท worker) โดยไม่ต้องมีการแทรกแซงจากมนุษย์
- **Audit log** — การประเมินกฎ การแจ้งเตือน และการดำเนินการแก้ไขทุกอย่างถูกบันทึกไว้

## Feedback Hub (/admin/feedback-hub)

Feedback Hub รวบรวม feedback ของผู้ใช้ที่ส่งผ่านกลไก feedback ในแอป

- **Feedback ทั้งหมด** — รายการ feedback ที่กรองได้ตามคะแนน พื้นที่ฟีเจอร์ และวันที่
- **แนวโน้ม sentiment** — sentiment เชิงบวก/ลบรวมตามเวลา
- **ปัญหาหลัก** — หัวข้อที่จัดกลุ่มโดยอัตโนมัติจาก feedback ข้อความเสรี
- **Export** — ดาวน์โหลดข้อมูล feedback เป็น CSV สำหรับการวิเคราะห์ในเครื่องมือภายนอก

## Content Quality (/admin/content-quality)

Content Quality ตรวจสอบคะแนนคุณภาพของผลลัพธ์ที่ AI สร้างทั่วทั้งแพลตฟอร์ม

- **คะแนนคุณภาพ** — คะแนนรวมตามโมเดล, skill และพื้นที่ฟีเจอร์
- **ผลลัพธ์ที่ถูกตั้งสถานะ** — รายการที่ได้คะแนนต่ำกว่าเกณฑ์คุณภาพสำหรับตรวจสอบด้วยตนเอง
- **Review queue** — ตรวจสอบผลลัพธ์ที่ถูกตั้งสถานะและทำเครื่องหมายว่ายอมรับได้หรือมีปัญหา
- **แนวโน้ม** — ติดตามการเปลี่ยนแปลงคะแนนคุณภาพตามเวลาเพื่อตรวจจับการเสื่อมสภาพของโมเดล

## Sandbox (/admin/sandbox)

Sandbox คือสภาพแวดล้อมทดสอบแบบ isolated ที่ admin สามารถทดสอบ skills และ agencies โดยไม่กระทบต่อผู้ใช้ production

- **การทดสอบ skill** — รัน skill ใดก็ได้ด้วย input ทดสอบเพื่อตรวจสอบพฤติกรรมก่อนเผยแพร่
- **การทดสอบ agency** — สร้าง sandbox agency run พร้อม logging ครบถ้วนสำหรับ debug
- **การทดสอบโมเดล** — ส่ง prompt ดิบไปยัง provider ที่กำหนดค่าไว้เพื่อเปรียบเทียบผลลัพธ์
- การเปลี่ยนแปลงใน Sandbox ไม่ใช้เครดิตผู้ใช้และไม่สามารถมองเห็นได้สำหรับผู้ใช้ทั่วไป
