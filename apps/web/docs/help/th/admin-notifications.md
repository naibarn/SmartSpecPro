# ศูนย์การแจ้งเตือน

## ภาพรวม

ศูนย์การแจ้งเตือนเป็นแดชบอร์ดแบบรวมศูนย์สำหรับผู้ดูแลระบบ ที่รวบรวมการแจ้งเตือนจากทุกแหล่ง — การแจ้งเตือนผู้ใช้ เหตุการณ์จาก Orchestrator และแจ้งเตือนจาก Guardian — เข้าในหน้าเดียว ใช้เพื่อติดตามสุขภาพระบบ ตรวจสอบแจ้งเตือนที่ยังไม่ได้รับทราบ และตรวจทานรูปแบบการส่งการแจ้งเตือน

**Feature flag:** ต้องเปิดใช้งาน `notificationUnifiedCenter` เพื่อให้หน้านี้ปรากฏ

## การ์ดสรุป

การ์ดสรุป 4 ใบที่ด้านบนให้ภาพรวมอย่างรวดเร็ว:

- **ทั้งหมด** — จำนวนการแจ้งเตือนทั้งหมดจากทุกแหล่งในช่วงเวลาที่เลือก
- **ยังไม่อ่าน** — การแจ้งเตือนที่ยังไม่ได้เปิดหรือรับทราบ
- **วิกฤต** — การแจ้งเตือนระดับ high และ critical ที่อาจต้องดำเนินการทันที
- **วันนี้** — การแจ้งเตือนที่สร้างใน 24 ชั่วโมงล่าสุด

## รายการการแจ้งเตือนแบบรวม

ตารางหลักแสดงการแจ้งเตือนจากทุกแหล่ง เรียงจากใหม่ไปเก่า แต่ละแถวแสดง:

- ป้ายแหล่งที่มา (User, Orchestrator, Guardian)
- ตัวบ่งชี้ระดับความรุนแรง (low, normal, high, critical)
- หัวข้อ ตัวอย่างเนื้อหา และเวลา
- ลิงก์ไปยังทรัพยากรที่เกี่ยวข้อง (ถ้ามี)

### การกรอง

- **แหล่งที่มา** — กรองตาม User Notifications, Orchestrator หรือ Guardian
- **ระดับความรุนแรง** — กรองตาม low, normal, high หรือ critical
- **ช่วงวันที่** — ตัวเลือกวันเริ่มต้นและสิ้นสุดเพื่อจำกัดช่วงเวลา
- **แบ่งหน้า** — เลื่อนดูผลลัพธ์ (20 รายการต่อหน้า)

## การรวมกลุ่มการแจ้งเตือน (Deduplication)

เมื่อเปิดใช้การรวมกลุ่ม (`notificationDedupEnabled`) การแจ้งเตือนซ้ำที่มี `groupKey` เดียวกันจะถูกยุบรวมเป็นรายการเดียว:

- **ป้ายจำนวนครั้ง** (×N) — แสดงจำนวนครั้งที่เหตุการณ์เกิดขึ้น
- **ขยายกลุ่ม** — คลิกเพื่อดูเหตุการณ์ย่อยทั้งหมดพร้อมเวลาที่เกิด
- **ครั้งแรก / ครั้งล่าสุด** — ช่วงเวลาของเหตุการณ์ที่ถูกรวมกลุ่ม

วิธีนี้ช่วยป้องกันความล้าจากแจ้งเตือนซ้ำ เช่น Health Check ล้มเหลวซ้ำๆ หรือ Job ผิดพลาดซ้ำ

## แผงรายละเอียด

คลิกการแจ้งเตือนใดก็ได้เพื่อเปิดแผงรายละเอียดที่แสดง:

- เนื้อหาการแจ้งเตือนฉบับเต็ม
- ข้อมูลเมตา (แหล่งที่มา, Event ID, รายละเอียดข้อผิดพลาด, ตัวชี้วัด)
- ปุ่ม Action (นำทางไปยังทรัพยากรที่เกี่ยวข้อง)
- ปุ่มยกเลิก / ทำเครื่องหมายว่าอ่านแล้ว

## การตรวจสอบสุขภาพ

สถานะสุขภาพของระบบแจ้งเตือนสามารถเข้าถึงได้ผ่าน Monitoring API (`monitoring.notificationHealth`) โดยตรวจสอบ 3 ส่วน:

1. **Redis Pub/Sub** — ทดสอบเวลาตอบกลับ (แจ้งเตือนหาก timeout เกิน 5 วินาที)
2. **Admin Broadcast** — อัตราข้อผิดพลาดในช่วง 5 นาที (แจ้งเตือนหาก > 10%)
3. **SSE Connections** — จำนวนการเชื่อมต่อแบบเรียลไทม์ที่ใช้งานอยู่ (แจ้งเตือนหาก > 500)

## เคล็ดลับ

- ใช้ตัวกรองระดับความรุนแรงเพื่อดูรายการ critical และ high ก่อน
- ตรวจสอบศูนย์การแจ้งเตือนหลังจาก deploy เพื่อจับคำเตือนสุขภาพระบบแต่เนิ่นๆ
- การแจ้งเตือนที่เก่ากว่าช่วงเวลาที่กำหนด (ตั้งค่าใน retention job) จะถูกลบอัตโนมัติ
- เปิดใช้การรวมกลุ่มเพื่อลดสัญญาณรบกวนจากแจ้งเตือนซ้ำ — กำหนดรูปแบบ `groupKey` ในจุดเรียกใช้การแจ้งเตือน
