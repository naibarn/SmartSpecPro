# Drama Script Evaluate & Improve Skill

ชื่อภาษาไทย: **Skill ประเมินและปรับปรุงบทละครแบบรวมในตัวเดียว**

## 1. Purpose

Skill นี้รวมความสามารถของ 2 skill เดิมไว้ในตัวเดียว:

1. ประเมินคุณภาพบทละคร / ซีรีส์สั้น / ละครแนวตั้ง / ไมโครดราม่า จากมุมมอง **ความน่าติดตามของคนดู**
2. วิเคราะห์ว่าอะไรดีแล้ว อะไรควรปรับปรุง และภาษาพูดเข้าใจง่ายพอไหม
3. ปรับปรุงบทละครทันทีด้วย loop engineering ภายใน
4. วนประเมินและแก้ไขสูงสุด 5 รอบ เพื่อหาเวอร์ชันที่ดีที่สุด
5. ส่งออกเฉพาะผลลัพธ์ที่ดีที่สุด พร้อมคะแนนหลังปรับปรุงสุดท้าย

เป้าหมายหลักคือทำให้ผู้ใช้ส่ง input น้อยลง ไม่ต้องแยกส่งไปยัง skill ประเมินก่อนแล้วค่อยส่งต่อไปยัง skill ปรับบทอีกครั้ง

---

## 2. Input Fields

Skill ใช้ input หลัก 2 ช่องเท่านั้น:

### `original_script`
บทละครก่อนแก้ไข อาจเป็น:

- เรื่องย่อรวม
- โครงซีรีส์
- โครงตอน
- รายช็อต
- บทพูด
- จุดค้างท้ายตอน
- รายละเอียดตัวละคร
- รายละเอียดสินค้า tie-in
- ข้อจำกัดเฉพาะของงาน

ให้ผู้ใช้วางทุกอย่างเป็นก้อนเดียวได้

### `user_revision_request`
สิ่งที่ผู้ใช้อยากให้ปรับเพิ่มเป็นพิเศษ เช่น:

- ต้องการฉากเรือนไม้ทรงไทย บรรยากาศสมัย ร.5
- ต้องการบรรยากาศริมทะเล มองเห็นเกาะไกล ๆ
- ต้องการเพิ่มความโรแมนติกระหว่างพระเอกนางเอก
- ต้องการให้คงฉากเดิมต่อเนื่องทุกตอน
- ต้องการให้เห็นหน้าตัวละครและเสื้อผ้าชัดเพื่อใช้สร้างภาพและวิดีโอ
- ต้องการให้บทพูดง่ายขึ้น ไม่วิชาการ
- ต้องการเพิ่ม mini-turn / cliffhanger / การพลิกเกม

ช่องนี้เป็น **high-priority creative constraint** ต้องใส่ใจเป็นพิเศษและทำให้เห็นใน output หากปลอดภัยและสอดคล้องกับเรื่อง

## 3. Output Field

Skill ส่ง output เป็น Markdown ก้อนเดียว:

### `final_result`

ต้องมี 2 ส่วนเท่านั้น:

1. **คะแนนหลังปรับปรุงสุดท้ายและสรุปสั้นมาก**
2. **บทละครเวอร์ชันปรับปรุงที่ดีที่สุด**

ห้ามแสดง:

- รายงานประเมินยาว
- ตัวเลือก 3 แบบ
- รายละเอียด loop ทั้งหมด
- เหตุผลเปรียบเทียบแต่ละรอบ
- chain-of-thought หรือการคิดภายใน

อนุญาตให้แสดงเฉพาะสรุปสั้น ๆ ก่อนบทละคร เช่น:

```markdown
# ผลลัพธ์สุดท้าย

**คะแนนหลังปรับปรุง: 8.6/10**
สรุป: ปรับให้โครงเรื่องมีแรงค้างมากขึ้น ภาษาพูดง่ายขึ้น และฉาก/มุมกล้องเหมาะกับการสร้างภาพและวิดีโอมากขึ้น

---

<บทละครที่แก้ไขแล้ว>
```

ถ้าบทละครยาวมาก ให้ output เท่าที่บริบทอนุญาต โดยรักษาลำดับจากต้นเรื่องไปท้ายเรื่อง และใส่ `--- ต่อจากนี้เป็นเนื้อหาตอนถัดไป ---` ระหว่างช่วงใหญ่ได้ แต่ไม่ต้องอธิบายกระบวนการทำงาน

## 4. Core Philosophy

ประเมินและปรับปรุงจาก **ความน่าติดตามของคนดูในแนวของเรื่องนั้น** ไม่ใช่ความครบสูตรทางทฤษฎีละคร

หลักสำคัญ:

- อย่าหักคะแนนหรือแก้ให้มีตัวร้าย ถ้าแนวเรื่องไม่ได้ต้องการตัวร้าย
- อย่าเพิ่มดราม่าหนัก ถ้าแนวเรื่องขายความอบอุ่น ความรู้ ความหวาน หรือฟีลกู๊ด
- อย่าเพิ่มมุกตลกถ้าจะทำลายอารมณ์หลัก
- อย่าบังคับให้ทุกเรื่องต้องมีครบทุกอารมณ์
- ต้องรักษาเสน่ห์เดิมของเรื่องก่อน แล้วค่อยเพิ่มแรงติดตาม
- บทพูดต้องฟังง่าย เป็นธรรมชาติ และเหมาะกับวัย/อาชีพ/ภูมิหลังของตัวละคร
- ถ้าเป็นละครให้ความรู้ ต้องแปลงคำยากให้เป็นภาษาคนดูทั่วไปเข้าใจได้
- ถ้าเป็นละครเพื่อภาพ/วิดีโอ ต้องระบุฉาก แสง บรรยากาศ blocking ใบหน้า และเสื้อผ้าให้ชัด

## 5. Internal Workflow Overview

Skill ต้องทำงานภายในตามลำดับนี้ แต่ห้ามแสดงกระบวนการเหล่านี้ใน output:

1. อ่าน `original_script`
2. อ่าน `user_revision_request`
3. ตรวจจับแนวละครหลัก/แนวรอง
4. ประเมินคะแนนตั้งต้นแบบสั้นภายใน
5. สรุปจุดแข็ง จุดอ่อน และเป้าหมายการแก้ภายใน
6. สร้างแนวทางแก้ไข 3 แบบภายใน
7. เลือกหรือผสมแนวทางที่ดีที่สุด
8. ปรับบทละครเป็นเวอร์ชันใหม่
9. ประเมินเวอร์ชันใหม่
10. วน loop สูงสุด 5 รอบ
11. เก็บเวอร์ชันที่ได้คะแนนดีที่สุดเสมอ
12. ถ้ารอบใดคะแนนต่ำลง ให้ทิ้งรอบนั้นและใช้เวอร์ชันที่ดีกว่า
13. ส่งออกเวอร์ชันที่ดีที่สุด พร้อมคะแนนหลังปรับปรุงสุดท้าย

## 6. Internal Evaluation Rules

ให้ประเมินคะแนนเต็ม 10 โดยใช้ชื่อภายในว่า:

```text
คะแนนความน่าติดตามของคนดู
```

ให้พิจารณา:

- Hook เปิดเรื่อง / เปิดตอน
- ตัวละครหรือสถานการณ์น่าตามไหม
- แนวเรื่องส่งมอบสิ่งที่คนดูคาดหวังไหม
- มี mini-turn หรือจุดพลิกเล็ก ๆ ไหม
- มีโมเมนต์จำง่ายไหม
- มีความคืบหน้าระหว่างช็อต/ตอนหรือไม่
- ท้ายตอนมีแรงดึงให้ดูต่อไหม
- บทพูดเข้าใจง่ายและเป็นภาษาคนพูดจริงไหม
- ฉาก สถานที่ บรรยากาศ และ visual continuity ชัดพอไหม
- เห็นหน้าผู้พูดและเสื้อผ้าชัดพอสำหรับ image/video generation ไหม
- user_revision_request ถูกนำไปใช้จริงไหม

### Score Target

เป้าหมายหลังปรับปรุงคือ **8/10 ขึ้นไป** หากทำได้โดยไม่ทำลายเรื่องเดิม

ถ้าเรื่องตั้งต้นมีข้อมูลน้อยหรือข้อจำกัดมาก อาจไม่ถึง 8/10 ได้ แต่ต้องพยายามเลือกเวอร์ชันที่ดีที่สุดและไม่อ้างข้อจำกัดยาว ๆ ใน output

## 7. Internal Loop Engineering

ให้ใช้ loop ภายในสูงสุด 5 รอบ:

```text
best_version = original_script
best_score = evaluated_original_score

for round in 1..5:
    create revised_candidate from best_version using:
        - evaluation findings
        - user_revision_request
        - genre promise
        - dialogue simplification
        - retention improvement
        - scene continuity
        - face/costume-safe visual blocking
    candidate_score = evaluate revised_candidate
    if candidate_score > best_score:
        best_version = revised_candidate
        best_score = candidate_score
    if best_score >= 8.0 and candidate is coherent, polished, and output-ready:
        may stop early

return best_version and best_score
```

ถ้ารอบใดทำให้:

- โครงเรื่องหลุด
- บทพูดแข็งขึ้น
- ฉากไม่ต่อเนื่อง
- ขัด user_revision_request
- คะแนนลดลง

ให้ทิ้งรอบนั้นและกลับไปใช้เวอร์ชันที่ดีที่สุดก่อนหน้า

## 8. Internal Three-Strategy Revision

ในแต่ละรอบ ให้คิดแนวทางแก้ภายในอย่างน้อย 3 แบบ แต่ห้ามแสดง:

### Option A: Conservative Polish
ปรับภาษา ฉาก และจุดค้างเล็กน้อย โดยรักษาเรื่องเดิมมากที่สุด

### Option B: Retention-First Revision
เพิ่ม hook, mini-turn, cliffhanger, แรงปะทะ, การพลิกเกม หรือจุดค้างท้ายตอนให้แรงขึ้น

### Option C: Character-Emotion / Visual Continuity Revision
เสริมอารมณ์ตัวละคร ความสัมพันธ์ ภาพจำ ฉาก บรรยากาศ และความต่อเนื่องของสถานที่

จากนั้นเลือกหรือผสมส่วนที่ดีที่สุดเป็น candidate เดียว

## 9. Genre-Aware Improvement Rules

ให้ปรับตามแนวละครที่ตรวจพบ ไม่ใช่ใช้สูตรเดียวกันทุกเรื่อง

### Edutainment / ละครให้ความรู้
- ต้องทำให้ความรู้ผูกกับเหตุการณ์ ไม่ใช่บรรยายลอย ๆ
- แปลงศัพท์ยากเป็นคำง่าย
- ใช้คำถามของตัวละครเป็น hook
- เพิ่มภาพทดลอง / หลักฐาน / before-after
- รักษาความถูกต้องของข้อมูล

### Romance / Romantic Comedy
- เพิ่มเคมี โมเมนต์เขิน การดูแลกัน การหยอกล้อ
- ไม่ต้องเพิ่มตัวร้ายถ้าไม่จำเป็น
- จังหวะใครพูดต้องเห็นหน้าคนนั้นชัด
- เลี่ยงฉากโจ่งแจ้ง โดยเฉพาะถ้ากลุ่มเป้าหมายไม่ใช่ผู้ใหญ่

### Revenge / พลิกเกม / เอาคืน
- เพิ่มการสลับได้เปรียบเสียเปรียบ
- ให้ตัวเอกมีจังหวะลงมือเอง
- เพิ่ม payoff สะใจเป็นระยะ

### Drama / Family / Healing
- รักษาอารมณ์จริง ความสัมพันธ์ และบาดแผลของตัวละคร
- ไม่เพิ่ม conflict เกินโทน
- เพิ่มการเปิดใจ การเลือกทำบางอย่าง และ emotional payoff

### Tie-in Product
- ให้สินค้าแก้ปัญหาในเรื่องอย่างเป็นธรรมชาติ
- เพิ่ม product moment ที่เห็นชัด แต่ไม่ขายแข็ง
- รักษาความน่าเชื่อถือของผลลัพธ์

### Comedy
- เพิ่มมุกจากคาแรกเตอร์ ไม่ใช่มุกแปะ
- จังหวะมุกต้องไม่ทำลายประเด็นหลัก

## 10. Dialogue Simplicity & Spoken Language Rules

ต้องปรับบทพูดให้:

- สั้นขึ้นเมื่อเป็นไปได้
- ฟังเหมือนคนพูดจริง
- เหมาะกับวัยและภูมิหลังของตัวละคร
- ไม่เหมือนอ่านข้อความอธิบาย
- ไม่ใช้ศัพท์วิชาการเกินจำเป็น
- ถ้าต้องใช้ศัพท์เฉพาะ ต้องมีคำอธิบายง่าย ๆ ในบทพูดหรือสถานการณ์
- ประโยคสำคัญควรจำง่ายและพูดซ้ำได้ เช่น signature phrase

ตัวอย่างแนวทาง:

- `ระคาย` → `แดง แสบ อับ`
- `สารอินดิเคเตอร์` → `น้ำเปลี่ยนสี`
- `ความเป็นกรด` → `เปรี้ยวแบบกรด`
- `การเปลี่ยนแปลงที่พาอาหารเสีย` → `ของที่ทำให้อาหารเสียทำงานช้าลง`

ถ้าผู้ใช้ต้องการละครวิชาการ ให้ใช้ศัพท์เฉพาะได้ แต่ต้องไม่ทำให้ผู้ชมหลุดจากเรื่อง

## 11. Scene Location, Atmosphere & Continuity Rules

ต้องเพิ่มและรักษารายละเอียดฉากให้ชัดพอสำหรับการนำไปสร้างภาพและวิดีโอ

ในเรื่องย่อ ตอน และช็อต ควรระบุเมื่อเหมาะสม:

- สถานที่หลัก
- จุดย่อยในฉาก เช่น เตียง โต๊ะข้างเตียง หน้าต่าง โซฟา เคาน์เตอร์ ตู้แช่
- เวลา เช่น เช้า สาย เย็น กลางคืน
- แสง เช่น แสงเช้าลอดหน้าต่าง แสงนีออนอุ่น แสงริมทะเลยามเย็น
- บรรยากาศ เช่น อบอุ่น หรูหรา เงียบ สบายใจ ตึงเครียดเล็กน้อย
- props สำคัญที่ต้องคงต่อเนื่อง
- ตำแหน่งตัวละครในฉาก
- ใครหันมองใคร ใครถืออะไร ใครนั่ง/ยืนตรงไหน

### Continuity Rule

ถ้าตอนถัดไปยังไม่ย้ายสถานที่:

- ให้รักษาฉากเดิม บรรยากาศเดิม และ set anchors เดิม
- อย่าเปลี่ยนห้อง ร้าน บ้าน หรือสภาพแวดล้อมโดยไม่มีเหตุผล
- ใช้ props เดิมเป็นตัวเชื่อม เช่น สมุดจด โต๊ะไม้ โคมไฟ หน้าต่าง ตู้แช่ เตียงเด็ก ฯลฯ

ถ้าย้ายสถานที่:

- ระบุให้ชัดว่าย้ายไปไหน
- ระบุเหตุผลการย้ายฉาก
- สร้างบรรยากาศใหม่ให้สอดคล้องกับเรื่อง

## 12. Face, Costume & Image/Video Generation Safety Rules

บทที่ปรับแล้วต้องคำนึงถึงการนำไปสร้างภาพและวิดีโอ โดยเฉพาะ start frame และ image-to-video

กฎสำคัญ:

- ทุกช็อตที่มีบทพูด ต้องพยายามให้เห็นหน้าผู้พูดชัด
- ต้องเห็นเสื้อผ้า ทรงผม และ identity detail ชัดพอ
- หลีกเลี่ยงมุมที่ทำให้ใบหน้าเพี้ยน เช่น ด้านหลัง เงาดำ ไกลเกินไป หน้าถูกบัง หันข้างมากเกินไป หรือ over-the-shoulder ที่ไม่เห็นหน้าผู้พูด
- ถ้าตัวละครหันหน้าคุยกัน ให้ใช้การตัดสลับ shot-reverse-shot แทน
- จังหวะใครพูด ควรเห็นหน้าคนนั้นชัดเสมอ
- wide shot ใช้ได้เพื่อ establish ฉาก แต่ไม่ควรเป็นช็อตหลักของบทพูดสำคัญ
- สำหรับช็อตสำคัญ ใช้ medium close-up หรือ close-up แบบหน้าตรง/สามส่วนที่เห็นใบหน้าและเสื้อผ้าชัด
- หลีกเลี่ยงคำบรรยายคลุมเครือ เช่น “คุยกันอยู่ในห้อง” โดยไม่บอกตำแหน่ง แสง หรือ framing

ตัวอย่างที่ควรใช้:

```text
ช็อต 3: Medium close-up เห็นหน้าฝ้ายชัด เธอยืนข้างโต๊ะไม้ในครัวหลังร้าน เสื้อยูนิฟอร์มสีครีมและผ้ากันเปื้อนเห็นชัด แสงนีออนอุ่นจากเพดานตกบนใบหน้า เธอมองใบข้าวที่อยู่นอกเฟรมก่อนตอบ
```

ตัวอย่างที่ควรหลีกเลี่ยง:

```text
ช็อต 3: ฝ้ายกับใบข้าวนั่งคุยกัน
```

## 13. Token-Efficient Revision Rules

Skill นี้ต้องลด token โดยไม่ลดคุณภาพ ดังนั้นการปรับบทต้องใช้หลัก **กระชับแต่พอสร้างภาพ/วิดีโอได้**

### Compact Visual Anchor Rule

ให้บรรยายฉากละเอียดเฉพาะเมื่อ:

- เปิดเรื่อง / เปิดตอน
- เปลี่ยนสถานที่
- เปลี่ยนเวลา แสง หรือบรรยากาศสำคัญ
- มี props ใหม่ที่ต้องใช้ต่อเนื่อง
- มีการเปลี่ยนเสื้อผ้า ทรงผม หรือ identity detail สำคัญ

หลังจาก establish แล้ว ช็อตถัดไปไม่ต้องทวนรายละเอียดทั้งหมดซ้ำ ให้ใช้คำอ้างอิงสั้น ๆ เช่น:

```text
ช็อต 4: Medium close-up ใบข้าวที่โต๊ะทดลองเดิม เห็นหน้าและเอี๊ยมยีนส์ชัด เธอก้มดูผ้าอ้อมแล้วเงยหน้าถามแม่
```

แทนการทวนฉากเต็มทุกช็อต

### Avoid Repetitive Shot Description

ห้ามทำให้ทุกช็อตยาวเกินจำเป็นด้วยการทวน:

- สีเสื้อผ้าเดิมซ้ำทุกครั้ง
- แสงเดิมซ้ำทุกครั้ง
- ตำแหน่ง props เดิมซ้ำทุกครั้ง
- คำว่าเห็นหน้าชัดแบบยาว ๆ ซ้ำทุกช็อต

ให้ใช้รูปแบบสั้น เช่น:

```text
ช็อต 5: Close-up ฝ้ายที่เคาน์เตอร์เดิม เห็นหน้าและยูนิฟอร์มชัดขณะตอบลูก
```

### Visual Detail Budget

โดยทั่วไป:

- เรื่องย่อรวม: ระบุสถานที่หลักและบรรยากาศหลัก 2-5 ประโยค
- เรื่องย่อตอน: ระบุสถานที่ เวลา แสง props หลัก และ blocking สำคัญ 2-4 ประโยค
- ช็อตทั่วไป: 1 ประโยคภาพ + บทพูด
- ช็อตสำคัญมาก: เพิ่มรายละเอียดได้ แต่ไม่ควรยืดยาวจนกลบบทพูด

### Preserve Readability

บทที่ปรับแล้วต้องอ่านง่ายสำหรับมนุษย์ด้วย ไม่ใช่กลายเป็น prompt ภาพล้วน ๆ

ให้รักษาสมดุล:

```text
ละครอ่านรู้เรื่อง + ฉากพอสร้างภาพได้ + ไม่ยาวเกินจำเป็น
```

### No Unnecessary Expansion

ถ้าต้นฉบับสั้น ห้ามขยายจนยาวผิดสัดส่วนโดยไม่จำเป็น
ถ้าผู้ใช้ไม่ได้ขอเพิ่มจำนวนตอนหรือช็อต ห้ามเพิ่มตอนหรือช็อตใหม่จำนวนมาก
ให้เน้นปรับคุณภาพภายในโครงเดิมมากกว่าขยายปริมาณ

## 14. Preserve Original Format

Output ต้องรักษารูปแบบต้นฉบับให้มากที่สุด

ถ้าต้นฉบับมี:

```text
ซีรีส์:
แนว:
โทน:
เรื่องย่อรวม:
ช่วงตอนที่เลือก:
ตอนที่ 1:
เรื่องย่อ:
จุดดำเนินเรื่อง:
บทพูดรายช็อต:
ช็อต 1:
จุดค้าง:
```

output ต้องใช้โครงสร้างแบบเดียวกัน

ห้ามแปลงรายช็อตเป็น prose ล้วน ถ้าต้นฉบับมีรายช็อต
ห้ามลบบทพูด ถ้าต้นฉบับมีบทพูด
ห้ามเปลี่ยนชื่อเรื่อง ชื่อตัวละคร หรือโครงหลักโดยไม่จำเป็น

## 15. User Revision Request Priority

`user_revision_request` ต้องถูกนำไปใช้จริงเมื่อเป็นไปได้

ตัวอย่าง:

- ถ้าผู้ใช้ขอ `เรือนไม้ทรงไทย บรรยากาศสมัย ร.5` ให้ปรับสถานที่ props เครื่องแต่งกาย มารยาท แสง และภาษาบางส่วนให้สอดคล้อง โดยยังรักษาหน้าที่ของฉาก
- ถ้าผู้ใช้ขอ `ริมทะเล มองเห็นเกาะไกล ๆ` ให้เพิ่มทะเล ลม แสง เกาะไกล ๆ คนชายหาด และ continuity anchors
- ถ้าผู้ใช้ขอ `เพิ่มเลิฟซีนพระเอกนางเอก` ให้ปรับเป็นฉากโรแมนติกที่เหมาะสมกับเรตเรื่อง เช่น สายตาใกล้ชิด การช่วยดูแล การเกือบสัมผัส การสารภาพความรู้สึก โดยหลีกเลี่ยงความโจ่งแจ้งหากไม่เหมาะสม
- ถ้าผู้ใช้ขอ `เห็นหน้าชัด` ให้บังคับใช้ face/costume-safe shot blocking ทุกช็อตสำคัญ

ถ้า request ขัดกับความปลอดภัย กลุ่มอายุ หรือโครงเรื่อง ให้ใช้เวอร์ชันที่ปลอดภัยและยังรักษาเจตนาหลักของผู้ใช้

## 16. Final Output Format

ต้องตอบตามโครงนี้เท่านั้น:

```markdown
# ผลลัพธ์สุดท้าย

**คะแนนหลังปรับปรุง: X/10**
สรุป: <หนึ่งถึงสามประโยคสั้น ๆ ว่าปรับดีขึ้นด้านใด>

---

<บทละครเวอร์ชันปรับปรุงที่ดีที่สุด โดยรักษารูปแบบต้นฉบับ>
```

ห้ามใส่:

- รายงานประเมินเต็ม
- รายละเอียด loop
- รายละเอียดตัวเลือก A/B/C
- ข้อความบอกว่า “ฉันได้คิด...” หรือ “กระบวนการภายใน...”

## 17. Long Output Handling

ถ้าบทละครยาวมากและอาจเกิน output limit ให้ใช้แนวทางนี้เพื่อลด token และยังคงคุณภาพ:

1. ปรับทั้งเรื่องภายในก่อน แล้วเลือกเวอร์ชันดีที่สุดตาม loop engineering
2. ส่ง output ตามลำดับเดิมจากต้นเรื่องไปท้ายเรื่อง
3. ห้ามตัดกลางช็อตหรือกลางบทพูดถ้าเลี่ยงได้
4. ให้จบที่ boundary ของตอนหรือช็อตเท่านั้น
5. ใช้ visual anchor แบบกระชับ ไม่ทวนฉากซ้ำทุกช็อต
6. ถ้าต้องแบ่ง ให้ใส่ท้าย output ว่า:

```text
[ต่อในส่วนถัดไป]
```

7. ในส่วนถัดไป ให้ดำเนินต่อจาก boundary เดิมโดยไม่ต้องเริ่มประเมินใหม่ และไม่ต้องทวนคำอธิบายยาว

ห้ามแสดงรายงานประเมินยาว กระบวนการ loop หรือเหตุผลภายใน แม้ต้องแบ่ง output

## 18. Final Quality Checklist

ก่อนส่ง output ต้องตรวจภายในว่า:

- คะแนนหลังปรับปรุงดีที่สุดเท่าที่ทำได้หรือไม่
- หากมีรอบไหนคะแนนลดลง ได้ทิ้งรอบนั้นแล้วหรือไม่
- เป้าหมาย 8/10 ขึ้นไปทำได้หรือยัง ถ้าทำได้โดยไม่ทำลายเรื่อง
- โครงสร้างเหมือน input เดิมหรือไม่
- คำสั่งของผู้ใช้ถูกนำไปใช้จริงหรือไม่
- จุดอ่อนหลักได้รับการแก้จริงหรือไม่
- จุดแข็งเดิมยังอยู่หรือไม่
- ภาษาพูดง่ายขึ้นหรือไม่
- ฉาก สถานที่ แสง และบรรยากาศชัดขึ้นหรือไม่
- scene continuity ต่อเนื่องหรือไม่
- ทุกช็อตพูดสำคัญเห็นหน้าผู้พูดและเสื้อผ้าชัดหรือไม่
- ใช้ visual anchor กระชับ ไม่ทวนฉาก/เสื้อผ้า/แสงซ้ำเกินจำเป็นหรือไม่
- output มีเฉพาะคะแนนสั้น ๆ และบทละครที่ดีที่สุดหรือไม่
