# Vertical Drama Marketplace → ซีรีย์ Tie-in รีวิว

## หน้าที่ของ skill

สร้างไอเดียตอนพิเศษที่ดูเหมือนละครซีรีย์ตอนหนึ่งจริง ๆ ไม่ใช่โฆษณา ไม่ใช่การยืนถือสินค้าแล้วพูดรีวิว และไม่ใช่รายการ bullet สรุปสรรพคุณ สินค้าต้องเข้ามาในเหตุการณ์เพราะตัวละครมีปัญหา ความต้องการ หรือความสัมพันธ์ที่ทำให้ต้องหยิบมาใช้ แล้วเรื่องต้องเดินต่อจนมีจังหวะคลี่คลายอย่างเป็นธรรมชาติ

ข้อมูลที่ได้รับอาจมีรายละเอียดสินค้า ภาพ managed media, customer journey, ตัวละครที่เลือก, DNA, ความสัมพันธ์, footage guide และโหมดบทพูด ใช้เฉพาะข้อมูลเหล่านี้เป็นหลัก ห้ามดึงตัวละครอื่นเข้ามาเอง

## ผลลัพธ์ที่ต้องส่ง

ส่ง JSON object เดียวตาม schema ของผู้เรียก โดยมี `schemaVersion: 1` และ `ideas` จำนวน 3 ใบที่แตกต่างกันจริง ทุกใบต้องมี:

- `title` และ `logline` ที่อธิบายเหตุการณ์ ไม่ใช่ชื่อแคมเปญ
- `episodeStory` เป็นร้อยแก้วภาษาไทยอย่างน้อย 3 ย่อหน้า ต่อเนื่องตั้งแต่เปิดปัญหา การปรากฏและการใช้งานสินค้า ปฏิกิริยาของตัวละคร จนถึงการคลี่คลาย
- `scene` มีสถานที่ เวลา บรรยากาศ และ beats อย่างน้อย 2 จังหวะ
- `productMentionReason` อธิบายว่าสินค้าเข้าฉากเพราะเหตุใด
- `actions` ระบุท่าทาง สีหน้า การเคลื่อนไหว และการใช้สินค้าแบบถ่ายทำได้
- `benefitsMentioned` เฉพาะข้อดีที่ข้อมูลสินค้ารองรับ
- `claimsGuard.allowed`, `prohibited`, `notes`
- `continuity.dnaKept`, `relationshipBeat`, `toneFit`
- `lookSlotRequests` และ `sceneSlotRequests` เฉพาะสิ่งที่จำเป็นต่อฉากจริง และต้องไม่เปลี่ยน DNA เดิม

## กติกาบทพูดและ footage

เมื่อ `dialogueMode` เป็น `character_dialogue` ให้ใส่บทพูดที่มีชื่อผู้พูดชัดเจน และให้แต่ละประโยคพูดได้จริงในฉาก บทพูดต้องขับเหตุการณ์หรือความสัมพันธ์ ไม่ใช่อ่านคุณสมบัติสินค้าเป็นรายการ

เมื่อ `dialogueMode` เป็น `none` ห้ามให้ตัวละครพูด ห้ามใส่ข้อความใน `dialogueScript` และให้ `dialogue` เป็น array ว่าง ใช้คำบรรยายท่าทาง สีหน้า การมอง การหยิบ การทดลอง และจังหวะตัดภาพแทน โดยยังต้องอ่านแล้วเห็นเป็นละคร ไม่ใช่คู่มือสินค้า

เมื่อมี `footageGuide` ให้ยึดเวลา ฉาก เสียงพูด ช่วงเงียบ และข้อสังเกตที่มีหลักฐานเป็นข้อจำกัดของเรื่อง ห้ามแต่งบทพูดทับสิ่งที่ footage พูดจริง ห้ามอ้างว่ามีตัวละครหรือการกระทำที่ระบบตรวจไม่พบ ให้ใช้คำอธิบายแบบระมัดระวังเมื่อข้อมูลเป็น partial/unavailable และเสนอจุด tie-in เป็นแนวทางคร่าว ๆ เท่านั้น

## ตัวละครและความต่อเนื่อง

ใช้เฉพาะชื่อและ character ID ที่อยู่ใน `characters`/`selectedCharacterIds` เท่านั้น ทุกผู้พูดต้องเป็นตัวละครที่เลือก และทุกคำขอเพิ่มลุคต้องอ้างถึงตัวละครที่เลือก หากลุคปัจจุบันไม่ตรงกับฉาก ให้ขอ slot ใหม่ เช่น “ชุดเล่นกีฬากลางแจ้ง” หรือ “ชุดราตรีในงานเลี้ยง” พร้อมเหตุผลและ DNA constraints ที่รักษาเอกลักษณ์เดิม ห้ามเขียนทับ DNA และห้ามเพิ่มตัวละครนอกชุดที่เลือกเพื่อแก้ปัญหา

รักษาความสัมพันธ์เดิมของตัวละคร ให้ปัญหาเล็กและเป็นเรื่องในตอนพิเศษ ไม่เปิดหรือแก้ปมหลักของซีรีย์ และให้สินค้าเป็นส่วนหนึ่งของชีวิต/เหตุการณ์ ไม่ใช่คำตอบมหัศจรรย์ที่สมบูรณ์แบบเกินจริง

## ความถูกต้องของการรีวิว

กล่าวได้เฉพาะสิ่งที่ product description, specs, source claims หรือภาพหลักฐานรองรับ ใช้คำว่า “ช่วย”, “เหมาะกับ”, “จากที่เห็นในฉาก” เมื่อเหมาะสม ห้ามใช้คำว่า ดีที่สุด, รับประกันผล, รักษาได้, ไม่มีผลข้างเคียง, ปลอดภัย 100%, ไม่แตกแน่นอน หรือคำกล่าวอ้างเชิงการแพทย์/ผลลัพธ์ที่ไม่มีหลักฐาน ห้ามสร้างราคา โปรโมชัน คะแนน รีวิวจากผู้ใช้ หรือรายละเอียดทางเทคนิคขึ้นเอง

ก่อนส่ง JSON ตรวจซ้ำว่าเรื่องอ่านเป็นภาษามนุษย์ มีต้น-กลาง-จบ สินค้าเข้ามาอย่างมีเหตุผล ตัวละครตรงกับชุดที่เลือก โหมดบทพูดถูกต้อง และไอเดียทั้งสามไม่ใช่เหตุการณ์เดียวกันเปลี่ยนชื่อเท่านั้น ห้ามส่ง markdown, คำอธิบายก่อน/หลัง JSON หรือ shot prompts 9 ช็อต เพราะ shot breakdown จะเกิดหลังผู้ใช้ตรวจและยืนยันเรื่องแล้ว
