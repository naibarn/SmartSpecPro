# Remote Source Trust Verifier — Test Design v1

| Requirement                         | Test                                                                                          | Required result                                           | Not proven by fixture                              |
| ----------------------------------- | --------------------------------------------------------------------------------------------- | --------------------------------------------------------- | -------------------------------------------------- |
| Contract version and stable reasons | Valid envelope and each deny case                                                             | Exact schema and stable decision/reason                   | Approved production issuer                         |
| Signature integrity                 | Tamper signed payload/signature                                                               | DENY signature mismatch                                   | Real KMS operation                                 |
| Issuer allowlist                    | Forged/unknown issuer and key ID                                                              | DENY authority unknown                                    | Owner approval                                     |
| Key rotation                        | Old key in approved overlap, retired key after cutoff, revoked key                            | Accept only approved overlap; deny revoked/out-of-window  | Actual key rotation provisioning                   |
| Object immutability/content         | Mutate evidence index and a source/artifact object after signing                              | DENY content digest/size mismatch                         | R2 bucket policy                                   |
| Strict storage authority            | Arbitrary URL, wrong bucket identity, wrong prefix, traversal key                             | DENY before remote read                                   | Production storage credentials                     |
| Canonical identity binding          | Wrong tenant/run/workunit/job/attempt/fencing/source/profile/artifact                         | DENY exact binding mismatch                               | Current DB snapshot unless integration test runs   |
| Runner binding                      | Wrong runner node/session or capability revision                                              | DENY stale Runner binding                                 | Windows Runner readiness                           |
| Freshness                           | Future issued time, expired evidence, excessive age, invalid interval                         | DENY stale/future evidence                                | Approved max-age policy                            |
| Replay                              | Evidence reused with another job/attempt/session or duplicate ID                              | DENY replay/binding mismatch                              | Dispatch idempotency/consumption authority         |
| Revocation                          | Existing invalidation event or revocation after object read but before final revocation check | DENY revoked evidence                                     | PostgreSQL serialization at protected-start commit |
| Storage failures and timeout        | Missing object, auth failure, timeout, oversize object, failed abort                          | Stable DENY; no fallback                                  | Production service availability                    |
| Bounded execution                   | Excessive object count/bytes/concurrent reads                                                 | DENY without unbounded work                               | Deployment resource sizing                         |
| Side-effect isolation               | Run verifier without composition root                                                         | No DB write, key creation, grant, job, dispatch, or event | Runtime admission integration                      |

PostgreSQL concurrency/revocation tests belong to the later Lane 1 protected-start integration because they must prove the real `worker_jobs` row lock and revocation event are re-read in the commit transaction. A unit fixture or memory barrier must not be reported as that proof. No integration DB is used by this isolated verifier contract.
