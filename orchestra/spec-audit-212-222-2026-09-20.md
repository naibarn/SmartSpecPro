# Spec 212–222 Codebase Consistency Audit

วันที่ตรวจ: 2026-09-20

## ขอบเขตและวิธีตรวจ

ตรวจ Specs 212–222 และ companion artifacts ที่อ้างถึง โดยเทียบกับ repository baseline จริงใน `apps/web`, Drizzle migrations, worker_jobs/outbox, tenant context, skill/runtime services และ OpenAI Agents/Cloudflare adapters ที่มีอยู่แล้ว

SocratiCode MCP ไม่ถูก expose ใน tool transport รอบนี้ จึงใช้ targeted shell discovery ตามกฎ fallback: `rg`, bounded file reads, JSON parsing, SHA-256/byte verification และ `git diff --check` แทนการอ่านทั้ง repository แบบกว้าง

การตรวจแบ่งเป็น 20 รอบที่มีมุมตรวจต่างกัน และทำ post-fix convergence เพิ่ม 2 รอบ

## สิ่งที่แก้ไข

- เพิ่ม R20 corpus artifacts ของ Spec 212: 2,930 use cases/catalog records, contiguous `UC-0001..UC-2930`, TH/EN parity และ 100 cases ใหม่ในหกครอบครัว `20/20/15/15/15/15`
- ปรับ `spec-212-current-contract-profile-r20.json`, `spec-212-corpus-manifest-r20.json` และ `spec-214-spec212-coverage-manifest-r20.json` ให้ revision/count/execution/path/hash สอดคล้องกัน
- แก้ category boundary ของ UC-2831–UC-2930 ที่เดิมเลื่อนหนึ่งรายการ และย้าย UC-2930 ไป family ที่ถูกต้อง
- แก้ repository paths และ package manifest ให้ชี้ไปยังไฟล์จริง พร้อม SHA-256/byte verification
- แก้ Spec 215 current normative references จาก Spec 214 v4 เป็น v5
- เพิ่ม baseline evidence ใน Spec 216 เพื่อป้องกันการเข้าใจผิดว่า current code ได้ cut over เป็น canonical 214/215 แล้ว
- ลบ wording ที่อาจนำกลับไปใช้ retired `/workflows` หรือ Docker dispatch; คงเฉพาะ Cloudflare Container boundary ที่อนุมัติ

## Boundary ที่ยังต้องทำใน implementation phase

Codebase ปัจจุบันมี Workflow Studio baseline, tenant-safe persistence และ durable job boundary แล้ว แต่ canonical Spec 214 v5 node registry และ Spec 215 v3 compiler/runtime cutover ยังเป็นงานของ Spec 216 upgrade program; Specs 217–222 เป็น architecture freeze candidates ที่ยังต้องผ่าน conformance tests. จุดนี้ถูกทำให้ explicit ใน spec แล้ว ไม่ได้ปกปิดเป็น implementation complete
