# Public semantic design diff

## Previous public candidate

- Home began with generic catalogue framing and relied on local WebP illustrations without recorded provenance.
- Features and Docs rendered multiple local marketing WebP files as feature evidence.
- Shared SEO supplied `dashboard-preview.jpg` when a route had no approved social image.
- The Home page frame stopped at a maximum width but lacked centering, leaving the content left-aligned at large desktop widths.

## Current candidate

- One bilingual outcome-led Home H1, direct `/signup` CTA and visible Vertical Series handoff precede capability/resource discovery.
- Home, Features and Docs use code-rendered concept/capability panels; Home discloses that its flow is not a product screenshot or customer work.
- Social preview images are emitted only when explicitly supplied by route or tenant metadata; no platform fallback is invented.
- Home content sections share a centered 1320px wide frame, fill the viewport below that width, and reflow without measured horizontal overflow from 360px to 1920px.
- The public navigation, Footer, emergency entry, tenant-host decision and established CTA routes remain owned by their existing modules.

## Limits

This is a source-to-source semantic summary, not an approval against a Spec 270 native design artifact. Candidate screenshots use a local Vite server with API responses mocked. No real Film output, signed-in product capture, customer evidence, human imagery, production crawl, or deployed-source proof is included.
