# Session Resume — R4 Read / Restore / Reconcile / Resume

Use when `/orchestra resume` is requested or an unfinished Orchestra session is detected. **Never discard existing files because a snapshot is missing.** This is recovery of existing state, not a new approval gate.

1. **Read:** Load `orchestra/snapshot.json` if valid, then `snapshot.md`, `progress.md`, `backlog.md`, existing `lifecycle.md`, decisions/contracts when relevant, and Deep Plan/Implement section/config artifacts. Use targeted reads of listed `checkpoint.key_files` rather than loading every file. If JSON is corrupt/partial, fall back to readable records and actual repository state.
2. **Restore:** Establish the task goal, owner/worktree, current source/base SHA, completed and integrated steps, in-flight operation, remaining sections/gaps and exact next action. Preserve the existing snapshot schema defined in [compaction-safety](compaction-safety.md), including absolute key-file paths.
3. **Reconcile:** Inspect `git status`, commits, current configured Main SHA, and the relevant PR status. Files and commits **newer than the snapshot** take precedence after verification. An already-merged PR must not be re-created; an already committed section must not be implemented again solely because a state file was not updated. For missing output, mark only the affected step incomplete. Do not reset/clean a dirty or foreign-owned workspace.
4. **Resume:** Continue from the last proven checkpoint and earliest actually unfinished sub-step. Preserve unaffected completed work. Write the corrected continuation pointer to the existing progress/HandOff record and proceed without asking the user to say 'continue'. A true missing external authority blocks only the affected path.

If no `snapshot.json` exists, reconstruct from `progress.md`, `backlog.md`, plan/implementation configs, canonical Spec HandOff and Git instead of archiving or starting over by default. Explicit user-requested fresh starts may archive prior work **without deleting it**, after establishing ownership. A resume report should succinctly state recovered source SHA, completed work, current work, and next action; no banner or full-file reread is required.
