# Section 01: Contract and Validation

## Goal

Define the bundle contract for subagent-aware skills and extend the validation/discovery layers so the runtime can trust that contract before any code executes.

## Scope

This section covers:

- the machine-readable `subagents.json` manifest
- the `agents/` directory structure for orchestrator and specialist descriptions
- validation of `SKILL.md`, `skill.lock.json`, and `MODEL_COMPATIBILITY.md`
- compatibility updates in skill discovery and bundle snapshotting
- failure handling for contract/path mismatches
- security policy and manifest integrity checks for runtime-visible subagents

## Files to touch

- `apps/web/skills/intelligence-skill-creator/isc/native_bundle.py`
- `apps/web/skills/intelligence-skill-creator/isc/creator.py`
- `apps/web/skills/intelligence-skill-creator/isc/cli.py`
- `apps/web/server/services/skillFiles.ts`
- `apps/web/server/services/skillRegistry.ts`
- `apps/web/server/services/skillCompatibilityGate.ts`

## Implementation notes

- Add a structured parser for `subagents.json` that validates the bundle shape without falling back to prose parsing.
- Keep `SKILL.md` as the human-readable contract, but treat the machine-readable manifest as the authoritative runtime topology source.
- Preserve single-agent bundles as valid inputs. Absence of `subagents.json` should not break existing bundles.
- Update native bundle scaffolding so `agents/orchestrator.md`, `agents/specialists/*.md`, and `references/subagents.md` are emitted alongside the Feature 106 files.
- Update discovery and contract snapshots so the new files are included in bundle inventories and compatibility checks.
- Reject invalid path traversal, undeclared subagents, missing checkpoint policies, and manifest/doc mismatches early.
- Validate manifest hash/signature references and security policy before any subagent code is loaded or any specialist tool is invoked.

## Acceptance criteria

- A valid subagent-aware bundle can be recognized without executing it.
- A malformed manifest is rejected before runtime loading.
- Existing single-agent bundles continue to validate and run unchanged.
- The contract files generated by ISC and the contract files inspected by runtime/maintenance agree on file names and topology.

## Test-first guidance

- Write contract tests before touching runtime or creator behavior.
- Cover valid and invalid manifests, missing policies, legacy bundles, and bundle snapshot expectations.

## Implementation Outcome

- `apps/web/skills/intelligence-skill-creator/isc/native_bundle.py` now emits `subagents.json`, `agents/orchestrator.md`, `agents/specialists/*.md`, and `references/subagents.md` when a plan includes subagents, while preserving legacy single-agent bundles unchanged.
- The native bundle validator now rejects malformed topology manifests, path traversal, undeclared routing targets, missing checkpoint and verification policies, and topology/doc mismatches before runtime loading.
- `apps/web/skills/intelligence-skill-creator/isc/creator.py` passes topology metadata through to native bundle generation, and `apps/web/skills/intelligence-skill-creator/isc/cli.py` records whether the created bundle is single-agent or subagent-aware.
- `apps/web/server/services/skillFiles.ts`, `apps/web/server/services/skillRegistry.ts`, and `apps/web/server/services/skillCompatibilityGate.ts` now inventory the new topology files and treat removals or invalid manifests as compatibility drift.
- Coverage was added in `apps/web/skills/intelligence-skill-creator/tests/test_native_bundle_contract.py`, `apps/web/server/services/skillFiles.test.ts`, and `apps/web/server/services/__tests__/skillCompatibilityGate.test.ts`.
