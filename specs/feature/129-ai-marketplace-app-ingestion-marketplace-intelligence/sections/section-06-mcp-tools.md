# Section 06 - MCP Tools

## Objective

Expose controlled marketplace intelligence tools that save and report on connector-derived marketplace data for the authenticated user only. In v1, Shopee data is obtained by the OpenAI/ChatGPT host through the Shopee app, then written back into SmartSpecPro through these tools or the matching HTTPS API alias.

## Scope

- Tool schemas.
- Tool registration in the repo's MCP server integration.
- HTTPS API alias for connector hosts that cannot call the MCP surface directly.
- Save snapshot, generate report, list snapshots, and get snapshot tools.

## Implementation Notes

- Route all writes through `marketplaceIntelligenceService`.
- Require SmartSpecPro user context and active SmartSpecPro write-back grant when saving connector-sourced data.
- Do not require, store, or infer Shopee cookies, OpenAI connector tokens, or connector-host session secrets.
- Tool descriptions must instruct the OpenAI host to call the save tool only after it has obtained Shopee search results from the Shopee app.
- The save tool must accept raw OpenAI-hosted Shopee output plus normalized hints and source provenance: `sourceProvider=openai_hosted_shopee_mcp`, `executionHost=openai_chatgpt`, upstream app ID, upstream tool name, host correlation ID, source captured time, and source freshness.
- Require the same authenticated user who owns the connector grant and snapshot. Tenant membership alone is not enough.
- Allow tools to return Marketplace Capture product-link candidates and enrichment results, but never mutate Marketplace Capture product truth without the service's confidence/provenance rules.
- Mark write-capable and read-only tools clearly.
- Make save operations idempotent.
- Return SmartSpecPro URLs for snapshots and reports.
- Exclude raw payloads from general read tools.

## Tests First

- Tool input schemas reject invalid auth, unsupported platform, unsupported execution host, missing write-back grant, and oversized payloads.
- Save tool accepts OpenAI-hosted Shopee payloads and stores source provenance.
- Cross-user grant/snapshot/tool access is rejected.
- Save tool returns the same result for duplicate idempotency keys.
- Report tool reads stored snapshots only.
- Read tools omit restricted raw fields.

## Acceptance Criteria

- External AI workflows can save useful marketplace data into SmartSpecPro without creating a second ingestion path.
- OpenAI-hosted Shopee app workflows can save real Shopee search payloads into SmartSpecPro without SmartSpecPro holding the Shopee session.
- Tool behavior remains auditable and tenant-safe.
- Tool behavior remains user-scoped: a user's connector access cannot be reused by another user or by a tenant-level automation in v1.

## Implementation Status

Completed foundation:

- All read/write behavior needed by future tools now routes through `marketplaceIntelligenceService`.
- The service exposes save snapshot, list/get snapshot, generate report payload, list reports, create report export, create watchlist, record/list watchlist events, diagnostics, field dictionary, and Marketplace Capture handoff functions.
- tRPC procedures provide the same validated path used by browser UI and MCP tools.
- Registered MCP tools in `apps/web/server/_core/mcpRegistry.ts`:
  - `smartspec.marketplace_intelligence.search_snapshot.save`
  - `smartspec.marketplace_intelligence.snapshots.list`
  - `smartspec.marketplace_intelligence.snapshot.get`
  - `smartspec.marketplace_intelligence.report.generate`
  - `smartspec.marketplace_intelligence.capture_batch.create`
  - `smartspec.marketplace_intelligence.watchlists.list`
  - `smartspec.marketplace_intelligence.watchlist.upsert`
- Added the `marketplace_intelligence` MCP family plus read/write tool groups with per-session `mcp:read` and `mcp:write` scope enforcement.
- Read outputs omit raw diagnostic payloads from stored snapshots.
- Tool outputs now include browser deep links for snapshots, reports, watchlists, and Marketplace Capture candidate batches.
- The shared path persists connector-derived outputs to Drizzle tables when DB is configured, so MCP tools do not need a second storage path.
- MCP registry tests verify read/write visibility by scope, save/report execution, deep links, and watchlist upsert/list behavior through the service.

Revised implementation requirement:

- Replace any save-tool path that fabricates a recorded probe with a real payload ingestion path. Recorded probes remain test fixtures only.
- Add the matching HTTPS write-back endpoint and make both MCP and API writes call the same validator/service.
- Add a user-scoped write-back token/package endpoint issued from the active SmartSpecPro connector grant so an external connector host can call the HTTPS alias without a browser session cookie. The token must be signed, expiring, revocable through the grant hash, and scoped to one tenant/user/provider.
- Add tests that prove an OpenAI-hosted Shopee payload becomes `sourceProvider=openai_hosted_shopee_mcp` and `sourceFreshness=live_at_writeback` only when trusted source provenance is present.
- Full idempotency replay semantics remain a follow-up hardening item.
