# Section 11: Fixtures, E2E, and Release Gates

## Goal

Build the test fixture matrix and browser verification required to prove the HyperFrames Auto Storyboard Review feature works end to end without regressing Standard Order.

This section is the release gate aggregator.

## In Scope

- Fixture definitions for service, router, worker, and UI tests.
- Playwright e2e coverage for Product Detail, Storyboard Review, MediaStudio, Library, and Standard Order preservation.
- Accessibility and responsive checks.
- Release gate command list.
- Evidence file expectations.

## Files To Create

- `apps/web/tests/e2e/marketplace-hyperframes-ui.spec.ts`
- fixture files under an existing test fixture directory, or `apps/web/test-fixtures/hyperframes/` if no suitable location exists
- `apps/web/test-results/marketplace-hyperframes/` generated by tests only
- script entries or command wrappers for dependency audit, doctor, fixture render, and snapshot test gates

## Existing Files To Review

- `apps/web/tests/e2e/production-director-browser.spec.ts`
- `apps/web/playwright.config.ts`
- existing Marketplace Auto Review service/router tests
- existing Product Detail test helpers

## Test First

Define failing or pending fixture-driven tests for:

- HyperFrames disabled with Standard Order working;
- HyperFrames enabled with Auto ready and one-click start;
- Auto blocked by worker/template/credit/anchor/compliance state;
- Standard Order still startable while Auto is blocked;
- storyboard ready queues preview;
- render completed enables review and Library save;
- duplicate Library save returns existing item;
- Storyboard Review reload keeps output context;
- MediaStudio reload resumes render-to-library session;
- Video Editor opens finalized MP4;
- mobile and desktop layouts avoid overlap/overflow.

## Fixture Matrix

Minimum fixtures:

- ready product with product image anchors;
- product missing required anchors;
- product with generated storyboard only;
- product with storyboard and generated clips;
- product requiring compliance/disclosure review;
- insufficient credit/quota;
- worker disabled;
- template disabled;
- completed render with QA pass;
- completed render with QA fail;
- duplicate finalize attempt;
- Standard Order full video request.

Use existing factories and mocks where possible. Avoid adding external network dependencies to tests.

Expanded spec-aligned fixture groups:

| Group | Cases | Required proof |
|---|---|---|
| Product categories | household, electrical appliance, cosmetics/skincare, food/beverage, fashion, electronics, mother/baby, automotive, pet supplies | product truth maps correctly and unsupported claims are blocked |
| Regulated/high-risk claims | whitening/beauty, supplement-like wording, medical/safety claims, price/discount volatility, affiliate/material connection | disclosures render when required and blocked claims are omitted |
| Thai text stress | long Thai title, mixed Thai/English, emoji/symbol input, long subtitle cue, narrow safe-area caption | no overflow, clipping, unreadable contrast, or layout shift |
| Media aspect/quality | square image, tall image, transparent PNG, multi-view sheet, missing thumbnail, low-resolution frame, odd-aspect video clip | product identity is preserved and fallback states are clear |
| Subtitle/audio | silent output, native video audio, TTS alignment, ASR transcript, subtitle-heavy final composite, drift beyond tolerance | subtitle/audio QA accepts or blocks correctly |
| Platform profiles | 9:16 generic, TikTok/Reels/Shorts 9:16, square 1:1, landscape 16:9, mobile preview, desktop preview | safe area, thumbnail, disclosure, and CTA placement pass |
| Failure/recovery | worker unavailable, FFmpeg missing, Chrome missing, template disabled, stale input hash, dead-letter retry exhausted | UI status projection and next action match status matrix |
| Permissions | product owner, runner, group-shared viewer, group-shared editor, cross-tenant attempted lookup | access projection, credit payer, and output links are correct |

Fixture outputs must include:

- input envelope JSON;
- composition HTML hash, not raw HTML in long-lived logs;
- snapshots at required key frames;
- expected status projection;
- expected Library metadata when final save is allowed;
- expected blocked reason when final save is not allowed.

## Release Gate Commands

Use the package manager already used by the repo. Suggested focused gates:

- `npm --prefix apps/web run test -- apps/web/shared/hyperframes`
- `npm --prefix apps/web run test -- apps/web/server/services/__tests__/hyperframes`
- `npm --prefix apps/web run test -- apps/web/server/routers/__tests__/marketplaceCapture.hyperframesRuntimeApi.test.ts`
- `npm --prefix apps/web run test -- apps/web/client/src/components/marketplaceCapture`
- `npm --prefix apps/web run test -- apps/web/client/src/pages/__tests__/StoryboardReviewPage.hyperframes.test.tsx`
- `npm --prefix apps/web run test -- apps/web/client/src/pages/__tests__/MediaStudio.hyperframesRenderSession.test.tsx`
- `npm --prefix apps/web run test`
- `npm --prefix apps/web run check`
- `npm --prefix apps/web run e2e -- marketplace-hyperframes-ui.spec.ts`
- `npm --prefix apps/web run hyperframes:dependency-audit`
- `npm --prefix apps/web run hyperframes:doctor`
- `npm --prefix apps/web run hyperframes:fixture-render`
- `npm --prefix apps/web run hyperframes:snapshot-test`

Adjust command names to the actual scripts in `apps/web/package.json` during implementation.

Required proof by gate:

| Gate | Must prove |
|---|---|
| `hyperframes:dependency-audit` | pinned package versions, compatible license, lockfile provenance, native/postinstall review, browser/FFmpeg/font version capture |
| `hyperframes:doctor` | Node, HyperFrames CLI/runtime, Chrome/headless shell, FFmpeg/FFprobe, fonts, storage, and temp workspace readiness |
| `hyperframes:fixture-render` | fixture composition renders playable MP4, snapshots, manifest, and cleanup |
| `hyperframes:snapshot-test` | golden frames pass for built-in templates, long Thai text, missing price/rating, CTA scene, disclosure scene, and 9:16 safe areas |

## Acceptance Criteria

- Fixture matrix covers ready, blocked, disabled, failed, completed, duplicate, and Standard Order cases.
- Fixture matrix covers the expanded product/category/text/media/audio/platform/permission groups from the spec.
- E2E proves Auto is auto-first and Standard is preserved.
- Browser evidence shows no overlapping controls or horizontal overflow.
- Security, router, dependency, doctor, fixture-render, and snapshot gates pass or are explicitly blocked before dependency rollout.
- Release gate command list is recorded in the implementation PR or closeout.

## Rollback Notes

Keep Standard Order tests in the gate suite after rollout so future HyperFrames changes cannot hide or break it.
