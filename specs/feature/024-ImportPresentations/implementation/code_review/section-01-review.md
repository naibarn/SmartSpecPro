# Code Review: section-01-db-migration

## CRITICAL (HIGH SEVERITY)

### Issue 1: `onConflictDoUpdate` broken by partial index change
**File:** `apps/web/server/services/presentationPersistence.ts`
**Severity:** HIGH — runtime crash for existing PPTX flow

The upsert uses `target: [tenantId, sourceItemId]` which generated `ON CONFLICT (tenant_id, source_item_id)`. The plain unique index was replaced by a partial unique index (`WHERE source_item_id IS NOT NULL`). PostgreSQL will throw `there is no unique or exclusion constraint matching the ON CONFLICT specification` at runtime. Requires `targetWhere: sql`${t.sourceItemId} IS NOT NULL`` in Drizzle.

### Issue 2: `presentationConversionResultSchema.sourceItemId` still required
**File:** `apps/web/shared/presentation/contracts.ts`
**Severity:** HIGH — Zod will throw when Google Slides record has `sourceItemId: null`

`sourceItemId: z.number().int().positive()` must become `.optional()` or `.nullable()` to support Google Slides imports where there is no source library item.

## MEDIUM SEVERITY

### Issue 3: `mapStoredConversionRecord` silently maps `"google_slides"` to `"pptx"`
**File:** `apps/web/server/services/presentationPersistence.ts`
**Severity:** MEDIUM — silent data corruption

```typescript
sourceFormat: row.sourceFormat === "ppt" ? "ppt" : "pptx",
```
A `"google_slides"` row returns as `"pptx"`. Needs a three-way check, and `StoredPresentationConversionRecord.sourceFormat` needs widening.

### Issue 4: Input interfaces not widened for Google Slides path
**File:** `apps/web/server/services/presentationPersistence.ts` and `presentationCompatibilityService.ts`
**Severity:** MEDIUM — sections 05/06 will be blocked by TypeScript errors

`UpsertPresentationConversionRecordInput.sourceItemId` is still `number` (not `number | null`) and `sourceFormat` is still `"pptx" | "ppt"`. Sections 05/06 need to call these functions with Google Slides data.
