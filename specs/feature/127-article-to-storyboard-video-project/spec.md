**Spec ID:** 127-article-to-storyboard-video-project
**Created:** 2026-06-28
**Updated:** 2026-06-30
**Status:** Proposed
**Owner:** Presentation Builder / Storyboard Review / Media Generation / Video Overlay
**Extends:** `111-presentation-builder-split-layer-video-editor`
**Related:** `118-marketplace-auto-review-create-storyboard-video-review-auto`, `122-video-segment-planner-multi-shot-storyboard-review`, `125-storyboard-preview-match-browser-capture`

## 1. Executive Summary

Presentation Builder currently turns an article/topic into a page-by-page presentation. That remains useful for document-style slides, but the new product direction is video-first:

> Turn each article/presentation page into a video shot inside Storyboard Review, then render the page title/key text as CSS text overlay on top of the generated video.

This feature adds a new opt-in output path, separate from existing Presentation output:

```text
article/topic
  -> existing article/page split
  -> per-page video shot plan
  -> Storyboard Review project
  -> one storyboard task/shot per article page
  -> video prompt/reference frame per shot
  -> CSS text overlay layer from page title/key text
  -> Storyboard Review generates/reviews video shots
```

The primary output is **not** a new static Presentation image. It is a **Storyboard Review Project** that represents the article as a modern presentation-style video: moving video backgrounds/visuals plus editable text overlays.

Existing Presentation modes must remain unchanged. This feature is an additional output option.

---

## 2. Problem Statement

The current article-to-presentation flow is slide-first:

- article pages become document-like visual pages;
- text is often baked into the slide image or presentation structure;
- motion/video is a later or separate step;
- the result can feel less aligned with current short-form and explainer-video workflows.

Users increasingly want to turn written content into video. For article/page-based content, the better target is:

- each page becomes one video shot or scene;
- page title/key text becomes an editable overlay layer;
- video generation happens in Storyboard Review where video review and replacement already exist;
- text remains CSS overlay, not baked into the generated video, so it can be edited, styled, timed, hidden, or exported cleanly.

---

## 3. Goals

1. Add an opt-in output option named **Article To Storyboard Video Project**.
2. Preserve all existing Presentation Builder modes and outputs.
3. Reuse the existing article/page split as the video structure.
4. Convert each article page into one Storyboard Review video shot/task by default.
5. Generate one 3x3 visual reference candidate sheet per page, optionally grounded by character reference images, then select 1-5 frames as reference images for video prompt generation.
6. Create a Storyboard Review Project as the primary output.
7. Use Storyboard Review's existing video generation/review flow for generated video shots.
8. Store text as CSS overlay layer metadata above video, not as baked text inside generated frames.
9. Use `seedance-multishot-review` to generate the initial Seedance-oriented multi-shot video prompt from page content and selected reference images.
10. Let users choose an audio strategy: separate TTS voiceover or native video audio/speech generated by the video model.
11. For separate TTS voiceover, generate voiceover as separate TTS script/audio, initially through Media Studio's Uvoice premium model path.
12. For native video audio, embed the spoken Thai narration/dialogue intent into the video prompt when the selected video model supports it.
13. Let users choose both the video model and voice model in the Builder preview when separate TTS voiceover is selected, then map those selections into Storyboard Review config.
14. Align total video shot timing to the generated/measured TTS voiceover duration as much as possible when using separate TTS voiceover.
15. Require a concrete voice ID for each selected TTS speaker when using separate TTS voiceover, not only a voice model.
16. Support both single-narrator voiceover and two-speaker dialogue mode for article storytelling.
17. Add a dedicated LLM skill that rewrites article pages into a more engaging storytelling voice script before either TTS generation or native video speech prompting.
18. Keep provider spend controlled with feature flags, previews, credit estimates, and explicit user actions.

---

## 4. Non-Goals

1. Do not replace normal Presentation generation.
2. Do not make article-to-video the default output.
3. Do not rebuild Storyboard Review inside Presentation Builder.
4. Do not build a new video editor engine for this feature.
5. Do not bake article text into generated video frames.
6. Do not make the 3x3 candidate sheet the final output; it is only a reference-selection stage for video prompting.
7. Do not remove the current full-slide image or split-layer Video Editor path.
8. Do not require per-frame generation or image-to-video repair in v1.
9. Do not ask a video model to generate speech unless the selected audio strategy is `native_video_audio` and the selected model capability supports the required spoken language.
10. Do not ask a video model to generate subtitles, captions, or readable overlay text; overlay text remains CSS metadata.
11. Do not silently change the selected video model, audio strategy, voice model, voice mode, or speaker voice IDs after handoff.
12. Do not build a full podcast editor in MVP; the first version only needs structured single-speaker and two-speaker script generation plus native-video-speech or per-speaker TTS handoff.

## 5. Product Direction

### 5.1 Chosen Approach

Use Presentation Builder as the article authoring/planning entry point, then hand off to Storyboard Review as the video workspace.

Recommended mental model:

- Presentation Builder owns article generation and page splitting.
- Feature 127 converts pages into video shot plans.
- Storyboard Review owns video shot generation, review, replacement, and downstream video workflow.
- CSS overlay metadata carries the article title/key text above each video shot.

This avoids forcing video workflow into the old Presentation document model. It also avoids duplicating Storyboard Review behavior.

### 5.2 Why Storyboard Review Is The Primary Output

Storyboard Review already matches the target job:

- generate and review video shots;
- replace failed shots;
- keep source metadata;
- support downstream video project workflows;
- support video plus overlay concepts.

Presentation Builder should therefore create a Storyboard Review Project, not a heavier Presentation draft.

### 5.3 MVP Shape

MVP should create:

- one Storyboard Review Project per article/video export;
- one video shot/task per article page;
- one 3x3 reference candidate sheet per shot;
- optional character reference images attached before generating the 3x3 candidate sheet;
- 1-5 selected reference images per shot;
- one Seedance-oriented prompt per shot generated through `seedance-multishot-review`;
- one CSS text overlay layer per shot;
- one storytelling script segment per shot;
- audio strategy per project/shot: either separate TTS voiceover or native video audio;
- selected video model, audio strategy, voice mode, and separate-TTS voice model/speaker voice ID config carried into Storyboard Review;
- selected voice ID carried per speaker when separate TTS is used so TTS can reproduce the intended voice later;
- single-narrator or two-speaker storytelling script generated from the article before TTS or native speech prompting;
- audio-first timing that adjusts shot durations to match generated/measured TTS length when separate TTS is used;
- optional repair/regenerate action through Storyboard Review.

The 3x3 sheet is not the final artifact. It is a visual reference picker for the Seedance prompt and video generation flow.

## 6. User Experience

### 6.1 Output Option

Add a new opt-in output option under Presentation Builder `Media & Output`.

Thai:

- `สไลด์แก้ไขได้`
- `สไลด์เป็นภาพทั้งหน้า`
- `แยก Layer Text สำหรับ Video Editor`
- `สร้าง Storyboard Video จาก Article`

English:

- `Editable slides`
- `Full-slide image`
- `Split text layers for Video Editor`
- `Article to Storyboard Video`

Explanation:

Thai:

> แปลงแต่ละหน้า article เป็น shot วิดีโอใน Storyboard Review พร้อมข้อความแบบ CSS overlay ซ้อนบนวิดีโอ

English:

> Convert each article page into a Storyboard Review video shot with editable CSS text overlay.

### 6.2 Builder Steps

The current Presentation Builder flow remains intact. This feature adds a new branch after article/page planning:

1. Generate article / import brief.
2. Plan pages from the article.
3. If normal Presentation mode is selected, keep the current Presentation output behavior.
4. If Article to Storyboard Video is selected:
   - create one video shot plan per page;
   - derive title/key text overlay per page;
   - attach character reference images when available;
   - generate/select 3x3 reference candidates per page;
   - select 1-5 reference frames for the video prompt;
   - build Seedance-oriented video prompt via `seedance-multishot-review`;
   - generate a storytelling voiceover/dialogue script via the article voice script skill;
   - choose audio strategy: separate TTS voiceover or native video speech/audio;
   - prepare voiceover script segments for Media Studio TTS when using separate TTS;
   - embed spoken script/dialogue lines into the video prompt when using native video audio;
   - choose video model, voice mode, and, only for separate TTS, voice model plus voice ID for each speaker;
   - preview estimated shot count, duration, and credits;
   - create a Storyboard Review Project.
5. Open the created Storyboard Review Project.
6. User generates/reviews/replaces video shots and voiceover in Storyboard Review.

### 6.3 Builder Preview UX

Before creating the Storyboard Review Project, show a compact preview that answers three user questions without requiring them to understand internal concepts:

1. **What will be created?**
   `N video shots in Storyboard Review`, one shot per article page.
2. **What text will appear on video?**
   A page list with the overlay headline/subtext for each shot.
3. **What will cost credits?**
   Creating the Storyboard Review Project should be cheap/non-provider work; paid video generation happens later in Storyboard Review.

Recommended layout:

- top summary: shot count, ratio, estimated duration, selected video model, selected audio strategy, selected voice model when applicable, selected voice/speaker count, credit estimate;
- model controls: video model selector, audio strategy selector, voice mode selector, and, for separate TTS only, voice model selector plus required voice ID selector for each speaker with provider/access warnings;
- audio mode explanation:
  - separate TTS: voice can be regenerated/replaced without regenerating video;
  - native video audio: speech is part of the generated video, so script or voice changes require video regeneration;
- page list: page number, page title, overlay text preview, prompt preview button;
- warning area: missing page text, long overlay text, unsupported ratio/model/audio strategy, missing access/credit estimate;
- primary action: `สร้าง Storyboard Review Project`;
- secondary action: `กลับไปแก้ Article`;
- no automatic video generation from this preview unless a later explicit mode is added.

The preview must clearly say that text is editable overlay and will not be drawn by the video model.

### 6.4 Storyboard Review Workspace

The created Storyboard Review Project should show:

- page/shot order from the article;
- each page as one video shot task;
- selected audio strategy for the project/shot;
- video prompt generated from article page content;
- storytelling script/native speech lines or separate voiceover text when available;
- separate TTS voice controls only when `audioStrategy = "separate_tts_voiceover"`;
- native-video-audio notice when speech is embedded in the generated video and script edits require video regeneration;
- CSS text overlay layer for title/key message;
- static slide/document image only as optional reference/fallback, not as the primary artifact.

Storyboard Review remains the place where the user:

- generates video;
- repairs/regenerates failed video shots;
- edits/replaces video output;
- previews text overlay over video;
- sends the result onward to Video Editor/final composite.

### 6.5 Text Overlay UX

Text should be editable as overlay metadata, not baked into provider-generated video.

Each page can produce:

- heading/title overlay;
- optional subtitle/body summary overlay;
- placement preset, for example `lower_third`, `center_title`, `top_caption`, `side_panel`;
- typography preset;
- timing relative to the shot;
- safe-area constraints for vertical/horizontal ratios.

The user should be able to edit overlay text and style after handoff without regenerating the video.

### 6.6 UI/UX Anti-Confusion Rules

The UI must keep these concepts visually and textually separate:

| Concept | User-facing label | What it controls |
| --- | --- | --- |
| Video prompt | `Video prompt` / `พรอมป์วิดีโอ` | What the AI video model should generate visually |
| Overlay text | `Text on video` / `ข้อความบนวิดีโอ` | CSS text shown above the generated video |
| Narration | `Voiceover` / `เสียงบรรยาย` | Audio/script spoken over the shot |
| Audio strategy | `Audio mode` / `โหมดเสียง` | Whether speech is generated inside the video or as separate voiceover |
| Reference image | `Reference image` / `ภาพอ้างอิง` | Optional visual guide for video generation |
| Video model | `Video model` / `โมเดลวิดีโอ` | Provider/model used for shot video generation |
| Voice model | `Voice model` / `โมเดลเสียง` | Provider/model used for separate TTS voiceover generation |
| Voice ID | `Voice` / `เสียงพูด` | Concrete speaker voice used by the selected TTS model |
| Storytelling script | `Voiceover script` / `บทพูด` | LLM-written narration/dialogue used by either separate TTS or native video speech |

Rules:

- never place video prompt and overlay text in the same editable field;
- overlay text fields should stay short and show character guidance;
- if prompt-like text is pasted into overlay text, show the existing Storyboard Review warning pattern and ask the user to shorten it into on-screen copy;
- if overlay text is too long for the selected preset/ratio, show an inline warning and offer a shorter suggested summary;
- video prompt must include an instruction not to draw captions/subtitles/text;
- when audio strategy is `separate_tts_voiceover`, video prompts must remain silent/no-speech and voiceover is generated separately;
- when audio strategy is `native_video_audio`, video prompts may include Thai speech/dialogue only if the selected video model capability supports native audio and the required spoken language;
- UI copy should avoid ambiguous wording: ElevenLabs Text to Dialogue is still separate TTS audio, while `native_video_audio` means speech generated inside the video clip by the video model;
- video model changes mark video prompts/stored video outputs stale;
- audio strategy changes mark video prompts and generated video/audio stale;
- voice model, voice ID, or speaker mode changes mark voiceover script/audio stale but do not mark video prompts stale when using separate TTS;
- Storyboard Review should show the selected shot with tabs or clearly separated sections: `Video`, `Text on video`, `Voiceover`, `Reference`.

Resolution rules:

- default to `separate_tts_voiceover` for predictable editing and timing;
- allow `native_video_audio` only when the selected video model capability and feature flags explicitly allow native audio in the requested spoken language;
- never silently downgrade from `native_video_audio` to `separate_tts_voiceover`; show the reason and ask the user to confirm the fallback;
- when `separate_tts_voiceover` is selected, block handoff until required voice model/voice ID config is complete;
- persist both requested and resolved strategy so Storyboard Review can explain why a fallback happened.

### 7.4 Storytelling Audio Contract

Storytelling script is separate from overlay text. It can be rendered either as separate TTS voiceover or as native speech/audio inside the generated video.

```ts

  language: string;

  modelPreference?: "uvoice_premium" | "other_tts";
  voiceModelId?: string;

  provider?: string;
  transport?: "gateway_api" | "mcp";
  primaryVoiceId?: string;
  speakers: ArticleStoryboardVoiceSpeaker[];
  segments: ArticleStoryboardVoiceScriptSegment[];

  mergedAudioUrl?: string;
  voiceSettings?: Record<string, unknown>;

  audioAssetId?: string;
  audioUrl?: string;

};
```

Rules:

- audio strategy must be explicit in Builder preview and persisted into Storyboard Review;
- when `audioStrategy = "separate_tts_voiceover"`, voiceover script segments are sent to Media Studio TTS, not to the video model;
- when `audioStrategy = "native_video_audio"`, spoken script/dialogue lines are embedded in the video prompt and generated by the video model;
- first separate-TTS rollout should prefer Uvoice premium when available;
- Builder must let the user choose the voice model and the concrete voice ID for each speaker only when separate TTS is selected; Uvoice premium is the recommended default, not a hidden hardcode;
- separate TTS single-narrator mode requires exactly one speaker voice ID;
- separate TTS two-speaker dialogue mode requires exactly two distinct speaker slots, each with its own required voice ID;
- provider capability determines the TTS render strategy for separate TTS:
  - TTS providers/models with provider-native multi-speaker dialogue support, such as ElevenLabs Text to Dialogue, should use `single_request_dialogue`;
  - single-speaker TTS providers/models, including UVoice, should use `segment_then_merge` for two-speaker dialogue;
  - simple one-speaker narration may use `single_request` when the provider supports the selected text length.
- video model capability determines whether native video audio is allowed:
  - models that support native Thai audio, such as supported Seedance versions, Veo 3.1, or omni-style video models, may receive Thai spoken dialogue/narration in the prompt;
  - models without native audio or without Thai speech support must fall back to `separate_tts_voiceover` or `silent`;
  - native video audio should be blocked when the selected model cannot guarantee speech in the requested language.
- ElevenLabs Text to Dialogue routes should preserve speaker turns and submit them as a structured separate-TTS dialogue input with each turn bound to its selected `voice_id`;
- UVoice routes should persist the selected UVoice `voiceID` value as `voiceId`/`primaryVoiceId` metadata and pass it back as `voiceID` in provider params;
- UVoice two-speaker dialogue must generate one audio segment per script turn or contiguous speaker group, then merge/place those segments sequentially on the Storyboard Review companion audio timeline;
- voiceover script text should remain editable before audio generation;
- editing the voiceover script marks TTS audio stale for separate TTS and marks the video prompt/generated video stale for native video audio;
- generated separate TTS audio should attach to the matching Storyboard Review shot/task;
- Storyboard Review render/final composite should be able to render video plus voiceover audio and CSS overlay together.

### 7.5 Storytelling Voice Script Skill

Add a new LLM-only skill dedicated to rewriting article pages into a spoken script:

- skill ID: `article-storytelling-voiceover-script`;
- input: article title/topic, locale, page list, desired script mode, tone, target total duration, per-page target durations, speaker roles, and safety constraints;
- output: structured script segments mapped back to `pageNumber` and `shotId`;
- the skill should use the provided speaker IDs/roles and must not invent or silently change voice model IDs or voice IDs;
- voice model IDs and voice IDs are required only for separate TTS; native video audio only needs stable speaker IDs/labels for prompt speech lines;
- supported modes:
  - `single_narrator`: one narrator reads a polished storytelling version of the article;
  - `two_speaker_dialogue`: two speakers discuss the article in a natural question/answer or host/cohost style;
- inspiration may come from product voiceover and dialogue examples such as ElevenLabs-style product narration/dialogue, but the skill must be SmartSpecPro-specific and optimized for article-to-video storytelling;
- script must preserve factual meaning from the article and avoid inventing unsupported claims;
- script should transform plain article prose into a stronger story arc: hook, context, key points, examples, takeaway;
- script should avoid saying slide/page numbers unless the article content requires it;
- script should not include visual prompt instructions, CSS overlay copy, sound effects, music cues, or video camera directions;
- script output must be safe for TTS/native speech and should avoid markup that would be spoken literally.

Recommended skill output shape:

```ts
type ArticleStorytellingVoiceScriptResult = {
  skillId: "article-storytelling-voiceover-script";
  mode: "single_narrator" | "two_speaker_dialogue";
  language: string;
  tone: "educational" | "documentary" | "casual_explainer" | "product_story" | "news_brief";
  speakers: ArticleStoryboardVoiceSpeaker[];
  segments: ArticleStoryboardVoiceScriptSegment[];
  fullText: string;
  estimatedDurationSeconds: number;
  recommendedTtsRenderStrategy?: "single_request" | "single_request_dialogue" | "segment_then_merge";
  warnings?: ArticleStoryboardVideoWarning[];
};
```

The script skill owns the storytelling and turn-taking structure only. The TTS adapter owns provider-specific rendering:

- for ElevenLabs Text to Dialogue, convert the ordered segments into one structured dialogue request, preserving `speakerId`, `voiceId`, and turn order;
- for UVoice, convert the ordered segments into multiple TTS requests like:

```json

  {
    "speaker": "พิธีกรชาย",
    "voiceID": "TH-KantapongPremiumHD",

```

Each UVoice item should generate its own audio asset first. The system then creates a merged/compound voiceover or timeline sequence by placing the generated assets in `sequenceIndex` order.

### 7.7 Seedance Prompt Rules

Each page should produce a video prompt that describes the visual scene and follows the selected audio strategy.

Prompt should include:

- page intent;
- key visual metaphor or literal scene;
- camera movement;
- subject/action;
- mood/style;
- duration target;
- narration context;
- reference image constraints when available;
- character reference constraints when character reference images are attached;
- instruction to avoid captions, subtitles, logos, random glyphs, or generated text unless the article page is explicitly about UI/screen content.
- if `audioStrategy = "separate_tts_voiceover"`, instruction that the video is silent/no speech/no lip-sync because voiceover is generated separately;
- if `audioStrategy = "native_video_audio"`, spoken Thai narration/dialogue lines from the storytelling script when the selected video model supports native Thai audio.

Use `seedance-multishot-review` for the initial video prompt:

- output must be plain text;
- use 4 or 5 internal shots as required by the skill;
- use selected reference images to ground visual scene/composition;
- use character reference images to lock host/character identity, appearance, outfit, and role when available;
- for non-product articles, map the article subject into `product_category = "other"` and use generic subject/scene wording;
- keep strict sanitization on for public-facing prompts;
- do not include the word Seedance in the prompt unless the skill/provider config explicitly allows it;
- for Seedance, native Thai speech must remain capability-gated because only supported versions should receive Thai dialogue instructions.

Important implementation note:

- the current `seedance-multishot-review` skill is a silent-video prompt generator;
- for `separate_tts_voiceover`, use the skill output directly as the final visual-only prompt;
- for `native_video_audio`, either add a capability-gated audio-policy extension to the skill or compose a final prompt from:
  - the visual prompt generated by `seedance-multishot-review`;
  - the selected native audio policy;
  - validated Thai speech/dialogue lines from `article-storytelling-voiceover-script`;
- do not bypass the capability gate by appending speech lines to a model/version that is still configured as silent-only.

### 7.8 Audio And Timing Rules

The system should try to keep video duration and spoken script duration aligned. The timing source depends on the selected audio strategy.

Rules:

- for `separate_tts_voiceover`, generate or measure voiceover duration before final video timing whenever `audio-first` mode is enabled;
- for `separate_tts_voiceover`, total shot duration should target total voiceover duration;
- for `native_video_audio`, prompt speech lines must fit within the selected video model's shot duration limits;
- for `native_video_audio`, if the script is too long for the shot duration, shorten the script or increase shot duration before video generation rather than expecting post-merge audio timing fixes;
- distribute duration across shots using page text length, narration segment length, and min/max model duration limits;
- update each `ArticleStoryboardVideoShotPlan.durationSeconds` after the timing pass;
- store `targetDurationSeconds`, `estimatedDurationSeconds`, and `actualDurationSeconds` where available;
- for separate TTS, if exact matching is impossible, prefer small speed adjustment or short visual hold over cutting narration;
- for native video audio, changing spoken script after generation requires video regeneration because the speech is part of the generated video asset;
- show a timing warning when video total duration differs from voiceover/native speech duration beyond the accepted tolerance.

Recommended tolerance:

- target mismatch <= 0.5 seconds for short clips;
- target mismatch <= 3% of total duration for longer clips.

### 7.9 Optional Advanced Reference Repair

Users may repair/regenerate reference imagery per shot when needed. Repair should not change overlay text or voiceover unless the user explicitly edits them.

## 9. Handoff Contracts

### 9.1 Storyboard Review Handoff

Storyboard Review is the first-class output target.

```ts
type ArticleStoryboardVideoHandoff = {
  source: "presentation_builder_article_video";
  sourceDraftId?: string;
  title: string;
  locale: string;
  canvasRatio: SlideCanvasRatio;
  modelSelection: ArticleStoryboardModelSelection;
  timing: ArticleStoryboardAudioFirstTiming;
  shots: ArticleStoryboardVideoShotPlan[];
};
```

Handoff must:

- preserve page order;
- preserve selected video model, audio strategy, voice mode, and, when separate TTS is used, voice model plus speaker voice ID config;
- preserve selected voice mode and per-speaker voice IDs when applicable;
- preserve the selected TTS render strategy so Storyboard Review knows whether separate audio is generated as one dialogue request or as merged segments;
- preserve audio-first timing targets;
- create one Storyboard Review task per page by default;
- attach video prompt and overlay metadata to each task;
- attach character reference images to each task when available;
- attach selected 1-5 reference images to each task;
- attach storytelling voice script, speaker mapping, and either native-video-audio prompt metadata or separate voiceover segment/audio metadata to each task;
- for segment-based providers such as UVoice, attach enough segment ordering metadata to rebuild/merge the companion audio sequence deterministically;
- keep text overlay editable;
- store lineage from downstream task back to source page;
- use idempotency or duplicate detection so retry does not silently create duplicate projects.

### 9.2 Video Editor / Final Composite Handoff

After Storyboard Review generates videos, downstream video composition should use:

- `V1`: generated video shot;
- `T1`: CSS/HTML text overlay layer;
- `A1`: generated voiceover/audio track when separate TTS audio is used;
- optional reference/static image only as fallback.

Text overlay and voiceover timing should follow the shot duration unless the user edits them.

For audio:

- native video audio lives inside `V1`; the generated video clip audio should remain enabled unless the user explicitly mutes/replaces it;
- ElevenLabs provider-native dialogue TTS output may arrive as one separate audio asset for the whole dialogue or shot;
- UVoice dialogue output should arrive as multiple generated audio assets, one per script turn or contiguous speaker group;
- Storyboard Review should either merge UVoice segments into one compound companion audio asset or place them sequentially on the audio timeline using `sequenceIndex`, `startTimeSeconds`, and measured durations;
- separate TTS final render should treat the result as one coherent `A1` voiceover track even when it is internally made of multiple clips;
- native video audio final render should not add duplicate `A1` narration unless the user explicitly switches to separate voiceover.

### 9.3 Presentation Note Relationship

Saving to Presentation Note remains optional and secondary.

If saved, each Slide Note may store:

- original page text;
- narration text;
- video shot prompt;
- overlay text/style;
- Storyboard Review task ID.

Presentation Note should not become the canonical video state. Storyboard Review owns video review state.

## 14. Failure Modes And Mitigations

### 14.1 Existing Presentation Flow Regresses

Mitigation:

- feature is opt-in and feature-flagged;
- existing output modes ignore article-video state;
- old draft normalization defaults to current behavior;
- regression tests cover existing Presentation output.

### 14.2 Text Gets Baked Into Video

Mitigation:

- prompts explicitly tell providers not to generate captions/subtitles/text;
- overlay is represented as CSS metadata;
- overlay preview is rendered separately from video;
- final composite uses separate video and text tracks.

### 14.3 Shot Does Not Match Article Meaning

Mitigation:

- page text and narration are included in shot planning;
- user can edit prompt in Storyboard Review;
- Storyboard Review repair/regenerate flow remains available;
- user can repair/regenerate the 3x3 reference candidate sheet and reselect references when the visual direction is wrong.
- character reference images can be reused during repair so repaired candidates preserve intended character identity.

### 14.4 Cost Surprise

Mitigation:

- preview shows shot count, reference candidate count, selected reference count, estimated duration, audio strategy, and audio estimate;
- credit estimate separates reference generation, Seedance/video generation, native video audio, separate TTS, audio merge, and render where available;
- video generation remains explicit in Storyboard Review;
- reference repair is optional and feature-flagged.

### 14.5 Duplicate Storyboard Review Projects

Mitigation:

- include source draft ID and source mode in downstream metadata;
- use idempotency key where target routers/services support it;
- detect existing downstream records from the same source and offer to open existing.

### 14.6 User Confuses Prompt, Overlay, And Voiceover

Mitigation:

- preview and Storyboard Review UI use separate labels and fields;
- overlay editor placeholder says `On-screen text for this shot`;
- prompt editor explicitly says it controls visual video generation;
- prompt-like overlay text triggers the existing warning pattern;
- browser tests cover the copy and field separation.

### 14.7 Overlay Text Overflows Or Blocks Important Video Content

Mitigation:

- ship only safe presets in MVP, such as lower third and center title;
- keep max recommended character count per preset;
- show safe-area preview for selected ratio;
- warn before handoff when text exceeds the preset recommendation;
- keep overlay editable after video generation.

### 14.8 Video Prompt Audio Policy Mismatch

Mitigation:

- use `seedance-multishot-review` silent-video rules when `audioStrategy = "separate_tts_voiceover"` or `silent`;
- add prompt preflight that rejects voiceover/dialogue/lip-sync instructions inside video prompts unless `audioStrategy = "native_video_audio"`;
- when `audioStrategy = "native_video_audio"`, preflight must verify the selected video model supports native audio and the requested spoken language before allowing speech lines;
- keep voiceover script segments in `ArticleStoryboardVoiceoverPlan`;
- browser/UI copy explains whether speech is generated inside the video or as separate voiceover.

### 14.9 Voiceover And Video Timing Drift

Mitigation:

- store per-shot `durationSeconds` and voiceover script segments together;
- store per-segment speaker IDs and estimated/actual durations;
- prefer Uvoice premium generation before final render when separate TTS voiceover is enabled;
- Storyboard Review render uses generated separate-audio duration when available or native-video-audio duration when speech is baked into `V1`;
- final composite keeps separate TTS audio on `A1`, native video audio inside `V1`, and overlay on `T1`.

### 14.10 Model Config Drift Between Builder And Storyboard Review

Mitigation:

- persist `ArticleStoryboardModelSelection` in the created Storyboard Review review data;
- map selected video model into existing Storyboard Review video option state and task model fields;
- persist audio strategy and native video audio capability metadata;
- add persisted voice model and per-speaker voice ID config because current Storyboard Review audio state is companion-audio-oriented;
- mark only the affected media stale when a model changes: video model/audio strategy affects video prompts/outputs, voice model/voice ID/speaker mode affects separate voiceover script/audio.

### 14.11 Storytelling Script Adds Unsupported Claims

Mitigation:

- `article-storytelling-voiceover-script` must preserve article meaning and avoid unsupported claims;
- pass source page text and page IDs into the skill so each segment can be traced back to source content;
- include script warnings when a segment is too promotional, speculative, or not grounded in the article;
- keep the generated script editable before TTS or native video generation;
- tests verify the script skill output does not include video directions, CSS copy, or fabricated claims.

### 14.12 Missing Or Invalid Voice ID

Mitigation:

- Builder preview blocks handoff when separate TTS is selected and any required speaker lacks a voice ID;
- UVoice `voiceID` is stored in speaker metadata and sent back to the provider during TTS generation;
- Storyboard Review displays missing voice ID as a recoverable configuration error, not as a failed video task;
- changing a voice ID marks only affected TTS audio stale.

### 14.13 Dialogue Provider Capability Mismatch

Mitigation:

- resolve `ttsRenderStrategy` from the selected voice model capability before preview/handoff;
- show clear UI copy when a provider cannot generate multi-speaker dialogue in one request;
- for ElevenLabs dialogue-capable TTS models, keep the dialogue as one structured provider-native request when possible;
- for UVoice, generate each speaker turn or contiguous speaker group separately using its own `voiceID`, then merge or sequence the audio clips;
- keep segment ordering deterministic with `sequenceIndex` and measured durations so retries do not reorder dialogue;
- credit estimates must account for multiple UVoice segment requests instead of assuming a single dialogue call.

### 14.14 Native Video Audio Capability Mismatch

Mitigation:

- resolve native video audio capability from the selected video model before preview/handoff;
- block `native_video_audio` when the model does not support native audio or Thai speech;
- for Seedance, only allow Thai speech prompts on versions/configs explicitly marked as Thai-native-audio capable;
- for Veo 3.1 or omni-style models, allow Thai speech prompts only when capability metadata confirms support;
- if native audio is unsupported, offer a one-click switch to `separate_tts_voiceover` while preserving the storytelling script;
- changing from native video audio to separate TTS marks video prompt/generated video stale because the prompt audio policy changes.

### 14.15 Character Reference Drift

Mitigation:

- store character reference images separately from generated 3x3 candidate frames;
- pass character reference images into both 3x3 candidate generation and video prompt generation when available;
- mark the 3x3 candidate sheet and video prompt stale when character reference images are added, removed, or changed;
- preserve previous selected references until the user confirms regenerated candidates;
- Storyboard Review should display character references separately from selected scene/reference frames so users understand which images lock identity.

## 18. Open Questions

1. Should default shot duration be 5 seconds, inherited from slide duration, or estimated from narration length?
2. Which overlay presets should ship first: lower third, center title, top caption, side panel?
3. Should overlay style inherit tenant/brand theme when available?
4. Should Storyboard Review show overlay editing in the first MVP or only preserve metadata for downstream composite?
5. Should reference frame selection be automatic first, or require user confirmation before Seedance prompt generation?
6. Should project creation immediately open Storyboard Review, or show a success screen with both `Open Storyboard Review` and `Back to Presentation Builder`?
7. What fallback TTS model should be used when Uvoice premium is unavailable?
8. Should audio-first timing generate TTS before Storyboard Review project creation, or create the project first and align timing inside Storyboard Review?
9. Should the default voice mode be single narrator or should the UI suggest two-speaker dialogue for some article types?
10. Should two-speaker dialogue require two different voice IDs, or only two speaker slots that may intentionally share a voice?
11. Should the default audio strategy be separate TTS voiceover or native video audio when the selected model supports Thai speech?

Recommended MVP answers:

1. Use 5 seconds per page by default, stretchable to narration length when audio exists.
2. Ship lower third and center title first.
3. Use tenant/brand theme when available, otherwise use safe default presets.
4. Show basic overlay preview/edit in Storyboard Review if the existing overlay surface is ready; otherwise preserve metadata and enable downstream composite first.

6. Open Storyboard Review immediately, with a toast/backlink to return to Presentation Builder.

9. Default to single narrator for simplicity, then let users switch to two-speaker dialogue in preview.
10. Require two distinct voice IDs by default to avoid confusing dialogue output; allow same-voice reuse later only as an explicit advanced option.
11. Default to separate TTS voiceover for predictable editing and timing, but show native video audio as an available option when the selected video model explicitly supports Thai speech.
