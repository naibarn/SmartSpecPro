## Implemented interactions

- Open/switch/close/reorder up to four separate Harness instance tabs; counts, last synthetic event, freshness, and unavailable state are shown. Tab close only hides the view.
- Codex has three executions, Claude two, Hermes two, plus an unavailable Harness fixture. Execution tabs remain scoped to their selected Harness and expose current/historical Attempts.
- Tabs, 2-, 3-, and 4-panel split modes preserve per-Harness execution context. At a 1440px viewport a four-panel selection renders 2×2 because the available work area is narrower; mobile renders only the selected panel. Each panel keeps its own Harness and execution picker.
- “Open in Task Control” carries the selected fixture execution and Attempt into the isolated project workbench. “Back to Mission Control” restores the Harness/split selection. These URL values are explicitly fixture-only and are not a canonical API contract.
- Readiness details separate discovery, connectivity, trust/enrollment, entitlement, workspace authorization, and dispatch readiness. Every record and event remains synthetic.
- Browser state restore validates execution-to-Harness and Attempt-to-Job fixture relationships. No fetch/dispatch call is made on tab switches or view navigation.
