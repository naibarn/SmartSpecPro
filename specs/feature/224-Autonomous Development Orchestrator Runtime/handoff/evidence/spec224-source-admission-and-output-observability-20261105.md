# SPEC-224 source admission recovery and execution output

- **Integrated source:** `4d3a468f44d596ca67d9b6c286fa1f31b3f131a2` (`origin/main`).
- **Root causes:** Runner capability `snapshotRevision` advances as a report sequence even when the repository content is unchanged; the Start flow treated it like source identity. Separately, a true `EXECUTION_SOURCE_CHANGED` rejection could happen after the durable Goal and pending Worker Job were created, leaving an unclaimed stale job in the external admission slots. Task Control also lacked a direct way to inspect Harness output and the event timeline for the selected run.
- **Changes:** Source identity now uses Runner ID, workspace ID, Git SHA, and the full content fingerprint. Report-only revision changes no longer invalidate the binding or change Goal idempotency, while a true source change remains rejected and is rechecked before staging and before delegated execution. The server conditionally cancels only unclaimed source-changed jobs through the canonical Job Control cancellation transaction, and reclaims eligible stale jobs before admitting a new Goal. Runner-assigned or leased work is preserved. Spec packages whose source references are unavailable now show a package blocker instead of failing the whole preparation. Task Control offers a recovery route for the affected Goal, requires review and an explicit resubmission, and displays Harness output plus execution timeline in Developer mode.
