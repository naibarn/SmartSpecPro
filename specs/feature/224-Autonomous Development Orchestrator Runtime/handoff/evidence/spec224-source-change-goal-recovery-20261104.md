# SPEC-224 source-change Goal recovery

- **Root cause:** `EXECUTION_SOURCE_CHANGED` is a valid source-pinning rejection, but it was thrown after the Goal and deferred Worker Job had been persisted. The router let that error escape as an opaque mutation failure, and the UI had no flow-level recovery. Repeated submission could therefore keep targeting the same Goal pinned to the old source.
- **Server change:** The Goal admission path now records the source-change outcome on the durable run and returns `EXECUTION_SOURCE_CHANGED` as a blocked, recoverable admission state. It does not acquire an execution lease or dispatch the stale Goal.
- **UI change:** Task Control refreshes the same authorized Platform workspace, verifies the binding against the current Runner snapshot, and prepares a new plan. It unlocks a fresh Goal key only when the snapshot advanced; the user reviews the plan and clicks again. The browser never automatically resubmits. First Run Pilot keeps its one-Goal guard and reports the blocked run.

The router case verifies the stale Goal remains blocked and its admission evidence is persisted.
