## Findings and repair candidate

### Tenant ID and related migrations

`0000_fine_pretty_boy.sql` declares `tenants.id` and its referencing columns as integers. `0001_sad_marvel_apes.sql` changes the parent `tenants.id` to `varchar(36)` but did not originally coordinate the referencing columns/FKs, causing PostgreSQL to reject the type change. The catalog-driven candidate conversion now captures single-column tenant FKs and their definitions, drops them, casts child values through text, removes the old serial default, converts the parent, then restores the original FK definitions. It aborts on composite tenant FKs rather than guessing.

A fixture built from journaled `0000` was seeded with tenant ID `42` and references in `gallery_items`, `seo_metadata`, `tenant_pages`, and `users.currentTenantId`. Applying the candidate `0001` SQL directly through `psql` succeeded. The tenant identity remained `"42"`; each child became `varchar(36)` and each of the four FKs was present afterward. This proves preservation for this fixture only, not every historical tenant encoding or full migration path.

The candidate leaves `0019_unified_library_schema.sql` library tenant columns as integers because journaled `0020_library_tenant_id_varchar.sql` already performs the explicit data-preserving conversion for those tables. `0003` aligns `invoice_config.tenantId`; `0004` aligns `menu_config.tenant_id` to the tenant key type.

### Other fresh-replay defects exposed in order

Repeated disposable canonical `db:migrate` attempts exposed and repaired these concrete conflicts before the stopping boundary:

1. `0003` re-added enum value `agency` already introduced by `0002`.
2. `invoice_config.tenantId` and `menu_config.tenant_id` used integer columns against varchar tenant IDs.
3. `0009`/`0010` attempted duplicate `image_video_generation` enum additions.
4. `0013` recreated `reminder_priority`, and duplicate reminder columns conflicted with earlier journal entries.
5. The first guard implementation compared `name[]` to `text[]`; the candidate now casts enum labels explicitly.

These repairs allowed replay to advance to `0015`; they do not demonstrate that later migrations pass.

### Canonical chain policy boundary

At `0015_naive_franklin_richards.sql`, fresh replay fails because `workflow_templates` does not exist. The following journaled migration `0017_volatile_millenium_guard.sql` creates the legacy workflow runtime tables and related authority. `AGENTS.md` explicitly retires `/workflows` and the legacy custom workflow engine and prohibits restoring/developing it. Therefore D3.38 does not synthesize those tables, modify historical migration history to skip errors, or continue through 0017. The unjournaled `0028_workflow_additions.sql` also remains excluded. A new, owner-reviewed migration policy is required before this boundary can be resolved without violating repository instructions.
