## Implemented changes

1. `economicDurableService.ts` now provides durable `captureEconomicHold` through the existing transaction, hold, budget, journal, event, and reconciliation tables. It locks the hold and budget, binds a stable settlement idempotency key, posts a balanced journal atomically, and persists a same-transaction audit event. Duplicate identical settlement replays; conflicting key reuse is rejected. Unknown/failed provider outcomes retain the hold and create reconciliation evidence; no blind retry or second charge is performed.
2. Reserve and release now also persist actor/policy-bound economic audit events in the same transaction. `DurableReleaseInput` requires actor and policy provenance; the existing Spec 224 authorization revocation caller supplies it.
3. `economicLedgerService.ts` now resolves actual account rows before posting and rejects missing, cross-tenant, wrong-currency, or closed accounts. The journal lines’ caller-supplied tenant labels alone are no longer treated as proof of account ownership.
4. `ApprovalDBService.submit_decision` serializes a retry on the approval row and returns the existing response for the same actor and identical decision; a conflicting replay is rejected. `_is_user_admin` selects only `role`, avoiding optional legacy ORM columns absent from the certified fresh schema.
5. Added loopback/database-name-guarded test-only economic provisioning under `server/services/__tests__/helpers`. It inserts only disposable accounts/budget and delegates journal invariants to canonical `recordJournalEntry`; it does not update account balances or create production funding.
6. Added PostgreSQL integration coverage for economic settlement and ApprovalDBService recovery.

No schema/migration changes were required.
