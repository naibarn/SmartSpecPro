# Section 05: Dialogue Quality Rules v2 + Character Speech Profiles (F132D dialogue + F132F speech)

## Goal

Ship the deterministic + prompt-level dialogue quality rules from spec §7.1–§7.2 (mystery grounding, pressure-not-summary, clue budget, anchor-line cadence, read-aloud one-idea-per-line, spoken register) and the structured character speech-profile system from §7.3, without touching rendering/audio mixdown or the multi-pass QC *runner* itself (Section 06 owns pass orchestration; this section owns the deterministic checks/metrics, the `speechProfile` schema, its generation/consumption wiring, and the name-blind voice-distinctness check *definition*). **Post-audit correction (resolves the central ownership gap the completeness audit found)**: the §7.1 rule-TEXT content is authored by Section 01 directly, inside `shared/verticalDramaSeries/qualityCriteria.ts`'s "dialogue rules v2" string constant (Section 01's own plan already claims this file as the home for "the raw prompt-fragment text blocks for dialogue rules v2 (§7.1)") — this section does NOT author the rule text itself, and does not edit `qualityCriteria.ts`. This section's job re: §7.1 is: (a) supply Section 01 with the complete content requirements (below, so the fragment is not left incomplete), (b) build every deterministic check/metric that gives the rule text teeth, and (c) consume the rendered fragment (via `renderCriteriaVersionMarker()`) in the two skill prompts it touches. **Content requirements Section 01's dialogue-rules-v2 fragment must include (full §7.1, not a subset)**: mystery-grounding (max 1 poetic/mysterious key line per shot, UNLESS the scene contract's `storyFunction` explicitly requires ritual/dreamlike speech — this exemption clause must be present verbatim, not just the density cap); pressure-not-summary (a line carrying information must also carry emotion/fear/doubt/urgency/resistance/intention; never merely describe what the visual already shows); clue budget (≤1–2 new important names/objects/dates/lore terms per shot; every new clue gets minimal context — what it is, why it matters, what to remember); anchor lines (≥1 per 2–3 shots, simple/direct/speakable); read-aloud (one main idea per line); spoken register (Thai: natural particles สิ/นะ/ล่ะ/เหรอ where the speech profile allows, contractions/ellipsis, no written-essay connectives in casual speech, formality matched to speaker relationship, narration-like lines are a violation even if short and clear). This fragment must be rendered into ALL THREE targets spec §7 line 450 names: `vertical-drama-script-builder`, **deep-draft prompts** (`generateStoryBibleDeep`/`generateStoryBibleDeepPremium` — an earlier draft of this section only wired the script-builder and dialogue-audio-planner skills and left deep-draft prompt rendering unassigned; Section 02/04's deep-draft prompt work should embed the same fragment, or if that's out of scope for Phase 1, this must be an explicit backlog item, not a silent gap), and the Dialogue QC pass (Section 06's territory).

Feature flags gated: **F132D** `verticalDramaMultiPassQc` (dialogue-rule and density-metric parts only — the 6-pass runner is Section 06), **F132F** `verticalDramaCharacterProfiles` (speech-profile schema + generation + consumption + editing UI).

## Risk & rollback

- **Highest risk**: modifying `analyzeVerticalDramaLineSpeakability` — depended on by many existing, unrelated call sites (episode drafting, manual dialogue edits). Mitigation: the new behavior is strictly additive/opt-in (`checkOneIdeaPerLine` flag), and step 3 above mandates running the FULL pre-existing test suite before adding new cases, to catch any accidental default-behavior change immediately. (The equivalent risk for `extractCharacterDescription` is now Section 08's to manage, since that edit moved there per Finding 1 — this section's only surface touching that function is the pure, side-effect-free `renderVoiceCardBlock`.)
- **Rollback**: since every change is additive and flag-gated (F132D/F132F default `off`), disabling both flags reproduces current behavior exactly for every consumer except `seedCharactersFromDraft`, which is not a flag-checked function itself (it's a pure helper) — its new code path only activates when the new typed `data.speechProfile` field is actually present, which only happens once F132F-gated generation writes it. So flag-off is byte-identical without any code revert needed; a full revert of this section's diff is the fallback only if a regression is found in the always-on helper paths.
- **Voice-distinctness check cost risk**: an LLM-judge call per season/episode adds cost; mitigate by sampling N (small, e.g. 6–10) exchanges rather than every line, and letting Section 06 decide cadence (per-episode vs. per-season) since it owns pass scheduling/budget.

## Acceptance criteria

Maps to spec.md §16.3 (Dialogue) and relevant §16.4 (voice-profile) bullets:

- Anchor-line cadence ≥1 per 3 shots is a deterministic metric (`anchor_line_gap`) with a defined threshold; new-proper-noun budget (`new_proper_noun_count_per_shot`) is respected and cross-checked against `contract.newClueIds` when contracts are available; ungrounded abstract lines are flagged (`abstract_line_ungrounded_count`) — §16.3 bullet 1.
- Read-aloud violations — existing speakability violations PLUS the new one-idea-per-line check — are reported per line with a suggested fix, without altering default behavior for any caller that doesn't opt in — §16.3 bullet 2 (first half).
- Name-blind attribution of sampled exchanges is scored against a defined threshold; falling below it fires `voices_too_similar` naming the character pair and the profile axis to separate — §16.3 bullet 2 (second half).
- Every lead character carries a structured `speechProfile` (once F132F-gated generation runs) consumed by the script-builder skill as a visible voice card in prompt artifacts — §16.4 bullet 1.
- Thai dialogue register violations (written-essay connectives in casual speech) surface via the existing `unnatural_dialogue_language` finding, now with a deterministic co-signal alongside the LLM judgment — §16.4 bullet 4.
- Legacy character rows (no typed `speechProfile`/`personality`) continue to render prompts identically via `extractCharacterDescription`'s fallback path (Section 08's implementation, this section's `renderVoiceCardBlock` simply has nothing to render for such rows) — no regression to existing character-portrait generation.

## Open questions / assumptions

- Whether/how a genre preset's `charactersJson` will ever carry `speechProfile` data (so `seedCharactersFromDraft` has something structured to carry through) is unresolved — no preset-authoring section currently defines this. Assumption: implement the optional `presetCharacterProfiles` param defensively now; it will simply never be populated until/unless a preset-authoring change (out of this section's scope) starts emitting it.
- Exact NER-lite heuristic quality for `new_proper_noun_count_per_shot` (Thai has no capitalization signal, so proper-noun detection must lean on honorific prefixes like คุณ/นาย/นาง/นางสาว plus a stoplist of common nouns, or defer to `contract.newClueIds` as ground truth when present and use the heuristic only as a fallback estimate) — flagging as an implementation-time judgment call, not a blocking design gap.
- Whether the `checkOneIdeaPerLine` clause-splitting heuristic should be locale-aware (Thai has no explicit sentence-final punctuation in casual speech) needs a small calibration pass against real drafted episodes during implementation; ship with a conservative (high) threshold to avoid over-flagging, tunable later.
- Exact prefill-suggestion UX in `VerticalDramaCharacterVoiceCastingCard.tsx` (button label, placement) is a UI-detail decision left to the implementer, constrained only by the "suggestion only, never auto-applied" hard rule from spec §7.3.
