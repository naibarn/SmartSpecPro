# Section 06: Multi-Pass QC & Scorecard v3 (F132D QC parts + F132H)

## Goal

Turn `critiqueSeasonDrafts` (`apps/web/server/services/verticalDramaStoryBible.ts:5888`) from one monolithic LLM critique call into a **six-pass runner** (Structure, Character, Evidence, Threat, Dialogue, Continuity), each pass = existing-style deterministic checks (mirroring `analyzeSeasonDramaturgy`, `:5132`) merged with one small, focused LLM call. Register the new finding kinds spec §8.1 lists onto `VD_SEASON_CRITIQUE_FINDING_KINDS` (`:5027`) and their Thai/English labels onto `verticalDramaCopy.ts`. Implement the Continuity Pass's causal-chain/hook-to-opening/knowledge-residue checks (F132H, spec §8.2). Ship scorecard v3 (`contract_version: 3`) on `qualityReviewScorecardSchema` (`verticalDramaEpisodeQualityReview.ts:124`) and align `VD_PREMIUM_DRAFT_SCORE_DIMENSIONS` (`verticalDramaStoryBible.ts:306`) to the same four new dimensions (`clarity`, `character_consistency`, `evidence_payoff`, `threat_escalation`), fixing the dimension-vocabulary drift noted in gap G24. Attach a `minor|moderate|major|structural` severity to every finding/issue. All of this must be **byte-identical to today** when F132D is off or `qualityPolicy.multiPass` is false.

## Risk & rollback

- **Primary risk**: multi-pass fan-out means 6 LLM calls instead of 1 per critique run — cost/latency increase must be intentional (gated behind F132D + `qualityPolicy.multiPass`, never silently on).
- **Flag-off contract**: with F132D off OR `qualityPolicy.multiPass !== true`, `critiqueSeasonDrafts` must produce the EXACT single LLM call, same prompt text, same schema, same credit math as before this section existed — verified by the byte-identical snapshot test (test-first plan item 1). Any diff here is a blocking regression, not a nit.
- **Regression guard risk**: `seasonCritiqueRevisionIntroducesNewFinding` is the safety net for `applySeasonCritique`'s auto-apply UX (Section 07 depends on this holding). Expanding `analyzeSeasonDramaturgy`'s output surface (16 new kinds) means the guard's kind-set comparison now has far more ways to fire — this is DESIRED (catches more regressions) but must be tested per new kind, not assumed to "just work" because the comparison logic itself didn't change.
- **Rollback**: reverting is a flag flip (F132D off) with zero data migration — jsonb additions are inert when unread. If a specific new deterministic check in `analyzeSeasonDramaturgy` produces false positives in production, it can be individually disabled (wrap in its own no-op-if-absent guard) without touching the other five passes.
- **Job kind unchanged**: `verticalDramaStoryJobs.ts`'s `season_critique` job kind, its Redis single-slot-per-series semantics, and the polling UI are NOT touched by this section — the multi-pass runner executes entirely inside the existing job body.

## Acceptance criteria

Maps to spec §16.2 (bullets 1-3, 5):
- "Every episode has want/obstacle/choice/cost derivable from contracts+beats; threat or consequence increases every episode (ladder check)" — covered by Structure + Threat passes' deterministic checks.
- "Major characters activated before midpoint or a Character Pass finding fires; evidence introduced is tracked to use/payoff or flagged" — Character Pass (`character_agency_zero_decisions` + Section 03's activation ledger) + Evidence Pass (`evidence_orphaned`/`evidence_no_resistance`/`evidence_no_payoff`).
- "Hook of episode N-1 answered in first 1-2 shots of N, or `hook_not_answered_in_opening` fires; removing any episode breaks the causal chain (`episode_replaceable` fires otherwise)" — Continuity Pass, F132H, directly implemented in this section.
- "Scorecard v3 shows per-dimension weakness per episode; a revision plan entry always names a scope" — scorecard v3 implemented here; the revision-plan scope naming is Section 07's job, fed by this section's severity-tagged findings.
- "Ledgers and story state update after every revision; re-score touches only revised episodes" — the re-score/reconcile mechanics are Section 07's (via Section 03's `reconcileLedgers`), but this section's per-pass output (small, targeted findings) is what makes a narrow re-score possible instead of forcing a full re-critique.

Deterministic findings get an explicit severity assigned by the check that produces them, per this fixed table (this section owns the table; Section 07/09 only consume the resulting value, no further decision needed there): `structural` → `episode_replaceable`, `hook_not_answered_in_opening` (breaks the causal chain — always structural); `major` → `evidence_orphaned`, `evidence_no_payoff`, `threat_not_escalating`, `decision_without_consequence`, `thread_stalled`, `knowledge_continuity_break`, `cast_visually_similar` (identity confusion is a structural-adjacent but character-scoped concern, kept major not structural since it never needs cross-episode scope escalation); `moderate` → `evidence_no_resistance`, `antagonist_idle`, `clue_overload`, `missing_anchor_line`, `voices_too_similar`, `emotional_residue_reset`, `premise_drifted`; `minor` → none by default (reserved for LLM-assigned downgrades). This table is a starting default, not a hard constant — an LLM pass MAY override a deterministic check's default severity when its qualitative judgment disagrees (e.g. a `clue_overload` in a pivotal reveal episode might warrant `major`), but the deterministic layer always supplies a non-null default so Section 07's scope-escalation logic never sees an unassigned severity.
