# Section 09: Character Image QC & Cast-Level Contrast (F132G image QC + §10.8)

## Goal
Add the deterministic + LLM-text scorecard that judges a character image **prompt** (never the rendered pixels — vision-based scoring stays explicitly deferred per spec.md §1.2/§10.6 and 131 §9.3) against the character's persisted Visual Bible (Section 08) and role-tier guardrails, gate the anchor-portrait render button on it (soft-block + override), persist a durable Visual Consistency Ledger entry on every character-asset generate/import/approval, and implement the pairwise cast-contrast comparator that flags two same-tier characters whose visual bibles are too similar (`cast_visually_similar`, spec §10.8). This section does **not** touch bible persistence, prompt block reordering, expression-set generation, or start-frame contract binding — those are Section 08 (§10.2–§10.4, §10.7). It does not touch voice distinctness (`voices_too_similar`) — that is Section 05's `verticalDramaVoiceDistinctness.ts`, referenced here only as the "cast contrast" story's other half.

## Risk & rollback
- **False-positive image-QC gate blocking legitimate renders**: the LLM-text judge scoring a well-formed prompt below threshold on a subjective dimension (e.g. `cinematic_quality`) would block a render the user actually wants. Mitigation: the gate is **soft** by design (`overrideImageQcGate`) — never a hard block; only the 4 required dims (+ conditional `audience_appeal`) can trigger it, not all 9; the override is one explicit boolean away and is itself audit-logged via the `linkAsset`/ledger write (`verdict` will show `revise` on an overridden low-scoring asset, so the override is visible in the ledger even when used). Rollback: flip F132G off — `previewCharacterPrompt`/`generateCharacterImage` skip the QC call and gate entirely, byte-identical to pre-section behavior.
- **False-positive cast-contrast flagging distinct-enough characters as too similar**: the deterministic overlap heuristic (word/keyword overlap on free-text `signatureVisualCues`/`colorPalette`) is a blunt instrument and can over-trigger on characters that share a *setting* (e.g. two office-drama leads both described with "tailored blazer, muted palette") without actually being visually confusable. Mitigation: `cast_visually_similar` is a **suggestion**, never an auto-applied change (spec §10.8: "surface as suggestions requiring user approval") — the finding always requires explicit user action via Section 06's Character Pass → revision-plan flow (§9), never a silent auto-revise; the similarity threshold is a documented, tunable constant (not hardcoded inline) so it can be relaxed without a code change if false positives prove common in practice.
- **Ledger write ordering bugs**: since `appendConsistencyLedgerEntry` and the asset-lifecycle write (`linkAsset`/`transition`) touch two different tables without a shared transaction in the current codebase's patterns (neither `verticalDramaCharacterStock.ts` nor `verticalDramaCharacters.ts` currently wraps multi-table writes in an explicit DB transaction), a mid-request failure could leave an asset linked without a matching ledger entry, or vice versa. Mitigation: treat the ledger write as best-effort/non-blocking for the asset-lifecycle outcome — if `appendConsistencyLedgerEntry` throws, log and continue rather than rolling back or failing the user-visible `linkAsset`/`transition` call (a missing ledger row is a recoverable audit gap, not a data-integrity problem, and is strictly better than corrupting the asset's own lifecycle state over a secondary write).
- **Regression tests to run before merging**: full `verticalDramaCharacterStock.test.ts` suite (idempotent-link dedupe, state-machine transitions, `pickBestCharacterSheetAsset` ordering — all untouched by this section) must pass unmodified; full `verticalDramaCharacters` router test suite (`previewCharacterPrompt`/`generateCharacterImage` existing assertions, credit-charge sequencing) must pass with only the new assertions added, no existing assertion altered.
- **Flag-off rollback**: with F132G off, `previewCharacterPrompt` returns no `imageQc` key (or a no-op passthrough), `generateCharacterImage` never evaluates the gate (`overrideImageQcGate` input is accepted but ignored), `linkAsset`/`transition` never call the ledger-append/anchor-update helpers, and `findCastVisuallySimilarPairs` is never invoked by Section 06's pass. This reverts to current production behavior without a code revert.

## Open questions / assumptions
- **Open question — audience_appeal tier scope mismatch in the spec itself**: spec.md §10.6 says the anchor-portrait gate requires `audience_appeal ≥8` "for adult lead tiers" (only), while §10.2 says `eraStyling`/`audienceAppealNotes` are populated "for adult lead/villain tiers" (both). Flag for confirmation with the spec owner; if villains should NOT be gated, `evaluateAnchorPortraitGate`'s tier-to-required-dims mapping is a single lookup table change, not a structural one.

- **Open question — ledger write transactionality**: whether `appendConsistencyLedgerEntry`'s best-effort/non-blocking failure mode (Risk & rollback, third bullet) is acceptable, or whether the project would prefer wrapping `linkAsset`/`transition` + ledger-append in an explicit DB transaction (a larger, cross-cutting change to both this section's and Section 08's/the stock service's write paths) — deferred to implementation-time decision since it affects multiple files beyond this section's scope.
