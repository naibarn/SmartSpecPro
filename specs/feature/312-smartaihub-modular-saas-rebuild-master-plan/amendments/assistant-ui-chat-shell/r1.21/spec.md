# SPEC-312 R1.21 — Chat outputs and control projections

**Status:** PARTIAL · **Date:** 2026-11-15 · **Scope:** additive Core, Chat, Task Control and Mission Control contracts.

## Normative outcomes

1. A successfully completed canonical Chat Job MAY persist its actual assistant response as a private output artifact. The producer MUST use the completed provider result, correlate it to the existing conversation, workspace, environment tenant, user, Job and attempt, and register metadata atomically with canonical job/credit completion. It MUST NOT create artifacts from input attachments or test fixtures.
2. Output bytes MUST use the dedicated private `CHAT_OUTPUTS` R2 binding. The versioned descriptor records media type, byte length, SHA-256, expiration and canonical ownership references. Registration is idempotent and rejects conflicting metadata. The authorized resolver validates DB ownership and object length/hash before returning bytes. Private object references and credentials MUST NOT be exposed to clients.
3. Artifact list, metadata and content reads MUST enforce the authenticated Core identity, environment tenant, workspace and conversation scope. Content is bounded to 128 KiB for the current Chat viewer, served private/no-store with nosniff and sandbox protections. Expired objects are removed by the dev cleanup task. Unavailable or unsupported content MUST fail safely and MUST NOT be embedded as privileged executable content.
4. Core advertises `artifacts=true` only when the actual producer, private storage binding, registration, authorized retrieval and Chat viewer are configured together. This capability is development-only in this amendment.
5. SPEC-277 remains the Task Control read-model owner. Its additive `smartaihub.task-control-projection.v1` DTO is read-only and tenant scoped. Canonical Job identity is shared with Chat; Task identity aliases that Job only for this projection. Unsupported attempt, event cursor and agent/harness/executor/machine identities remain null; artifact references are empty unless the owning read model supplies authorized IDs. The Modular Core Chat adapter reads only the same canonical Chat `worker_jobs` and registered artifacts, with workspace/user authorization. It does not dispatch work or create task state.
6. SPEC-294 remains the Mission Control projection owner. `smartaihub.mission-control-projection.v1` is an additive nullable contract only. The current implementation does not provide tenant Mission entities or a tenant-scoped Mission API: `modularSaasProjectMissionControl` serves the platform-engineering project/spec-ingestion/run catalog. Do not adapt that catalog into tenant Chat navigation or fabricate Mission/Run IDs. Runtime Mission adapter/navigation remain blocked on an authoritative tenant-scoped Mission identity, source projection, authorization binding and canonical Chat/Job relationship.
7. Existing durable Chat events, replay, reconnect, polling and `worker_jobs`/outbox authority remain unchanged. Inspector reads MUST NOT dispatch or duplicate Jobs. Optional identity joins are populated only from verified canonical sources.
