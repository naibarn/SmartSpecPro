# SPEC-312 R1.17 — attachment upload proxy body-stream fix

- **Date:** 2026-11-14 (Asia/Bangkok)
- **Source:** `smartaihub-platform/main@10f83cd1ee5cb8f7305b45bfbc88959614b583ec`; both task commits are pushed and local `main` equals fetched `origin/main`.
- **Reported failure:** signed-in Chat upload of `wan22.png` (2.6 MB PNG) returned the generic send error and retained the prompt/attachment.
- **Root-cause evidence:** the Chat Worker journal recorded `POST /api/chat/v1/attachments 400` at 2026-11-14 16:47:53 +07:00. The corresponding Core service journal slice contained no attachment POST. In source, the Chat proxy returned this 400 only when its bounded body reader threw; immediately before that, `proxyWorkspaceRequest` constructed a second `Request` from the incoming request solely to inject the resolved tenant header, introducing an unnecessary streamed-body clone/tee before the bounded read. This identifies the failing boundary; the exact runtime stream exception was not logged and is not claimed.
- **Fix:** the route passes the original `context.req.raw` to `proxyCoreChatRequest` and passes the already-authorized tenant ID separately. The proxy adds that tenant ID to Core-bound headers and reads the original bounded body once. A safe diagnostic logs only the allowlisted route path and error class if bounded body reading fails; it excludes the exception message, request body, filename, cookie and credentials. Upload size, authentication, workspace binding, private R2 storage and the queued provider/credit flow are unchanged.
