# Deep Frontend Security Audit — Round 2: Agency Swarm
**Date:** 2026-03-23
**Auditor:** CMD-6 Frontend Security Auditor
**Scope:** AgencyBuilder.tsx, NodePropertyPanel.tsx, AgencyChatStream.tsx, AutoCreateAgencyModal.tsx, CustomToolCreator.tsx, ToolPicker.tsx, JsonSchemaEditor.tsx, useAgencyHistory.ts, useAgencyStream.ts, TextContentPreviewContent.tsx
**Branch:** codex/feature-044-multimodal-chat-memory

---

## Summary

Previous Round 1 fixes (DOMPurify on markdown path, isOwned gate on Edit/Delete, 14 node types) are correctly applied. The `dangerouslySetInnerHTML` in `TextContentPreviewContent.tsx` uses DOMPurify with an allowlist for both HTML and markdown paths — clean.

Round 2 reveals **6 new findings**, ranging from HIGH to LOW. No new CRITICAL XSS was found in the six audit focus areas. The most significant gaps are: (1) no server-side enforcement of node count allows resource exhaustion via the API; (2) `Last-Event-ID` header value from SSE events is written into an outbound request header without sanitization; (3) the drag-drop surface accepts arbitrary JSON from `dataTransfer` and passes it directly to node construction; (4) `confirm()` for custom tool deletion is client-only with no server-side "in-use" check; (5) `__proto__` key in raw JSON Schema editor produces a polluted object that gets persisted to the database; (6) `errorMsg` from a failed Celery task is reflected directly into the DOM.

## Findings

| ID   | Severity | File:Line | Anti-Pattern | Description | Recommended Fix |
|------|----------|-----------|--------------|-------------|-----------------|
| FE-R2-01 | HIGH | `apps/web/server/routers/agency.ts:1148` | No node count cap | `saveBuilder` Zod schema declares `.min(1).max(20)` at line 1420, but the `agents` array itself has no `.max()` constraint before the per-agent `.superRefine()`. The `.max(20)` at 1420 is on `communicationFlows`, not `agents`. An attacker can POST a crafted tRPC call with 1000+ agent objects, each with 50 KB instructions (max), causing a large DB transaction and potential OOM in the Node process. | Add `.max(50)` (or appropriate limit) to the `agents` z.array() at line 1148. Mirror the cap in the client `addNodeFromTemplate` handler. |
| FE-R2-02 | HIGH | `apps/web/client/src/hooks/useAgencyStream.ts:295-296` | Unsanitized `Last-Event-ID` in outbound request header | `lastEventIdRef.current` is populated directly from `evt.id` (line 347) which comes from raw SSE frame data controlled by the server. If the SSE endpoint is ever proxied through a compromised upstream, or if a MITM injects a crafted `id:` line, the value is written verbatim into `headers["Last-Event-ID"]`. HTTP header injection is possible if the value contains `\r\n`. The fetch API in modern browsers will throw on CRLF in headers, but the lack of validation makes the intent fragile and degrades to a risk when running in non-browser contexts (e.g., Tauri's native HTTP stack). | Sanitize: `headers["Last-Event-ID"] = lastEventIdRef.current.replace(/[\r\n]/g, "").slice(0, 128)` before setting. |
| FE-R2-03 | MEDIUM | `apps/web/client/src/pages/AgencyBuilder.tsx:519-532` | Unsanitized drag-drop `templateData` feeds node construction | `onDrop` reads `event.dataTransfer.getData("application/templateData")`, JSON-parses it, and passes the result to `addNodeFromTemplate` without validation. While drag data originates from `AgencySidebar` (trusted), `dataTransfer` is also writable by any script in the same page that simulates a drag event. A crafted `nodeType` value (e.g., `"__proto__"`) or an oversized `name`/`instructions` field could slip through. The `addNodeFromTemplate` function accepts `templateData.nodeType` directly into `AgencyNodeData.nodeType` with only a TypeScript cast (`as AgencyNodeData["nodeType"]`), not a runtime allowlist check. | Validate the parsed template against an allowlist: check `nodeType` is in the 14 known types, truncate `name`/`description` to their server-side max lengths, and discard unknown keys. |
| FE-R2-04 | MEDIUM | `apps/web/client/src/components/agency/JsonSchemaEditor.tsx:149-157` | `__proto__` key in raw JSON persists to DB | In raw mode, `handleRawChange` calls `JSON.parse(text)` and immediately calls `onChange(parsed)`. `JSON.parse('{"__proto__":{"isAdmin":true}}')` returns `{}` in V8 (prototype is not polluted by JSON.parse itself), but `propertiesToSchema` and `schemaToProperties` iterate `Object.entries(properties)`, which skips prototype-inherited keys. The real risk is narrower but still present: a property named `__proto__` or `constructor` can be saved as a valid JSON key in the schema blob and then stored in the `inputSchema`/`outputSchema` JSONB column on the server. When the server later calls `ajv.compile(tool.inputSchema)` (agency.ts:3521), AJV processes arbitrary nested JSON including keys that could exploit AJV schema injection (e.g., `$ref` pointing to external URIs, `if`/`then`/`else` recursion). | In `handleRawChange`, after parsing, strip any property named `__proto__`, `constructor`, or `__defineGetter__` from `parsed.properties`. Disable AJV external `$ref` resolution on the server (set `ajv.opts.loadSchema = undefined`, use `{ strict: false, allowUnionTypes: true }` and no URI resolver). |
| FE-R2-05 | MEDIUM | `apps/web/client/src/components/agency/AutoCreateAgencyModal.tsx:424` | LLM `errorMsg` rendered without length cap | `errorMsg` is populated from `status.error` (line 152), which is the raw error string returned by the Celery task. This string is rendered in JSX as `{errorMsg}` (line 424), so React escapes it and XSS is not directly possible. However, there is no length cap: a server returning a multi-megabyte error string (e.g., from a runaway prompt) will render it all in the DOM, causing layout thrash and potential tab freeze. Additionally `statusMessage` (line 348) is rendered without a cap. | Truncate both fields: `setErrorMsg((status.error ?? "Agency creation failed").slice(0, 500))` and `setStatusMessage((status.message ?? "").slice(0, 200))`. |
| FE-R2-06 | LOW | `apps/web/client/src/components/agency/ToolPicker.tsx:272` | `confirm()` deletion has no server-side "in-use" guard | Delete is gated on `isOwned && CUSTOM_TOOL_TYPES.has(toolType)` which is server-verified (the `isOwned: true` flag is set only for tenant-owned db rows). The `confirm()` dialog is client-side only. No check is made whether the tool is currently assigned to any agent before deletion. Deleting a tool that is actively assigned silently orphans `agencyAgentTools` rows (toolId references a deleted row). The `deleteCustomTool` server mutation should either reject if the tool is in use, or cascade-clear the assignments. | Add a server-side check in `deleteCustomTool`: if `agencyAgentTools` has rows with this `toolId`, return a 409 with the count of affected agents, and surface that in the UI ("Tool is used by 3 agents — remove it from all agents first"). |

## Notes on Areas That Passed

- **AgencyChatStream.tsx — SSE rendering:** `text_delta` tokens accumulate into `streamingMsgRef.current` (a plain string) and are passed to `SafeMarkdown` which uses `react-markdown` + DOMPurify. No raw HTML injection. `agent_switch` names are rendered inside a `<Badge>` as `{e.agentName}` (JSX text node — React-escaped). `guardrailEvents` name/action fields are similarly escaped. **Pass.**
- **AutoCreateAgencyModal.tsx — `guide` field:** Rendered at line 443 as `{guide.slice(0, 200)}...` inside a `<p>` tag — JSX text, not HTML. **Pass.**
- **AutoCreateAgencyModal.tsx — `q.question` from LLM:** Rendered in a `<Label>` JSX text node. **Pass.**
- **NodePropertyPanel.tsx — ErrorHandlerForm:** `watchedNodeIds` is built exclusively from `siblingNodes` IDs that originate from the local React state (already-validated nodes), not from raw user input. Checkboxes are controlled. **Pass.** The JSONPath and Mustache template inputs are plain `<Input>` / `<Textarea>` components storing values in React state — not rendered as HTML anywhere in the panel. **Pass.**
- **useAgencyHistory.ts — undo/redo:** The snapshot stores only structural fields (`nodeType`, `name`, `description`, `model`, `nodeConfig`). Restoring a snapshot calls `setNodes`/`setEdges` with typed data; no `innerHTML` or `eval` is involved. The 40-entry cap limits memory. A corrupted snapshot can only render wrong names/positions — no script execution path. **Pass.**
- **AgencyBuilder.tsx — `agencyData` hydration:** Server-returned strings (`agent.name`, `agent.description`, etc.) are placed into React state and rendered via JSX text nodes or controlled inputs — not via `innerHTML`. **Pass.**
- **ToolPicker.tsx — `isOwned` forge:** `isOwned` is set server-side in `listTools` (agency.ts:741) only for rows that belong to the authenticated user's tenantId. The client reads it from the tRPC response but cannot forge it to affect server behavior — the `deleteCustomTool` and `updateCustomTool` mutations re-verify ownership on the server. The Edit/Delete buttons are cosmetic-only; hiding them for non-owned tools is defense-in-depth but not the enforcement boundary. **Pass** (the actual enforcement is server-side).
- **TextContentPreviewContent.tsx — `dangerouslySetInnerHTML`:** Both the markdown and HTML paths pass through `DOMPurify.sanitize()` with explicit `ALLOWED_TAGS`/`ALLOWED_ATTR` allowlists and `ALLOWED_URI_REGEXP` blocking `javascript:`. **Pass.**

## Verification Steps for Fixes

1. **FE-R2-01:** POST to `/trpc/agency.saveBuilder` with `agents` array length > 20 — should receive `BAD_REQUEST` after the `.max()` is added.
2. **FE-R2-02:** Inject `\r\nX-Injected: evil` into an SSE `id:` line in a dev proxy — verify the sanitizer strips it before the header is set.
3. **FE-R2-03:** In browser console, dispatch a synthetic drag-drop event with `templateData.nodeType = "__proto__"` and `templateData.name = "A".repeat(200)` — verify both are rejected/truncated before `addNodeFromTemplate` runs.
4. **FE-R2-04:** In raw JSON mode, enter `{"type":"object","properties":{"__proto__":{"type":"string"}}}` and save — verify `__proto__` key is stripped; verify AJV on the server has external `$ref` disabled.
5. **FE-R2-05:** Mock `autoCreateStatus` to return `error: "A".repeat(600)` — verify the DOM truncates at 500 chars.
6. **FE-R2-06:** Assign a custom tool to an agent, then delete the tool — verify the server rejects with a descriptive error rather than silently orphaning the assignment.
