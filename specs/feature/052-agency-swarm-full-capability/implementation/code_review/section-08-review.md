### Summary

The diff completes the camelCase rename in the `create` procedure, both property panels (for the non-new fields), the Python adapter, the orchestrator, the SQL bridge, and the shared TypeScript types — but misses the **primary write path**: the `saveBuilder` Zod schema still uses `max_tokens` and `top_p` and does not accept `parallelToolCalls`, `maxTurns`, or `reasoningEffort`. This means every save from the visual builder will either reject the camelCase payload or silently discard the new runtime settings. The `AgentPropertyPanel` (the dedicated agent drawer) also lacks the three new UI fields entirely. The `reasoningEffort` → `Reasoning` object mapping in the Python adapter uses a raw `dict` instead of the typed `Reasoning(effort=value)` constructor the spec requires, which may fail at runtime depending on whether the `agents` SDK's Pydantic model coerces dicts. All three spec-required test files are absent. These issues together constitute a production-blocking gap and require changes before merge.
