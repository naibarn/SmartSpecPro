## 1. Project Overview

Build a comprehensive **Public API & External Agent Gateway** for SmartSpecPro that exposes all platform capabilities (LLM, skills, agencies, media generation, presentations, video projects) to external AI agents and developers through REST, SSE, and MCP interfaces.

### Key Decisions (from Interview)
1. **All consumers equal priority** — Manus AI, OpenClaw, custom agents, internal tools
2. **Low scale** initially — <100 API keys, <1K req/day
3. **Full admin UI** included — API key CRUD, usage charts, webhook management
4. **Domain-based implementation sections** — organized by domain, not by phase
5. **Configurable webhooks** — retry with exponential backoff + fire-and-forget, per endpoint
6. **MCP spec standard only** — protocol v2025-03-26, no vendor-specific hacks
7. **Users + admin create keys** — users create personal keys (own credit budget), admins create tenant-wide keys
8. **Unified auth** — single auth layer across ALL endpoints (new + existing OpenAI-compatible)
9. **Audit logging required** — all API calls logged with user, timestamp, action, traceId

### Design Principles (from Spec)
1. **Reuse existing infrastructure** — every endpoint wraps existing services
2. **Credits for every call** — all external API calls deduct credits
3. **Tenant-scoped** — API keys belong to tenants, multi-tenant isolation
4. **OpenAI-compatible where possible** — LLM endpoints follow OpenAI conventions
5. **MCP-native** — full MCP protocol compliance
6. **Audit everything** — traceId correlation across providerUsageLog and apiAuditEvents
7. **Defense in depth** — HMAC key hashing, timing-safe auth, SSRF firewall, scope ceiling

## 2. Feature Specifications

### F01: API Key Management & Auth

**Authentication:**
- Key format: `sk-ssp_{tenantShortId}_{32-char-random}` — OpenAI SDK compatible
- **HMAC-SHA256** hashing with server pepper (`API_KEY_HMAC_SECRET`)
- Keys stored as HMAC hash only, never plaintext
- Startup assertion: `API_KEY_HMAC_SECRET` must exist with ≥32 bytes entropy
- 15 granular scopes: `llm:chat`, `skills:execute`, `agencies:invoke`, `media:generate`, `presentations:create`, `video_projects:create`, `mcp:read`, `mcp:write`, `webhooks:manage`, `events:read`, `admin:keys`, etc.

**Users + admins both create keys:**
- Users create personal keys scoped to their own credit budget
- Admins create tenant-wide keys
- Users view/manage their own keys, not others'

**Unified auth in `authorizeRequest()`:**
- Detect `sk-ssp_` prefix → HMAC hash → lookup in `api_keys` table
- Validate: isActive, not expired, tenant `publicApi` feature flag enabled
- Return `AuthContext { userId, tenantId, mode: 'api_key', apiKeyId, scopes }`
- Works on ALL endpoints (new + existing OpenAI-compatible)

**AuthContext refactor:**
- Replace raw `userToken: string` with `{ userId, tenantId, mode: 'session' | 'api_key', apiKeyId? }`
- Affects: `executeSkill()`, `agencyBridge.executeRun()`, `autoGenerateDraft()`, `triggerPresentationExport()`, `generateImage/Video/Audio()`
- **protectedProcedure gap**: Extract business logic from tRPC mutations to service functions

**Rate limiting:**
- Per-key: Redis sliding window, default 60 RPM
- Per-tenant: 600 RPM global cap
- Daily credit limit per key (optional)
- Headers: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`

**Database:**
- `api_keys` table: varchar(36) PK, tenantId FK, userId FK, name, keyPrefix, keyHash (UNIQUE), scopes JSON, rateLimit, creditLimit, expiresAt, lastUsedAt, isActive, metadata JSON
- Indexes: keyHash (unique), tenantId

### F02: Skill Execution API

**Endpoints:**
- `GET /v1/skills` — list available skills (scope: `skills:list`)
- `GET /v1/skills/:id` — skill detail with input schema
- `POST /v1/skills/:id/execute` — execute skill (scope: `skills:execute`)
- `POST /v1/skills/detect` — auto-detect skill from prompt

**Implementation:**
- Wraps `skillExecutor.executeSkill()` and `skillRegistry.ts`
- Validates inputs against skill's JSON Schema
- Supports `stream: true` for SSE streaming
- Credits deducted via `creditService.deductCredits()` with `api_skill` source type

### F03: Agency Invocation API

**Endpoints:**
- `GET /v1/agencies` — list agencies (scope: `agencies:list`)
- `POST /v1/agencies/:agencyId/invoke` — invoke agency (scope: `agencies:invoke`)
- `GET /v1/agencies/:agencyId/runs/:runId` — poll run status
- `GET /v1/agencies/:agencyId/runs/:runId/stream` — SSE streaming

**CRITICAL — agencyConversations vs conversations:**
- Agency API uses `agencyConversations` table (varchar(36) ID), NOT `conversations` (integer ID)
- No `tenantId` column on `agencyConversations` — tenant isolation via JOIN through `agencies.tenantId`
- New `getOrCreateAgencyApiConversation()` function for API-initiated conversations
- Chat/skill API uses `conversations` table (integer ID) with separate `getOrCreateChatApiConversation()`

**Implementation:**
- Wraps `agencyBridge.ts` and `agencyStreamProxy.ts`
- `max_credits` budget cap per invocation
- Conversation support for multi-turn via `conversation_id`

### F04: Presentation API

**Endpoints:**
- `POST /v1/presentations/generate` — create from topic (scope: `presentations:create`)
- `GET /v1/presentations/tasks/:taskId/progress` — SSE progress stream
- `GET /v1/presentations/decks/:deckId` — get completed deck
- `POST /v1/presentations/decks/:deckId/export` — trigger export
- `GET /v1/presentations/decks/:deckId/export/download` — authenticated download

**Implementation:**
- Topic Zod validation: 3-1000 chars
- IDOR protection via `libraryItems` ownership check
- Signed download URLs with Bearer auth + ownership verification
- Extract `triggerPresentationExport()` from tRPC protectedProcedure to service function

### F05: Video Project API

**Endpoints:**
- `POST /v1/video-projects` — create video project (scope: `video_projects:create`)
- `GET /v1/video-projects/:id` — get status
- `GET /v1/video-projects/:id/export/download` — authenticated download

**Duration-based credits:** 3/5/10 per minute for draft/standard/high quality

**Database:**
- `video_project_exports` table with tenantIdx, idempotencyIdx
- Tenant isolation enforced

### F06: Media Generation API

**Endpoints:**
- `POST /v1/media/images/generate` — image generation (scope: `media:generate`)
- `POST /v1/media/videos/generate` — video generation
- `POST /v1/media/audio/generate` — audio generation
- `GET /v1/media/:taskId/status` — poll async status

**SSRF validation for `reference_image_urls`:**
- Each URL passes `sanitizeUri()` + `assertPublicIp()` individually
- Max 5 URLs per request
- `assertPublicIp()` checks ALL A/AAAA DNS records

### F07: Public MCP Server

**Transport:** Streamable HTTP at `POST /v1/mcp`
**Protocol:** v2025-03-26, JSON-RPC 2.0

**25+ tools registered:**
- Skills: list, execute, detect
- Agencies: list, invoke, status
- LLM: chat, embed
- Media: generate_image, generate_video, generate_audio
- Presentations: create, list, export
- Video projects: create, list, export
- Jobs: submit, status, cancel
- Files: read, list
- Drive: search, read
- Browser: execute_actions

**Constraints:**
- 60s tool execution timeout, 100KB result limit
- Redis-backed session state machine
- Auth: API key with `mcp:read` and/or `mcp:write` scope
- `GET /.well-known/mcp.json` discovery manifest

### F08: Job Automation API

**Endpoints:**
- `POST /v1/jobs` — create job (scope: `jobs:create`)
- `GET /v1/jobs` — list jobs (scope: `jobs:read`)
- `GET /v1/jobs/:id` — get status
- `DELETE /v1/jobs/:id` — cancel job

**Job types:** `skill_execution`, `media_generation`, `agency_run`, `batch_skill`, `presentation_create`, `video_project_create`
- `VALID_JOB_TYPES` enum validation
- Credit overflow guard: `MAX_SINGLE_JOB_CREDITS = 10,000`
- Atomic refund on failure

**Implementation:**
- BullMQ queue `automation-jobs` (queue-agnostic language for future Cloud Tasks migration)
- Credit pre-reservation → execute → refund excess
- Pipeline support: multi-step chains with `{{steps.stepId.field}}` template variables

### F09: Webhook Callbacks & Event Streaming

**Webhook management:**
- `POST /v1/webhooks` — register callback URL with event filter (scope: `webhooks:manage`)
- `GET /v1/webhooks` — list endpoints
- `DELETE /v1/webhooks/:id` — remove endpoint

**Configurable retry policy (per endpoint):**
- Default: retry with exponential backoff (1s, 5s, 25s), dead-letter after 3 failures
- Opt-in: fire-and-forget (single attempt, log failures)
- HMAC-SHA256 signature on all deliveries

**Event stream (SSE):**
- `GET /v1/events?types=job.completed,media.ready` — requires `events:read` scope
- Event types: job.completed, job.failed, job.progress, media.ready, agency.message, credits.low, key.expiring

**Security:**
- Webhook tenant ownership verification
- `apiKeyId` FK: nullable, ON DELETE SET NULL
- Params secret leakage prevention
- SSRF validation on callback URLs

### F10: Admin UI

- API key CRUD page with scope checkboxes
- One-time key display dialog
- Usage dashboard with per-key analytics
- Webhook endpoint management
- Integrated into existing admin panel

### F11: SDK & Documentation

- OpenAPI spec at `/v1/openapi.json`
- Swagger UI at `/v1/docs`
- MCP manifest at `/.well-known/mcp.json`
- Python SDK (`smartspecpro`) with async httpx
- TypeScript SDK (`@smartspec/sdk`)

## 4. Security Requirements

- HMAC-SHA256 key hashing with server pepper
- Startup assertion for `API_KEY_HMAC_SECRET` presence and entropy
- Scope ceiling enforcement on every endpoint
- Tenant isolation — API key resolves to specific tenant
- Rate limiting per key (60 RPM) + per tenant (600 RPM)
- Daily credit limit per key
- SSRF validation on callback URLs and reference_image_urls
- Webhook secrets encrypted with AES-256-GCM
- Signed download URLs for presentation/video exports
- Atomic credit refunds on failure
- Credit overflow guard (MAX_SINGLE_JOB_CREDITS = 10,000)
- 100KB result limit + 60s timeout on MCP tools
- Pipeline templates: restricted variable substitution only
- Audit logging: all API calls with user, timestamp, action, traceId
- Feature flag kill switch: disable `publicApi` → all API key access blocked
