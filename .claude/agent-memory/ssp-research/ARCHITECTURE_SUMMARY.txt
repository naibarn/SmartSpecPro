2. KEY ENDPOINTS & DATA FLOW
================================================================================

USER MESSAGE FLOW (sendMessage):
──────────────────────────────

Client: POST /trpc/agency.sendMessage
  ├─ agencyId, conversationId, message
  ├─ Auth: JWT token

→ Node.js router.sendMessage()
  ├─ Validate: conversation belongs to user
  ├─ Call: agencyBridge.executeRun()
  │   └─ headers: Authorization (Bearer), X-Tenant-Id, X-User-Id

→ Python POST /api/v1/agencies/{agencyId}/run
  ├─ Authenticate: get_current_user from Bearer token
  ├─ Check: AGENCY_SWARM_ENABLED flag
  ├─ AgencyService.execute_run()
  │   1. Load agency config (Node.js tables, no FK)
  │   2. Load agents + communication flows
  │   3. Pre-check credits (→ Node.js gateway)
  │   4. Resolve tools for each agent
  │   5. Create persistence hooks (load/save callbacks)
  │   6. Construct agents via adapter
  │   7. Construct agency via adapter
  │   8. Create agency_runs record (status: running)
  │   9. Execute adapter.run() with timeout + retry
  │      └─ agency.get_response(message)
  │         └─ Agent LLM calls (routed via Node.js /api/llm/v2)
  │            └─ Gateway: deduct credits per call
  │  10. Apply multiplier markup (→ Node.js gateway)
  │  11. Update agency_runs (status: completed, duration_ms, step_count)
  │
  └─ Return: AgencyRunResponse {run_id, status, output, credits_used, duration_ms}

← Node.js: Parse response, return to client
← Client: Display response


CREDIT DEDUCTION FLOW:
──────────────────────

Pre-check (Python → Node):
  GET /api/internal/credits/balance?userId={user_id}
  ← balance: float
  ├─ If balance < estimated_cost: raise HTTP 402
  └─ Optimistic (True) if gateway unavailable

Per-call (during Agent LLM calls):
  Agent calls LLM via gateway (/api/llm/v2)
  ├─ Gateway: Call provider
  ├─ Gateway: Calculate cost
  ├─ Gateway: Deduct from credits_transactions
  └─ Gateway: Record in provider_usage_log (traceId, cost, etc.)

Post-run (Python → Node):
  POST /api/internal/credits/agency-markup
  Body: {userId, agencyId, markupAmount, sourceType: "agency"}
  ├─ Markup = (total_gateway_cost * multiplier) - total_gateway_cost
  ├─ If multiplier = 1.0: no-op
  └─ Failure logged but doesn't raise (post-deduct pattern)

4. MULTI-TENANCY & SECURITY
================================================================================

Isolation:
  • Database: agencies.tenantId + query filter
  • Request: X-Tenant-Id header + user_id in context
  • Runtime: user_context dict in Agency instance
  • Tools: whitelist per agency

Tool Authorization (risk levels):
  • low: Always allowed, direct HTTP call
  • medium: Whitelisted per agency, direct HTTP call
  • high: Whitelisted per agency, dispatched to OpenSandbox

Error Handling:
  • Transient (retry): ConnectionError, HTTP 429/502/503/504
    └─ Exponential backoff: 1s, 2s, 4s (max 3 retries)
  • Permanent (fail fast): Auth failure, validation, insufficient credits
  • Optional (skip): Agent marked optional=true

Feature Flag:
  • AGENCY_SWARM_ENABLED check in code (fast path)
  • Fallback to system_settings table (DB override)
  • Returns 404 (hidden feature) if disabled
  • Checked on: Node router, Python router, admin endpoints


5. DESIGN PATTERNS
================================================================================

Pattern 1: Adapter Isolation
  • Only agency_swarm_adapter.py imports from agency-swarm library
  • All other modules use adapter methods
  • Upgrade-safe: library update only affects adapter.py

Pattern 2: Per-Request Instantiation
  • Fresh Agent instance per agent per run
  • Fresh Agency instance per run
  • Discarded after run (garbage collected)
  • Zero state leakage between requests

Pattern 3: Callback-Based Persistence
  • Agency-swarm calls load_cb() to read message history
  • Agency-swarm calls save_cb() to persist new messages
  • Callbacks read/write to agency_messages table
  • Agent-to-agent communication tracked in DB

Pattern 4: Error Classification
  • Retry on transient errors (connection, 429/5xx)
  • Fail fast on permanent errors (auth, validation, credits)
  • Optional agents degrade gracefully on failure

Pattern 5: Feature Flag Gating
  • AGENCY_SWARM_ENABLED controls visibility
  • Hidden (404) not disabled (403) when feature off
  • Gradual rollout to beta users

7. KEY RISKS & MITIGATIONS
================================================================================

Risk: Agency-swarm library crash → Blocks all multi-agent features
  Mitigation: Version isolation (adapter pattern), full error handling,
              circuit breaker on gateway

Risk: Infinite loop in agent communication → Runaway costs
  Mitigation: maxRunTimeSeconds (30–3600s), step_count tracking,
              test harness with controlled agents

Risk: Tool-based privilege escalation → Agent escapes agency scope
  Mitigation: Tool whitelist per agency, sandbox isolation for high-risk,
              callbacks limit agent to conversation context

Risk: Agent prompt injection via message → Model compromise
  Mitigation: Input validation (50k char limit), guardrails (TODO),
              system prompt control per agency

Risk: Credit exhaustion mid-run → User charged unexpectedly
  Mitigation: Pre-check (advisory), per-call gateway deduction,
              multiplier applied only for marked-up costs

Risk: Tenant data leakage in tool outputs → Privacy violation
  Mitigation: Tool whitelist enforced, callback persistence scoped,
              tenant_id in all queries, audit logging (TODO)
