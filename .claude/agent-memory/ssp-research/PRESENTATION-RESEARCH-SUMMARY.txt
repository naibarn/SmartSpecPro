KEY DISCOVERIES
======================================================================

1. DUAL REPRESENTATION
   - Components have BOTH semantic (slotBindings) AND rendered (fallbackElements) representations
   - Fallback elements are generated during component creation
   - Allows editing at both levels: slots or raw elements

2. TEXT UNIT SYSTEM
   - Grapheme-weighted text measurement for multilingual support
   - Thai text (1.2 weight) takes more space than Latin (1.0)
   - Budgets defined in text units, converted to estimated char counts per language
   - Functions: measurePresentationTextUnits(), clampPresentationTextToUnits()

3. RENDER ORDER
   - Explicit renderOrder[] array controls z-order
   - Can mix elements and components: "element:id-1", "component:id-2"
   - Required when using both elements and components on same slide

4. CANVAS PRESETS
   - 7 aspect ratios: 16:9, 9:16, 4:3, 3:4, 4:5, 5:4, 1:1
   - Canvas size: width/height independently specifiable (1–10,000 px)
   - Scaling system in presets: base 1280×720, scales proportionally

5. AI DESIGN METADATA
   - Every AI-generated slide includes aiDesign object
   - Tracks: mode (recipe used), fitScore, narrative, candidateRecipes, fallbackHistory, mediaModeMetadata
   - Enables understanding WHY a recipe was chosen and what alternatives were considered

ARCHITECTURE SUMMARY
======================================================================

LAYER 1: Atomic Elements
- 5 primitive types (text, image, video, rect, line)
- Common properties: id, type, x, y, width, height, opacity, rotation
- Direct editing in canvas

LAYER 2: Component Recipes
- 31 semantic templates with named slots
- Slots define WHAT content should go where
- Recipes auto-generate fallback elements to SHOW content
- Dual representation: semantic + rendered

LAYER 3: Slide Content
- Container for elements, components, and metadata
- Explicit render order controls display
- Supports audio, background, transition, AI metadata

LAYER 4: Block Presets
- Pre-designed element layouts (no semantics)
- Used for quick slide creation
- Generated dynamically, scaled to canvas

LAYER 5: Editor UI
- PresentationEditor.tsx manages state
- CanvasObjects renders interactive canvas
- SlideElementPreview renders read-only preview

DATA FLOW EXAMPLES
======================================================================

PRESET → SLIDE:
User clicks "Process Steps" preset
  → buildPresentationBlockPreset("process-steps", canvas)
  → returns 100+ elements
  → setSlideContent({ elements, ... })
  → CanvasObjects renders

NARRATIVE → COMPONENT → SLIDE:
User provides narrative (title, body, sections)
  → generateAIDraft({ narrative })
  → evaluates content profile
  → selects best recipe (e.g., "article-focus")
  → buildBuiltInPresentationComponentInstanceFromNarrative()
  → generates slotBindings + fallbackElements
  → setSlideContent({ components: [instance], elements: instance.fallbackElements, ... })
  → CanvasObjects renders fallbackElements

ELEMENT EDIT:
User selects text element and edits text
  → onUpdateElement(elementId, { text: newText })
  → updateElementById(slideContent, elementId, patch)
  → setSlideContent(updated)
  → CanvasObjects re-renders with new text
