CURRENT STATE (8 Node Types)
================================================================================

✓ AGENT (LLM + 16 tools + knowledge base)
✓ SUPERVISOR (semantically distinct, functionally identical to Agent)
✓ ROUTER (keyword/regex/LLM classification, single branch execution)
✓ AGGREGATOR (merge N parallel results via first_wins/majority_vote/llm_merge/concat)
✓ KNOWLEDGE BASE (RAG search, vector + keyword, multi-scope)
✓ SKILL CALL (execute SmartSpec skills, static input mapping)
✓ HUMAN APPROVAL (async decision gate, timeout policies)
✓ BROWSER SESSION (hands-off automation, RPA)

CRITICAL GAPS (10 Missing Node Types):

✗ CONDITIONAL BRANCH — "if/else/else-if" multi-branch routing
✗ PARALLEL FAN-OUT — "send to N agents simultaneously, collect results"
✗ LOOP / RETRY — "repeat until condition met, exponential backoff"
✗ DATA TRANSFORM — "map/filter/template intermediate results"
✗ TIMER / DELAY — "wait N seconds or cron trigger"
✗ MEMORY / STATE — "persist state across runs"
✗ WEBHOOK TRIGGER — "trigger from external events"
✗ CODE EXECUTION — "run Python/JS in sandbox"
✗ HTTP API CALL — "first-class HTTP requests with retry logic"
✗ ERROR HANDLER — "try/catch branches with fallbacks"

================================================================================
SKILL INTEGRATION ISSUE
================================================================================

PROBLEM: skill_call node has static input mapping
- 50+ skills exist (image-creator, video-engineer, product reviewers, etc.)
- Each skill defines input.schema.json (required fields) + ui.schema.json (UI layout)
- But orchestrator ignores these schemas
- All skills receive identical context (message + knowledge + prior results)
- No field-level routing ("feed knowledge to prompt field, results to context field")
- This creates a leaky abstraction: skill modularity is lost

SOLUTION: Implement skill input mapping (4-6 hours)
- Parse skill input.schema.json in property panel
- Visually map skill inputs to context fields (message, knowledge, results)
- Use JSONPath or Jinja2 templates for field extraction
- Validate before execution

QUICK WIN: Expose Sub-Agency node (3-4 hours)
- builtin-agency-call tool already exists (not exposed as node type)
- Just needs UI card + property panel
- Reuse existing tool execution path

================================================================================
ARCHITECTURE ASSESSMENT
================================================================================

✓ DATABASE: Extensible
  - agencyAgents.nodeType is varchar (easy to extend)
  - agencyAgents.nodeConfig is JSON (flexible per-type)
  - No migrations needed until scale requires it

✓ ORCHESTRATOR: Extensible
  - agency_orchestrator.py _execute_node() dispatch (add case per type)
  - ExecutionContext is mutable (can add fields for new node types)
  - No refactoring required

✓ FRONTEND: Extensible
  - BaseAgencyNode dispatcher (add card component per type)
  - Property panels exist for all types
  - Node property panel in sidebar (extend NODE_TYPE_SECTIONS)

⚠ RISKS:
  - Execution latency from complex graphs (conditional + loop = more LLM calls)
  - State persistence requires new DB table + backward compatibility design
  - Code execution is security-sensitive (must use sandbox, feature flag)
  - Webhook/Timer nodes require infrastructure (Celery job queue, reverse DNS)

KEY TAKEAWAYS
================================================================================

1. Current 8 node types cover basic orchestration but miss common patterns
   (conditional routing, parallel work, loops, error handling)

2. Skill system is isolated from agency orchestrator
   (separate detection, routing, chaining; no input mapping)

3. Architecture is READY for extension
   (no blockers, incremental implementation possible)

4. Recommend Phase 1 + validation approach
   (3 core nodes, measure adoption, add remaining on-demand)

5. Parallel fan-out + loops unlock most enterprise workflows
   (enables 70% of missing patterns)

6. Skill input mapping is HIGH-VALUE quick win
   (4-6 hours, improves UX significantly)
