### Contract Compliance

- **Mock completeness:** All direct imports consumed by `unifiedOrchestrator.ts` are mocked: `skillRegistry`, `executorRegistry`, `contextBuilder`, `skillExecutionPolicy`, `taskPlannerMiddleware`, `artifactRouter`, `creditService`, `auditLogger`, `traceContext`, `textSkillExecutor` (side-effect import). No import is missing from the mock list.
- **`vi.mock` hoisting:** All `vi.mock(...)` calls appear before `import` statements in the file. Vitest hoisting rules are followed correctly.
- **`beforeEach` reset:** `vi.clearAllMocks()` is called at the top of `beforeEach`, and every mock has its return value re-established after the clear. The pattern matches the companion test files (`executorRegistry`, `contextBuilder`, `textSkillExecutor`).
- **Type usage:** `vi.mocked()` is used for all 15 typed mock references rather than casting. `ExecutorResult`, `CapabilityExecutor`, `CapabilityFamily`, `PersistenceHook` are imported from the shared types module — no local redefinitions.
- **`buildRequest` helper:** Uses `Partial<UnifiedExecutionRequest>` spread pattern consistent with the project's other test helpers. Provides a valid required-field baseline.
- **Async patterns:** All `await executeUnified(...)` calls are correctly awaited. No floating promises.
- **Isolation concern (HIGH):** `persistenceHooks` is module-level mutable state and is NOT reset by `vi.clearAllMocks()`. See HIGH finding above.
- **`classifyCapability` suite:** Covers all five classification branches in the production function (explicit `capability_family`, category mapping, swarm mode, review pattern by slug/tag, default). String-serialized `executionPolicy` JSON is also tested. Coverage is complete for this pure function.
- **Error result shape:** Verified that `makeErrorResult` fields (`route.reason`, `result.type`, `metadata.error`, `telemetry.executorId`) are asserted by name in the error handling tests rather than via generic property existence.

### Summary

The test file is well-structured and covers the main execution paths: skill resolution fallback chain, executor fallback, context routing by channel, all three credit modes, the planner record-step branch, web search `extraBodyParams` injection, and the full step-ordering sequence. The most significant defect is that `registerPersistenceHook` writes into a module-level `Map` that is never cleared between tests, creating silent cross-test state contamination. Two behavioral gaps also stand out: the non-`chat_reply` artifact classification path (which populates `result.metadata`) and the `systemPromptSuffix` web-search mutation path are both untested, meaning future regressions in those branches will go undetected.
