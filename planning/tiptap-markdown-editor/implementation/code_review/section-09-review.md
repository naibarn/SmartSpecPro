## Review Report

### Verdict: APPROVE_WITH_FIXES

### Findings

| Severity | File:Line | Issue | Recommended Fix |
|---|---|---|---|
| HIGH | `pasteHandlers.ts:114` | Post-DOMPurify img regex reintroduces raw attribute interpolation. After DOMPurify runs, a second regex reconstructs `<img>` tags by splicing `pre` and `post` capture groups back in verbatim. If DOMPurify leaves any attribute fragment (e.g. a partially-encoded event handler or a second `src=`) in `pre`/`post`, those fragments bypass `sanitizeMediaSrc` and land in the final HTML string without escaping. DOMPurify should be the terminal step, not a middle step. | Move the `src`-sanitization regex to run **before** `DOMPurify.sanitize()` (or use a DOMPurify hook), so DOMPurify makes the final pass. Alternatively: use a `FORCE_BODY + RETURN_DOM` DOMPurify mode and mutate `img.src` attributes on the DOM tree before serialisation, avoiding regex entirely. |
| HIGH | `uploadMedia.ts:69` | `classifyMediaType` uses a broad prefix match (`image/`, `video/`, `audio/`) that accepts `image/svg+xml`. SVGs can carry embedded `<script>` tags and are rendered inline by some browsers as image sources. Accepting pasted/dropped SVG files and uploading them is a stored XSS risk unless the server explicitly sanitises SVG content. | Add an explicit deny for `image/svg+xml` in `classifyMediaType`, or add a client-side content scan. Cross-check with `ACCEPTED_TYPES` in the same file (which already includes `image/svg+xml` for the base file picker) and decide consistently whether SVG is supported in the editor drag/paste path. |
| HIGH | `TiptapEditor.tsx:43,47` | `editorRef.current!` non-null assertion is used inside `handlePaste` and `handleDrop` wrappers. On the very first render, `editorRef.current` is `null` (the `useEditor` call has not returned yet — the ref is assigned on line 55 of `TiptapEditor.tsx`, which runs after `useEditor` returns but before the component is committed). Because `editorProps` is passed to `useEditor`, the handlers are registered before the ref is populated. If Tiptap fires a paste or drop event during initialisation the `!` assertion will allow `null` to be passed to `handlePaste`/`handleDrop`, and both functions dereference `editor.isDestroyed` without a null guard, throwing a runtime crash. | Either guard inside each handler (`if (!editor) return false;`) or pass the editor instance directly from the `editorProps` callback context, which already receives the live `EditorView` (the editor is available as `view.state.editor` via the Tiptap bridge, or by reading `editorRef.current` with a null check). |
| MEDIUM | `dropHandler.ts:60` | All files in a multi-drop batch are inserted at the same fixed `pos`. After the first `insertContentAt(pos, ...)` the document has grown, so all subsequent inserts land at the same stale position, stacking all nodes on top of each other rather than sequentially. | Track a cursor position: after each successful insert, advance `pos` by the size of the inserted node (or use `editor.chain().focus().setNodeSelection(pos).insertContentAt(pos, node)` and read the new cursor position from the editor state after each `.run()`). |
| MEDIUM | `pasteHandlers.ts:531` | `XML_NS_TAG` regex is `/<\/?[a-zA-Z]+:[a-zA-Z]+[^>]*>/g`. This also strips valid SVG and MathML namespaced tags that an author may have intentionally pasted (e.g. `<svg:circle>`). More critically, it matches tag patterns before DOMPurify sees them, which can leave dangling `>` characters if the content is malformed, potentially confusing the DOMPurify parser on the next step. | Run DOMPurify **first** with a `FORBID_TAGS` list that includes `o:p`, `w:sdt`, etc., or use DOMPurify's `beforeSanitizeAttributes`/`afterSanitizeElements` hooks. If the regex pre-pass is intentional, add a brief comment explaining why it must precede DOMPurify rather than following it. |
| MEDIUM | `pasteHandlers.ts:55` | `MSO_STYLE_ATTR` regex is `style="[^"]*mso-[^"]*"`. This only strips `style` attributes that contain at least one `mso-` property. If Word emits `style="color:red;mso-bidi-font-weight:normal"` the whole attribute is stripped, but if it emits `style="mso-bidi-font-weight:normal;color:red"` (mso- prefix then other) the attribute is also stripped — those cases are correct. However the regex does NOT strip style attributes that begin with a non-mso property and contain mso- mid-string when the `mso-` token appears inside a value rather than a property name (e.g. `style="font-family:'mso-Calibri'"`). This is a minor hygiene issue but can leave Word cruft in the output. | Use a per-property stripper rather than a whole-attribute regex, or rely on DOMPurify's `ALLOWED_ATTR` (which already excludes `style` from the whitelist), and simply drop all `style` attributes in the pre-DOMPurify pass. |
| MEDIUM | `pasteHandlers.ts` | `handlePaste` intercepts only `image` clipboard items. Pasted `video` and `audio` files from clipboard are silently dropped (returns `false`), which means Tiptap tries to handle them as text, producing no insert. This is a UX gap that may also surprise users who expect the same behaviour as drag-drop. The plan spec (Section 09) lists paste handling for images only, but dropping video/audio works via `handleDrop`, creating an asymmetry. | Either document this asymmetry explicitly, or extend `handlePaste` to handle `video` and `audio` clipboard items using `insertContentAt` (same pattern as `handleDrop`). |
| MEDIUM | `__tests__/paste-handlers.test.ts:219-240` | The DOMPurify mock is a simplified regex-based sanitiser. Crucially, the mock does NOT strip `data:text/html`, `data:image/svg+xml`, or `javascript:` from `src` attributes on tags other than `<img>` (e.g. `<a href="javascript:...">`). The mock therefore does not validate the real security surface: tests that claim to verify XSS stripping pass because the mock is lenient in the right direction but would also pass even if DOMPurify were removed entirely. | The mock should be replaced by a stricter one that mirrors the actual PURIFY_CONFIG allowlist — or, better, test `transformPastedHTML` in a jsdom environment where real DOMPurify can run. At minimum, add a test that verifies `<a href="javascript:alert(1)">` is stripped (currently not covered). |
| MEDIUM | `uploadMedia.ts:73` | `uploadMedia` sends the file to `/api/media-jobs/upload` without CSRF protection. The request uses `credentials: "include"` (session cookies are sent), so a malicious page could trigger a cross-origin file upload if the CSRF middleware on that Express route is missing or bypassed. The server-side route (line 923 of `mediaJobs.ts`) applies multer but inspection of the code shows no CSRF token check on this endpoint. | Verify and enforce CSRF token validation on `/api/media-jobs/upload`. The standard pattern in this codebase is to include a CSRF header checked server-side. If the endpoint is already behind the CSRF middleware, document this; otherwise add the check. |
| LOW | `TiptapEditor.tsx:6-7` | `handlePaste` and `transformPastedHTML` are imported from `./pasteHandlers` in two separate import statements. | Merge into a single import: `import { handlePaste, transformPastedHTML } from "./pasteHandlers";` |
| LOW | `dropHandler.ts:55` | `const nodeType = type;` is a redundant assignment — `type` is already a `"image" | "video" | "audio"` discriminant from the destructure on line 50. `nodeType` is used once on line 60. | Remove the intermediate variable and use `type` directly. |
| LOW | `uploadMedia.ts:83` | `(await res.json()) as { url: string }` is an unchecked type cast. If the server returns a different shape (error object, or `{ fileUrl: string }`), the cast silently returns `undefined` for `data.url`, and the caller receives `undefined` cast as a `string`. | Add a runtime check: `if (!data?.url) throw new Error("Upload response missing url");` |
| LOW | `__tests__/drag-drop.test.ts:201-209` | The `moved=true` test asserts `result === false` but does not assert that `uploadMedia` was never called. This matters because a future refactor could move the `if (moved) return false` guard after the file filter, causing uploads to proceed for internal moves. | Add `expect(mockUpload).not.toHaveBeenCalled()` to the `moved=true` test. |
| LOW | `__tests__/paste-handlers.test.ts` | There is no test for `handlePaste` when `editor.isDestroyed` is `true` at the time the async upload resolves. The guard `if (editor.isDestroyed) return;` on line 42 is untested — a regression here would cause a "cannot dispatch on a destroyed editor" runtime error. | Add a test: resolve the upload promise after setting `editor.isDestroyed = true` and assert that `editor.chain()` is never called. |

### Summary

The core implementation is structurally sound: DOMPurify is correctly integrated with a tight allowlist, the data URL prefix fix from the Section-08 review is confirmed applied, and the `editor.isDestroyed` unmount guard is present. Three issues require fixes before merge: the post-DOMPurify regex reconstruction of `<img>` tags which bypasses the sanitiser as the terminal step (HIGH); `image/svg+xml` acceptance via the broad `classifyMediaType` prefix match which can allow stored XSS through uploaded SVG (HIGH); and the non-null assertion on `editorRef.current` which can produce a null-dereference crash during editor initialisation (HIGH). The multi-drop position stale `pos` bug is a notable correctness issue that will produce surprising stacking behaviour for all multi-file drops.
